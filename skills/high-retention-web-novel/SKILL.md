# High-Retention Web Novel

创作原创、可持续连载的商业小说。目标是让读者因为已经获得价值、在意人物并期待一个具体后果而继续阅读，而不是依靠欺骗性截断。

首要目标是提高小说质量：因果可信、人物有复杂动机、情绪有铺垫和余波、语言具体且有辨识度。留存与付费建立在作品质量上，不能用堆字数、重复受辱、同义争吵或拖延兑现来制造网络水文。

## 基本原则

- 跟随用户的语言。用户未指定时，中文请求用中文，英文请求用英文。
- 把框架当作质量检查，不把它写成可见的机械模板。阶段顺序严格，表达形式可变；用实际阅读收益证明选择，不要求每章使用相同开场、主角决断或反转结构。
- 不承诺点击率、付费率或商业结果。可以解释设计意图，但只把它表述为提高续读可能性的假设。
- 只创作原创内容。不要复刻具体作品的专名、关系图、桥段序列、独特设定或标志性措辞，也不要模仿在世作者的独特风格。
- 文件格式、是否像正文、是否私密、用户是否拥有版权，都不能自动把素材变成当前项目的 canon。先按下述输入分流确认用途。
- 写作质量改进只落实到 Skill 与 Prompt 指令，不授权修改 Novel OS 框架、部署配置或宿主应用与认证设置；基础设施修复需作为用户另行提出的任务处理。

## 输入分流：步骤 0，不可跳过

在模式路由和创作前，把与任务有关的输入标记为以下一种；内部记录判定依据，不必把标签机械地展示给用户。

- `user_constraint`：用户为本次新作品直接指定的角色、设定、偏好、篇幅、内容边界，或已经认可的原创设计。它可以进入设计和写作上下文，但不因此把任何参考作品变成 canon。
- `reference_only`：用户提供的外部素材默认归入此类，包括用户称为“素材、灵感、参考、案例、拆解对象、同类作品”的内容，以及用途含糊的外部正文。用户说“只参考思路、必须原创、不要续写或不要沿用”的指令优先级最高；即使素材是用户原创、私密或已获授权，也仍是 `reference_only`。
- `project_canon`：只有用户明确说明这是同一项目已经成立的正文或设定，并要求续写、改写或保持其事实连续性时才成立。只有这一类内容继承人物、事件、秘密、时间线与私密原稿细节。

若多类内容同时出现，分别处理，不让参考素材污染项目 canon。分类会实质改变任务且用户意图仍不明时，只问一个用途问题；不得以版权状态代替用途判断。

处理 `reference_only` 时执行一次干净交接：

1. 在素材分析阶段只提取抽象功能，例如目标读者、情绪承诺、通用类型机制、压力类型、节奏问题与用户明确要保留的非表达性约束。
2. 列出不得继承的来源特征：专名、角色组合、特色场景、独特设定、揭示内容、反转机制、重大选择顺序、转折链、措辞和可逐场对应的摘要。
3. 从空白因果链重建人物目标、职业能力、关系利益、世界限制、代价、前三个重大选择、揭示逻辑和代表场景。只保留通过原创性审查、符合用户已确认约束的设计。
4. 进入规划或写作运行上下文时，只携带符合 `user_constraint`、且已经内部原创审查的设计。不得携带来源正文、来源角色表、来源情节路径、逐章摘要、来源文件路径、文件标题、来源身份标签、私有逐项比较记录或它们的改写版；需要再次核对原创性时回到隔离的素材分析阶段。

用户要求直接写作时，内部完成原创审查后即可执行，不要为了“认可原创设计”额外要求一次批准。只有新设计会重大改变用户已经确认的故事身份、结局方向、内容边界或篇幅时才询问确认。

可以复用“调查者测试假设”“关系胜利带来资源代价”等通用类型机制，但不能用换名字、换职业、换地点、换时代或换物种掩盖同一特色场景、揭示顺序或转折链。

## 模式路由

根据请求选择最窄的工作模式；除非用户要求，不要把所有模式的产物一次性倾倒出来。

| 用户目标 | 模式 | 主要交付物 |
| --- | --- | --- |
| 从零开发小说 | `project` | 创作简报、故事引擎、角色关系、长线弧、免费微弧 |
| 已有设定，规划连载 | `outline` | 分卷/篇章结构、章节表、悬念与兑现台账 |
| 写首章或任意一章 | `draft` | 章节标题与正文；需要时另附极短自检 |
| 基于既有内容续写 | `continue` | canon 增量、下一章契约、正文 |
| 提升吸引力或重写 | `revise` | 问题证据、修改策略、完整改稿 |
| 分析留存、节奏或付费点 | `diagnose` | 证据化评分、优先问题、可执行修复方案 |

## 按需读取参考

开始任务前完整读取对应参考文件。不要加载与当前模式无关的材料。

- `project`：始终读取 [references/story-engine.md](references/story-engine.md) 和 [references/paid-conversion.md](references/paid-conversion.md)，因为默认交付包含免费微弧与首个付费章承诺。
- `outline`：读取 [references/story-engine.md](references/story-engine.md)。涉及免费试读或付费节点时再读取 [references/paid-conversion.md](references/paid-conversion.md)。
- `draft`、`continue`、`revise`：读取 [references/chapter-craft.md](references/chapter-craft.md)。若本章处于免费窗口末端或首个付费章，再读取 [references/paid-conversion.md](references/paid-conversion.md)。
- 新书批量写作前、重大人物或关系转变、深入正文修订及重要故事段落结束时，读取 [references/prose-quality.md](references/prose-quality.md)，处理本书文风基准、转变证据、场景展开和整段复读。直接写单章不增加额外样本作业。
- `diagnose`：读取 [references/quality-rubric.md](references/quality-rubric.md)，并按问题补读其他参考。
- 交付大型项目方案或关键章节前，读取 [references/quality-rubric.md](references/quality-rubric.md) 做最终检查。

## 输入契约

输入分流完成后，优先从用户提示、`project_canon` 和审核通过的原创设计中提取信息，不重复追问已经给出的内容。`reference_only` 原文不属于本契约。

记录以下变量：

- 题材、目标读者、语言和内容边界
- 视角、时态、单章篇幅及预计总长度
- 核心情绪承诺和读者反复想获得的体验
- 主角、关键关系、外部目标、失败代价和期限
- 世界规则、已知时间线、秘密和不能改变的 canon
- 免费试读窗口、目标里程碑或平台限制（如有）

缺失项不影响方向时自主选择题材相容的默认值。缺失项会实质改变故事身份、受众边界或既有 canon 时，只问最少的澄清问题。若用户要求直接写，做出保守假设并执行，不在正文前解释假设。

## 有序工作流

任何模式都先完成步骤 0 输入分流。`project`、`outline` 执行第 1–3 步后进入章节设计。包含章节正文的 `draft`、`continue`、`revise` 必须依次完成：原创设计或已通过设计 -> 章节契约 -> 完整正文 -> 结构修订 -> 连续性、文风和质量检查 -> 通过后更新状态。未写正文不能因规划优秀而标记章节通过，质量检查失败时先修订再复检，不能先更新 canon 或悬念台账。

快捷模式可以复用有证据的既有故事契约、`project_canon`、已通过章节设计和连续性台账，不必重做第 1–3 步；但不得跳过输入分流、当章契约、正文、结构修订和质量门。不要为写一章而输出或暗中展开整套项目规划。

### 1. 建立故事契约

用一句内部工作句定义：谁想要什么、为何现在必须行动、最大优势会带来什么代价、失败将失去什么。再定义核心情绪承诺，例如禁忌亲密、智性复仇、身份逆转或真相逼近。

高概念必须同时通过四项检查：一句话清晰、能自然产生许多不同冲突、能迫使主角重新定义自己、能通过改变代价类型持续升级。

### 2. 建立可再生故事引擎

组合五股持续力量：外部目标、关系困境、内部误信、秘密或谜团、持续施压机制。每股力量都要能改变人物选择；删除后若剧情不变，就不是有效引擎。

为主角和核心对手定义目标、筹码、限制、边界与压力下的典型选择。主角必须主动制造关键因果，而不是只被告知、被救或被伤害。

### 3. 规划弧线与兑现

先规划当前篇章，再规划单章。篇章应在目标、规则、关系、舞台、身份或时间压力上留下足以改变后续故事的结果，不按变化项数凑升级。

维护三层悬念：短期问题在当前或下一章兑现；篇章问题在局部故事弧兑现；长线问题贯穿卷或全书。优先采用“回答一个旧问题，让答案产生范围更具体、风险更高的新问题”。

只为关键人物与关系的重大变化规划证据链，并区分计划和已写事实；新书进入批量正文前，用已通过的原创设计建立本书文风样本，或复用本书已批准正文。具体做法见 [正文质量参考](references/prose-quality.md)，不另索样本审批，也不把练笔写入 canon。

### 4. 定义章节契约

写章前只在内部确定五件事：

- 本章视角与主要功能是什么，开场如何让读者进入当前处境
- 人物行动如何获得反馈，或既有事件的余波如何改变理解、关系与后续可能
- 本章兑现、推进或重新解释什么，并给读者什么当下价值
- 离开本章时，局势、人物状态、读者理解或关系感受发生什么实质变化
- 结尾如何完成本章意义，并留下具体期待、未消化的后果或值得停留的余韵

行动章可按“目标 -> 阻碍 -> 选择 -> 代价 -> 转折”检验因果；非主角 POV、余波章与静场按其功能检验价值，不强行插入主角决断或事故。变化场景长度、开场方式、冲突类型和句法节奏。

### 5. 写正文

选择能承载本章功能的入口：行动中的失衡、一个判断、关系细节或事件余波都可以。尽早让读者辨认当前处境与值得在意之处，不必每章同时重报主角损失和行动目标。用行动、感官、物证、对话潜台词和具体共同生活建立投入；只解释读者理解当前场景所需的设定。

重大选择、关系转折、揭示和胜负必须在正文中场景化，让读者经历可感知的动作、对话、判断及空间时间，而不是把大纲扩成事件摘要。过渡、重复劳动和已知信息可以概述，展开程度服从节点的重要性。

结尾先完成本章的动作或情绪意义，再按章节功能留下具体期待、后果或余韵。有效牵引可以是决定、发现、代价、关系位移、倒计时、道德困境或带刺的胜利；静场和收束章不必制造新的危机。

每个场景都要能指出进入状态、离开状态和读者收益。收益可以是行动推进、答案、关系换义、人物理解或情绪处理，不要求每场都有外部爆点，也不要求收益立刻变成新决定。非主角 POV、余波和静场可用读者理解或关系感受的实质变化举证。若删除场景既不改变因果、信息、信任、解释、决定或后续情绪选择，也不损失独特阅读体验，就删除或压缩。

篇幅是用户确认的产品约束，不是填充配额，也不能被擅自改长或改短。内容不足时深化两难、证据、关系反馈或选择后果；不要添加重复内心独白、无功能回忆、往返路程、同义争吵或无新信息的说明来凑字数。

### 6. 结构修订

先检查进入状态与离开状态，再按因果、能动性、兑现、关系利益和场景必要性修订。只有结构成立后才做句子级润色。保留安静但有效的情绪场景：如果沉默、照顾、日常动作或共同物件改变信任、理解、边界或下一步选择，它通过删除测试；不要为了“节奏”强塞事故、争吵或新秘密。

重要故事段落结束时，连读该段实际正文，复查重复觉醒、关系跳跃、胜利余波和中段是否换皮复用旧困境。依据段落整体节奏修订，不以章节表或逐章通过记录代替复读。

### 7. 连续性、文风与质量门

交付前检查：

- 本章是否完成其功能？推进主线的关键选择是否由人物作出，而非作者救场？
- 每个主要场景是否有可引用的局势、人物或读者体验变化？
- 是否兑现、推进或深化了值得读者在意的内容？
- 存在反转时，是否有可回看的事实、误读与动机？
- 承诺了代价时，是否可观察并影响后续，而非口头声明？
- 关键人物与关系转变是否有正文证据，文风是否延续本书基准而适应当下情绪？
- 章末是否完成本章动作和意义，牵引或余韵是否来自已建立的故事？
- 是否出现具体作品、作者风格或模板句式的可识别复刻？

使用 [references/quality-rubric.md](references/quality-rubric.md) 作诊断时，只评适用维度并引用实际文本证据；明确不适用的项目记 `N/A`，缺少材料或尚未核查的项目记 `not_reviewed`。不按总分自动交付。语言、人物声音、视角、潜台词和情绪可信度分别检查，结构分不能抵消正文问题。规划证据不能证明未写正文已经通过。关键章节和重要改稿按量表中的协议进行独立正文试读；没有独立审者时如实报告第二遍自审，不冒充真人反馈。

### 8. 通过后更新状态

正文完成结构修订，并通过连续性、文风、原创性和质量检查后，才更新角色状态、关系、时间线、世界规则、悬念台账和章节通过状态。只记录正文中真正发生且经检查的变化；不要把计划中的未来事件提前写成 canon，也不要悄悄改写已建立事实。

若后续文风润色改变了事实、人物决定或伏笔，先重新检查受影响的连续性与兑现证据，再更新状态。

## 各模式输出

### `project`

依次交付：创作简报、高概念与情绪承诺、故事引擎、角色与关系矩阵、规则与限制、长线弧、免费微弧与首个付费章承诺、风险清单。提供可直接进入写作的具体选择，不堆砌备选点子。

### `outline`

先给篇章目标、不可逆转折和结局方向，再给章节表。每章表包含视角与功能、行动或情绪焦点、预期变化、读者收益和结尾落点；行动章写清主动选择。未知 canon 标记为“待定”，计划节点不当成已写事实。

### `draft` / `continue`

用户要求“只输出正文”时，仍在内部走完契约、正文、结构修订和质量门，外部只输出章节标题和通过后的正文，不解释方法。保持视角、时态、称谓、规则和时间线一致。首章要兑现题材承诺；免费末章使用“阶段兑现 -> 答案迫使主角作出有代价选择 -> 本章展示不可逆后果 -> 明确下一目标、时限或关系风险”的连续链；首个付费章要立即承接该后果。

### `revise`

先用原文证据指出最多五个高影响问题，再说明保留项与修改目标，最后给完整改稿。除非用户只要局部润色，不要用零散句子替代可阅读的完整版本。

### `diagnose`

按“问题 -> 原文证据 -> 对阅读体验的影响 -> 优先修复 -> 示例方向”输出。区分结构问题、执行问题和个人偏好；不要把主观口味伪装成绝对规则。

## 自然付费边界

免费部分应构成一个完成的微弧：证明独特承诺、建立人物投入、展示代表性场景、兑现至少一个问题，并让主角跨过不可逆门槛。付费点必须按顺序完成阶段兑现、由答案触发的主动选择、本章内可见的不可逆后果，以及一个具体的下一目标、时限或关系风险。单纯得到答案不等于跨过门槛。

不要中句截断、在兑现前强行上锁、故意拆碎正常章节、连续只挖悬念、用无铺垫角色制造假惊奇，或宣称“下一章改变一切”。首个付费章必须先承接钩子的直接后果，再扩展支线。

## 完成标准

只有同时满足以下条件才算完成：

- 主线设计能说清人物目标与失败代价；单章或片段让读者理解当前处境及值得在意之处。
- 核心转折来自人物选择与既有规则，而非作者临时救场。
- 章节提供当下价值，并按功能形成具体期待、情绪余韵或应有的收束。
- 人物具有欲望、能力、边界和矛盾，不以创伤或标签代替深度。
- 最近章节没有无新增意义地复用同一困境、觉醒、争吵或章末手法；有意义的重复意象、地点和日常仪式可以保留，其情境或意义变化应能从正文指出。
- 输出保持原创、连续、符合用户内容边界。
