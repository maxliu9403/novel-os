# 骨架确认后的书名设计

初始书名可留空或作为暂定名，不应阻止故事设计。用户确认完整骨架后，依据最终的
核心冲突、人物选择、情绪承诺、类型、目标读者、发行地域和语言设计书名。

- 通常推荐五个有实质区别的候选名，并用简短中文说明各自强调什么。
- 书名默认使用正文语言；尊重用户指定的语言、长度、保留词、语气与平台偏好。
- 结合用户历次命名要求继续优化，不限制迭代次数。最新明确要求优先，保留未被推翻的限制。
- 用户说“优化这个书名”时，以当前选中或手动修改的标题为起点；该草稿仍需用户最终确认。
- 每个候选都必须忠于已确认的故事，不编造关系、身份或结局来制造点击，也不泄露最大反转。
- 候选尚未被采用；最终书名由用户选择，可自由修改或自行输入。用户明确要求保留原名时遵守。
- 不声称已核查商标、唯一性、搜索热度或畅销潜力，除非确实完成相应核查。
- 命名只改变作品书名，不改写骨架情节，不把系列总名、分卷名或章节名一并替换。
- 最终选择同步到顶部 Title、实际书名标题、封面交接顶层 title，再生成与之匹配的启动命令。
  多本系列的 series.title 表示系列总名，应单独保留。
- 用户返回修改基础设定或故事后，保留历史与上一版骨架；更新相关设计，重新确认书名及命令。
  正在推导的输入保持本轮快照，不用中途改表单的值覆盖正在执行的请求。

直接助手交付可用 Markdown 候选列表；Web 宿主指定 JSON 时严格遵循该传输格式，
由界面向用户展示候选、理由和编辑框。命名失败时保留骨架、已有建议与全部用户要求。
