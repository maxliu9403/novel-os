# 头脑风暴第三阶段分块交付修复

## 问题与实现

最新任务第三阶段持续返回正文活动，仍在本地 900 秒期限结束时被终止；原生 CLI 尚未交付完整消息，不能从指标计数恢复正文。此前一轮前两阶段用掉大部分时间，第三阶段仅获约 54 秒。详见 [诊断](2026-10-13-workshop-assembly-timeout.md)。

保留原生 Codex CLI、模型和推理档位。第三阶段改为 6 个有界补充：创作规格、人物关系与世界规则、秘密与伏笔、阅读回报与文风、封面故事交接、交付复核。模型只返回当前部分的 JSON；已有故事设计、人物、因果链、结局、决定和全章节规划由程序组装进入最终 17 节，不再次要求模型转写。每次请求继续携带完整作者上下文和已保存成果。

每部分完成局部格式／合同校验后持久化；最终仍执行现有完整骨架、章节数、组织形式、作者修改和交付合同校验。最终错误可定位时只修订对应部分，不退回整书输出；无法定位或超出修复额度时保留成果并停止，不擅改已确定的故事。全局仍至多两次格式修复，超时无自动模型重试。

旧 `workshop.delivery.v1` 记录和 Skill 指纹保持兼容，前两阶段哈希不变。新可选 parts 扩展采用追加式哈希链，局部修订保留此前版本，最终骨架绑定全部部分及修订。保存仍受会话版本、job、取消状态和原生进程退出锁保护；读取进度不产生模型请求。

兼容原阶段允许的自由文本：嵌套章节／编号节标题只调整 Markdown 层级；正文中的 `POV:` 等元数据行加引用前缀，避免被当成全书配置；额外故事与章节字段完整保留为 JSON 补充记录。多行章标题保留原值并另生成单行显示标题。原始检查点不改，普通正文逐字保持，未删减事实。

单次请求继续使用配置的超时（默认 900 秒）；阶段交付整轮固定上限为其三倍（默认 2700 秒），从本轮原始起点计算，包含等待和保存，不随活动或修订重置。普通讨论与已有完整骨架修改仍使用原整轮预算。界面区分单次请求和整轮时限，并展示第三阶段当前部分、已保存数量及暂停／失败后的继续入口。
