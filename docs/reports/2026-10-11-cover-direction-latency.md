## 已实现

1. **字段修订协议**：有完整有效基线的来源绑定方向使用 `cover-direction-patch.v1`。
   模型只返回需要变化的方案字段及必要共享字段，原稿哈希绑定；对象与数组完整替换。
   保持方案 ID、数量和顺序，禁止新增审批/来源权威字段、无效哈希和空变化。
   原稿有歧义则保持原完整回复修复；旧适配器完整回复继续兼容，但同样约束 ID 与顺序。
2. **完整检查保留**：本地重建后对全部四套方案执行完整 schema、来源、人物、构图、
   排版、编译预算及独立语义/逐引文审核。每次有效修订产生新的完整审核回执。
   连续修订绑定上一轮合并后的原稿；无效补丁保留旧基线。共用原两次修复上限。
   初轮仍探索不同创意；修订不再要求重新探索全部无关方向。
3. **固定来源前置**：只调整无损打包后的 JSON 顶层字段顺序，完整原文、全部分析、
   证据 ID、完整上轮回复及字节预算不变。固定来源、证据、分析先于变化的错误与方案。
4. **真实阶段**：诊断先持久化，再为精确作品/任务发布生成、校验、独立审核、修订、
   保存阶段、轮次、阶段起点与已收到回复数。切页恢复；规划器完成不等于保存完成；
   失败/重启保留最后阶段。显示 Token 结算时点，不显示虚构的百分比、TPS 或完成时间。

## 离线证据与限制

对真实保存的三份稿件反推字段差异，再由生产补丁模块重建，结果与完整稿严格一致：

| 修订 | 紧凑完整回复 | 紧凑字段补丁 | 回复字节减少 |
| --- | ---: | ---: | ---: |
| 稿 1 → 稿 2 | 47,598 B | 6,561 B | 86.22% |
| 稿 2 → 稿 3 | 53,320 B | 39,009 B | 26.84% |

这是已有稿件的离线差异测量，**不是实际新模型输出或耗时降幅**。实际模型仍可能需要
更广泛的修订。首轮完整设计与独立审核耗时仍存在，不能承诺一分钟完成。

实际来源重放中，首轮到修订的共同 user 前缀由 136,041 B 增至 240,628 B；JSON
内容与总大小相等。独立审核使用不同 system，不能把 user 相同前缀当成跨角色缓存命中。
[OpenAI 延迟指南](https://developers.openai.com/api/docs/guides/latency-optimization)
支持通过减少重复输出降低等待；
[缓存文档](https://developers.openai.com/api/docs/guides/prompt-caching)
要求完整前缀和有效缓存边界匹配。GPT-6 的共享字符串本身不保证命中；当前 Codex CLI
没有为此提供应用级显式断点控制，因此此处仅稳定请求格式，不承诺缓存或费用降幅。

本轮不更换型号或降低推理档位，不缩短故事来源、不减少独立审核，不调用真实模型或
自动重试旧失败任务，不生成图片或修改历史方向、批准、选择及预算。
