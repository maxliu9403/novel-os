# 头脑风暴首次提交后停留在运行中

## 现象与根因

讨论 `d7c6589ce293` 于北京时间 2026-10-08 11:22:03 提交。后台任务在约
1.7 毫秒后变为 `done`，没有进入模型调用；持久化讨论却仍为 `running`。
页面持续轮询、计时，模型的 15 分钟超时机制没有机会开始执行。

在当前 Docker Desktop 的 `/data` 挂载目录上，首次以 `open('a')` 创建
`.lock` 并持有阻塞式 `flock(LOCK_EX)` 时，另一线程能够在解锁前进入。
同一文件预先创建并关闭后，锁又能正确阻塞。因此，对已存在锁文件的
只读 / 非阻塞式检查不能复现这个问题。

真实调用顺序已在隔离临时会话中记录：

1. 请求线程持锁读取 `draft / revision 0`，开始提交后台线程。
2. 请求线程尚未完成保存 `running / revision 1`。
3. 后台线程提前进入锁，读到旧版本，命中过期任务保护并直接返回。
4. JobRunner 把正常返回记为 `done`；请求线程随后才保存 `running`。
5. 原有状态恢复只判断任务不存在，没有处理任务已结束的情况。

## 修复

- 给整个讨论事务增加进程内互斥锁，以解析后的讨论路径作为键；同一讨论的
  不同服务实例共享锁，不同讨论和工作区可并行。保留文件锁用于进程间协作。
- 弱引用保存锁，避免为已经不再访问的讨论永久占用锁表。
- 查询讨论或讨论列表时，若当前后台任务已结束而讨论仍在运行，则写入可重试
  错误。保留基础设定、对话、骨架、命名记录及候选结果。
- 过期任务提前退出时记录安全诊断字段，不记录提示词、认证信息或模型原始错误。

此修复针对单进程 JobRunner 的 Web 任务协调，不改变小说生成引擎、Skill、
模型配置、超时时间或交付格式。它不添加多进程任务队列支持。

## 验证

- 使用真实 WorkshopService 和 JobRunner、仅替换模型返回的隔离实验：
  修复前容器 `/tmp` 为 30/30 成功，`/data` 为 0/30 成功；修复后两处均 30/30 成功。
- 最小文件锁实验：挂载目录中首次创建锁文件 5/5 出现重叠；预先创建并关闭
  锁文件后 5/5 正常阻塞；容器 `/tmp` 两种情况均正常。
- `tests/test_workshop_thread_lock.py`：恢复原有仅文件锁实现时有 3 项失败，
  包括模型调用次数为 0 的实际提交场景；修复后 9 项通过。
- `tests/test_workshop_terminal_state.py`：修复前 8 项失败；修复后 17 项通过。
  覆盖讨论与命名、详情与列表、上下文保留、重复读取、重试及新旧任务隔离。
- 原有头脑风暴 API、交接、命名、暂停、结构修复和探索测试，加上终态测试，
  共 123 项通过。加上线程锁 9 项和模型取消 13 项，合计 145 项通过。
  其中两项取消测试需要只读 `ps` 权限，在解除该沙箱限制后通过。

隔离实验使用模拟模型，不代表执行了真实小说生成或模型内容质量评测。
