# 封面初始生成任务刷新恢复

日期：2026-10-11，Asia/Shanghai。

## 问题与复现

用户报告封面生成虽在后台运行，刷新后却看不到任务。旧工作室把 Job ID、轮询和进度保存在组件内存；页面卸载后这些状态丢失，重新进入只读取候选列表，生成按钮可能恢复可点。已先用页面卸载／重新挂载测试复现：后台仍 running，按钮却启用且进度消失。

问题影响初始封面批次，不依赖某本小说的故事、模型或构图。此次统一修复项目、讨论和项目旧版生成入口；单张重试、重新评估、排版应用仍沿用原任务流程，不宣称它们已经具备相同的恢复能力。

## 实现

- `api/cover_generation_tasks.py` 在所属封面目录的 `generation_tasks/` 原子保存任务、Job ID、方向 ID、精确候选组 ID、阶段、数量、时间和失败原因。
- 保持原 `POST /covers/generate` 的 202 Job 合同，增加 `task_id`。项目与讨论都有 `GET /covers/generation-tasks/latest` 和按 task ID 查询接口。
- 现有 JobRunner 继续异步执行，活动批次按所属作品／讨论去重；来源绑定入口在额度预检前返回已有任务，避免已预留额度导致重复请求无法找回原任务。worker 再检查来源绑定与批准，再由原工作流预留额度。
- CoverService 在准备、生成图片、合成、审核、整组比较和保存边界发布真实进度。首次保存候选组后立即绑定其 ID；不通过「最新集合」或列表差集猜测。计数必须与磁盘上的候选一致。
- 任务进度保存失败会抛出不被候选错误处理吞掉的异常，在下一次付费操作前停止。已经消耗的额度保留；不自动重绘、不退款、不重放。服务重启后未完成任务显示中断，查询不会重新派发工作。
- `useCoverGenerationTask` 挂载时只读取持久状态；提交后按精确 task ID 查询。POST 响应丢失时先查任务，不自动重发。断线、初始查询、候选组尚未同步时保持按钮禁用。
- 页头展示当前阶段、候选序号、已处理／可查看／生成失败数量、真实耗时和状态同步时间。已处理包括失败尝试；生成完成、图片可查看和质量审核通过不混为一谈。
- 完成时只选中任务绑定的候选组；跨作品迟到响应、页面卸载后的请求、初始旧列表均不能覆盖新结果。先显示已确认终态，再读取图片；图片读取失败不把 completed 改回 running，已有错误说明仍保留。
