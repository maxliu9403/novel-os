# 头脑风暴模型诊断日志

原有任务日志只能证明 Codex 调用开始、结束或超时。轮询 `communicate()` 时没有
保留输出事件，超时后又清理临时目录，无法判断最后活动、连接重试及是否已有输出。
本次补充可持久化的执行元数据，不修改模型、推理级别、提示词或超时时间。

## 日志位置与关联

默认部署的文件位于：

```text
docker-data/workshop_v2/<完整讨论 ID>/diagnostics/<版本>-brainstorm.jsonl
docker-data/workshop_v2/<完整讨论 ID>/diagnostics/<版本>-titles.jsonl
```

多工作区使用原有会话所属目录。每条 JSONL 记录包含 UTC 时间、讨论、后台任务、
版本、操作和尝试次数；开始模型请求后另含唯一 request_id。格式修复会保留各次
尝试的记录，使用同一轮原有总超时预算，不会因为写日志额外调用模型。

## 记录内容与读法

- `attempt.start` / `request.start`：调用配置、系统和用户上下文的字符数与字节数。
  `max_tokens` 是配置值，不代表 Codex CLI 实际应用了该上限。
- `process_started` / `stdin_sent`：进程启动及完整输入交付。输入改用匿名临时文件后，
  后者表示输入与 EOF 已可供子进程读取，不表示 CLI 已读完或模型已经接收。
- `first_output`：首次观察到进程输出；`first_cli_event` 是首次识别的 Codex JSONL
  事件。两者都不等于模型的首个正文 token，也不能证明模型正在持续推理。
- `cli_event` / `retry` / `cli_error`：允许的事件类型、重连编号、可识别的 HTTP
  状态与固定错误类别。重连次数按日志中最高编号记录，不能覆盖未输出的内部重试。
- `heartbeat`：无其他诊断事件时，每 30 秒记录一次存活检查及最后输出距今时长。
- `cli.timeout` / `cli.cancelled` / `cli.failed`：记录最后阶段、输出字节数、最后
  CLI 事件和临时结果文件的存在与大小。终止进程后有界读取剩余输出，再清理临时文件。
- `request.*` / `attempt.*`：区分底层调用结束与应用校验结果；`validation.failure`
  和 `format_retry` 记录 JSON、结构合同、基础设定或书名格式问题的固定类别。

CLI 阶段包括 `startup`、`input_transfer`、`awaiting_cli_event`、`cli_active`、
`turn_completed`、`turn_failed`。HTTP 类提供商目前记录请求边界和校验事件，
没有 Codex 级别的进程细节。

## 保留边界

采用字段和值的白名单，不持久保存提示词、用户构想、原始 stdout/stderr、认证信息、
原始错误正文或模型思考内容。stdout 只解析指定 JSONL 事件；模型正文里的“HTTP”
或“重连”不会被当作网络故障。未知或超长行被丢弃并记录计数。

诊断目录权限为 0700，文件为 0600。单文件上限 5 MiB，预留 64 KiB 给结束记录；
容量不足时写入截断标识，保留最新结束记录。写入失败不会改变模型结果或重试次数。
界面继续显示简明讨论日志，详细日志由运维在会话的数据目录中用 `tail -f` 查看。

这些日志只能记录启用后的调用，不能补回此前 900 秒超时请求已经丢失的输出。
