# 对 Romance 200 Rewrite Kit 的核对

2026-11-05。对象为 `/Users/max/workspace/goodnovel/GoodNovel_Romance_200_Rewrite_Kit`。本文记录可核查的问题；全量正文阅读覆盖由独立台账决定，不因本审计完成而视为200本已读完。

## 可以保留的基础

本地原始目录与 Kit 的书籍 ID 集合一致：200本。metadata 均列 Romance，共1,743个所列章节文件、90个去重原始标签；没有缺失的清单路径或未列出的章节 Markdown。原始状态164 Completed、36 Ongoing；194份 metadata 声明 rating_verified，6份没有评分人数。这里的 verified 是采集记录字段，不是本次独立核验了平台评价真实性。

200书都有cover.jpg、overview.md和reading_guide.md，但只有10书具有raw目录。因此导入协议不能要求raw必备。metadata的`complete=true`在200书全部出现，它描述采集完成状态，不能代替小说Completed/Ongoing，也不能证明拥有付费全文。

Kit 对类型、关系、冲突、主角行动和章末期待的关注可以作为研究问题；它也明确提醒没有阅读付费全文。这些优点值得保留。问题在于后续 Prompt 把局部统计和假设变成了全体小说硬规则。

来源：[文件及哈希清单](source-inventory.json)、原 Kit 的 `catalog.json / design_summary.json / design_profile.json`。清单没有进行语义阅读。

## 需要纠正的推断

| 原做法 | 核查结果 | 新系统处理 |
|---|---|---|
| 用前三章与末免费文件提炼整套故事机制 | `design_profile.json` 的 chapters_read：198本为3、一本为1、一本为2，合计597；另有断点分析。不是1,743文件完整阅读 | 逐书读完实际提供范围，标签未观察、未知后续分别记录 |
| 把最后免费文件当作付费转化断点 | 作者通知、番外、续作广告混入目录；最后提供的文件未必是连续正文末章，也未必对应可测量付费断点 | 区分文件角色和故事顺序；没有转化数据就不称为转化效果 |
| 所有 Romance 前10章执行同一节拍 | 已读作品有事业与友情开场、双向轻喜剧、长期生存困境、未来番外等；并不存在统一十章结构的证据 | 保存多种机制，按本书因果和篇幅设计 |
| 每章一次权力变化、对话40–55% | 比例来自局部启发式；反应、日常互惠、情感恢复也能给读者价值 | 编辑评价有效变化与体验，不机械凑比例或权力逆转 |
| 男主必须更有权力、女主必须由弱转强 | 多本女主原已拥有财富、能力或职业成就；部分关系与身份结构不同 | 权力分维度，性别/能力/资源按作者和本书设计 |
| 目标读者固定18–35岁、默认中文长篇 | 样本多为英文，未提供可靠读者年龄证据 | 读者、语言、长度独立由作者设定，英文词数不直接转成中文字数 |
| 书长映射成80或100章的新作 | `story_cards.json` 中121本建议100章、67本建议80章 | 根据本书场景容量与每章设置分配，不从参考书总章数推定 |
| Regret等价追妻并默认复合 | 悔恨和重新建立关系是不同承诺；免费范围通常不足以验证结局 | 独立Tag；是否复合由作者采用的方向决定 |
| 避免连续8词重复即可保证原创 | 人物网、独特桥段、事件顺序和关键揭示仍可能高度重合 | 参考创作重建独立因果；文本重合只作为风险信号 |
| 把 overview / 自动人名列表称为故事骨架 | overview 是生成内容，人名识别可能漏主角、误认一般词；其解释不天然高于原文 | 作为待核实辅助资料；正文和官方简介保留各自证据 |

不能用“200本热门作品中常见”证明某种结构导致高质量或商业成功。样本有选择偏差，且小说状态、规模、阅读量与评分的含义不同。

对200份`rewrite_prompts.json`的直接字符串核对还发现：全部200份都写入同一个“第1章危机、第2章男主/盟友、第3章首次公开冲突/亲密升级”的解释，并统一建议18–35岁读者、出现平收则升级钩子。这是生成任务卡时施加的共同模板，不能反过来作为200本原作都遵循该结构的证据。它恰好会放大用户希望避免的内容同质化。

## 已定位的具体例子

### 作者通知被当成章末钩子

`Ex-Husband's Regret`（31000657155）提供的第8文件实际标题为 Chapter 44，全文是作者因个人状态暂缓更新的通知。Kit 将其结尾致谢文字当作 `平收/场景收束` 的免费断点短引，继而建议改成悬念钩子。这里先要纠正的是文件角色，不是叙事强度。

见[逐书笔记](book-notes/31000657155.md)及该目录 `008_Chapter-44.md`。不能与另一部同名不同ID的作品（31000750233）混淆；后者第5章是故事场景。

### 番外并不补全缺失的中段

`DEVIN`（21000013234）的前5文件为离职与追回开场，第6文件是发生在婚后育儿阶段的 Christmas Special，含新书推广。能观察番外中披露的未来状态，但不能声称读过从开篇走到该状态的关系修复过程。

见[逐书笔记](book-notes/21000013234.md)。

### 元数据标签不保证正文已经兑现

`Baby Genius: Daddy Is A Billionaire`（31000511405）的免费内容涉及八个孩子，而 Twins 标签不能准确描述该事实；天才能力与契约婚姻也不能仅靠标签就写成已观察的免费剧情。相关书名以原始 metadata 为准，不能根据Tag改事实。

见[逐书笔记](book-notes/31000511405.md)。这种差异说明类型知识可以规定新书要兑现什么，但不能反过来替原作编造它已经兑现的证据。

### 简介和正文时间尺度不同

`Billionaire's Substitute Bride and Her Secret Child`（31000101092）的简介用孩子推动父母亲密的对话承诺团聚；所提供5章主要写生产危机、父亲丧失、学业与重逢，孩子的该项推动尚未兑现。简介可预告后续，但分析时必须分开“承诺”和“已读到的执行”。

见[逐书笔记](book-notes/31000101092.md)。

### 作者声明的重复发行与非独立样本

`The Billionaire’s Fight For Redemption`（31001092545）的第6文件 `006_Chapter-33.md` 是作者通知，包含年龄纠错，并称本书与 `Ex-Husband’s Regret` 中的Noah故事内容相同、涉及翻译发行安排。前5文件是叙事，第6文件不能作为故事钩子。这里报告的是作者声明，尚未以另一书相应付费段落逐字核验。

见[逐书笔记](book-notes/31001092545.md)。200个书籍ID因此也不能直接当作200个互相独立的叙事实验。统计应按来源条目如实列数，对跨书重复的已知线索单列，不用未知的去重率改写样本规模。

### 同名标签并不总是同义

`Rude Awakenings`（31000001163）的Affair在所供五文件中没有婚外关系依据，First-Person POV却与实际第三人称近距离叙述不符。`My Crippled Husband who loves me dearly`（31000415196）所见年龄24与25，不能仅凭Age Gap就归纳显著代际权力差。

见[前者](book-notes/31000001163.md)、[后者](book-notes/31000415196.md)。源标签应保留原值，知识条目另行明确语义，不能从统计频率直接生成无歧义的系统分类。

## 替代方法

将Kit视为索引和待检验假设集。完整逐书阅读后，提炼：人物处境、具体行动、信息分布、选择代价、即时回报、剩余承诺、简介的销售方式，以及相同Tag的不同实现。保留例外，降低只会生成一套离婚豪门结构的风险。

研究输出不直接进入每次模型请求。编辑后的 Genre/Tag Markdown 才是创作入口；原文证据、研究统计和未采用方案保存在独立研究层。正文阶段不重复灌入200本分析或每本的完整原始语料。
