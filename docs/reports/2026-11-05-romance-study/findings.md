# Romance 研究结论与系统落地

2026-11-05。已完成200本所提供免费范围与200份官方Synopsis的逐书完整阅读；1,743个章节目录文件与200份简介，共1,943份阅读声明通过当前来源哈希和范围核对，见[coverage.json](coverage.json)。每书有逐文件观察；章节目录包含公告、预览、番外与重复，不能把文件数等同连续故事章数。未读付费部分不作结局判断。本文不是源站排名报告，也没有真实付费转化数据。

## 1. 核心判断

值得学习的不是一套“豪门受辱—身份揭露—追妻”的固定情节，而是把**人物真正需要的东西，放进有具体成本的关系选择里**。优秀的局部场面往往同时完成三件事：让读者在意一个人，让一个关系发生变化，并给出继续读下去的具体期待。

这批作品并不都具有同等质量。重复误会、身体反应代替感情发展、强行降智、错误职业或身体知识、代词/姓名漂移、作者公告被当章节等问题都存在。平台分类、评分和阅读量不能把这些问题变成写作原则。新系统要学习有效机制，并明确拒绝把源书缺陷也“忠实复制”。

对 Novel OS 最有用的改造是：**Genre 定义主要阅读承诺；Tag 定义怎样改变故事；模型为本书选择具体实现；既有写作与编辑流程负责把实现写成场景。** 更换 Markdown 格式本身不提高文笔，真正重要的是这条传递链及知识内容。

## 2. 可以迁移的七种机制

下面是多书观察后的编辑归纳，不是七条所有小说都必须同时满足的机械门槛。

| 机制 | 原文观察 | 可以怎样用于新小说 | 不能机械学成什么 |
|---|---|---|---|
| 具体劳动让关系价值可见 | 《I Quit Being a Stepmother》用过敏清单、陪诊、洗澡和孩子证言呈现实际养育；《Mute Wife》用手语交流、学校演出、喂饭和座位呈现理解与排斥 | 先让读者看见人物做了什么，再让否认、承认或重新分配产生情绪 | 所有女主都必须靠牺牲家务证明价值 |
| 资源兑现后产生新的代价 | 《NO ONE ELSE COMES CLOSE》家产恢复已经兑现，却成为持续控制的杠杆；《My Marriage Is A Contract》口头与书面条款差异改变退出空间 | 让一次“解决问题”真实有效，同时引出人物必须面对的新选择 | 契约必须是男方单向控制，或者虚构合同一定现实有效 |
| 相同空间持续改变关系 | 《Rude Awakenings》的薄墙、走廊与房门反复改变距离；《Mute Wife》的餐桌与沟通工具不断改变谁被接纳 | 重用有生活功能的地点或物件，改变谁有决定权、谁主动回应 | 每章重复同一段争吵、每次都添一个新坏人 |
| 吸引来自被具体理解 | 《My Crippled Husband who loves me dearly》让设计评价、一起钓鱼的设想和先做朋友构成亲近；《Resent, Reject, Regret》的工作与暂不逼问伤痛形成另一种支持 | 写出对方看见了何种能力、需要或顾虑，并用行动回应 | 有钱、好看、送礼或占有就等于爱情成立 |
| 信息差改变不同人的行动 | 《Our Billion-Worth Twins》孩子交换身份且各有自己的愿望；《Married by Mistake》冒名与伪造信息改变判断，但不能抹去实际伤害 | 区分读者知道、角色知道、角色误判；新信息必须改变选择 | 所有人永远拒绝解释，以误会无限续章 |
| 亲近与离开都付代价 | 《The Billionaire’s Fight For Redemption》长辈求助让已经退出的女主再次靠近；《I Quit Being a Stepmother》孩子的爱既是支持，也是离开的牵挂 | 给人物两个有价值但不能轻易兼得的东西，让选择体现性格 | 每次两难都靠增加灾难，或者选择只能由强势伴侣代做 |
| 即时价值和长期期待并存 | 互相尊重、孩子维护养育者、一次专业认可、一次机智反击，都能在远期关系尚未解决时给读者回报 | 每个主要场面让读者获得某种理解、情绪或进展，再留下新期待 | 每章必须权力逆转、吻到一半或悬停在危险前 |

证据：[继母与孩子](book-notes/31001089435.md)、[手语与家庭](book-notes/21000012245.md)、[资产与退出权](book-notes/31000397918.md)、[双层契约](book-notes/31000258755.md)、[薄墙与边界](book-notes/31000001163.md)、[互认能力](book-notes/31000415196.md)、[工作与信任](book-notes/31000403570.md)、[儿童自己的目标](book-notes/31000297886.md)、[冒名与责任](book-notes/31000003975.md)、[求助重启关系](book-notes/31001092545.md)。每份笔记保留逐文件定位。

这些例子既有可借鉴之处，也有重复、越界或因果薄弱之处。例如愿意先做朋友的场面与占有性用语可能出现在同一本；研究必须分别记录，不能整体盖上“高质量模板”的印章。

能力也应通过行动换取具体空间。《Sentenced to Marriage》以电脑维修争取续租和迁址，《Five Years of Marriage to Mr. Bradford》通过学习与导师关系恢复行动空间；这与突然赠送巨额财产、万能儿童一次解决所有问题不同。不是要求每部小说都写事业线，而是让奖励与人物已经展示的能力和选择有联系。见[维修交易](book-notes/31000313756.md)、[学习与重新接纳](book-notes/31001218698.md)。

**日常磨合与温暖开场同样可以承载故事。**《Married at First Sight》十二章主要通过早餐、门锁、消费记录与工作分工推进陌生夫妻，男方身份尚未向女主揭开；《The Arranged Bride》的女主已有营销职业、好友和尊重她的父母，相遇来自与孩子的互动，不需要先把她写成孤立无援。两书也有信息不平等或先入为主的问题，但反驳了“只有离婚反击才有看点”的单一路径。见[陌生夫妻的生活磨合](book-notes/31000384431.md)、[职业与温暖家庭](book-notes/31000064559.md)。

## 3. 为什么同一个 Tag 不该产生同一部小说

标签是机制入口，不是具体剧情。多样性不靠随机换职业和名字，而靠关系与行动的不同组织方式。

| Tag | 已见到的差异 | 应写入知识的变量 |
|---|---|---|
| CEO | 有的直接控制雇佣与工作资源；有的是女方自己经营；有的仅落在家长背景，未真正推动爱情 | 角色是谁、资源能否使用、工作责任、依赖关系、权力边界 |
| Independent | 从退出隐形劳动、保留现有工作，到追回知识成果、以多份工作维持抚育 | 想自主决定什么、已有何种能力、还依赖什么、承担什么后果 |
| Contract Marriage | 父辈强迫安排、双方一年退出办法、资产交换与单向退出权并不相同 | 为什么签、双方获益、知情差、可否退出、条款怎样改变相处 |
| Hidden Identity | 婚姻隐瞒、亲子错认、职业身份、冒名补偿对象、身份恢复 | 谁隐瞒/误认、谁知道、为什么相信、揭露如何改变既有选择 |
| Sweet Love / Comedy | 互认专业能力、可拒绝的邀请、生活摩擦与机锋，均不同于持续撒糖 | 具体互惠、人物声音、目标错位、笑过之后留下的情感变化 |
| Regret / Second Chance | 后悔、寻回、原伴侣重建关系是不同阶段，不是一组可互换标签 | 谁悔恨、承担什么、谁有选择权、作者是否承诺再次结成关系 |

除上述证据外，见[女方也有经营能力](book-notes/21000008120.md)、[职业依附](book-notes/31000654418.md)、[继承不等于自由](book-notes/31001148338.md)、[双亲分养的信息差](book-notes/21000005929.md)。

知识中应提供多个可变化的轴，但不让每本故事轮流勾选全部变体。首轮方案只需在主要行动、关系权力或最终回报上给出两三个实质不同的选择。作者采用后，后续章节围绕这一版本发展，不能每轮随机换方向。

## 4. Genre / Tags 的语义必须先整理

本地 200 份 metadata 的 Genre 都是 Romance，出现 90 个不同原始 Tags。完整清单与本数见[标签表](romance-tags.md)。它说明这批书如何被标注，不证明整个站点只有这些标签，更不证明每本免费章节都兑现了所标标签。

这些 Tags 实际横跨关系机制、身份、世界背景、情绪、节奏和 POV。前端可以分组帮助选择，但不必把这些组变成四次强制填表。一个 Genre 后选择多个相关 Tags 足够，标签的作用由知识条目解释。

必须处理的歧义包括：

- `Affair`：有的作品涉及既存婚姻，有的只是在写恋情；《Rude Awakenings》所提供范围没有婚外关系依据。不能统一翻译为“婚内出轨”。
- `Age Gap`：《My Crippled Husband who loves me dearly》所见年龄是24和25；《On My Professor’s Bed》是20和39且存在教学权力。不能只凭相同标签推断同一故事结构。
- `First-Person POV`：《Rude Awakenings》实际为第三人称近距离，说明元数据也可能错误。
- `Lawyer`：在《NO ONE ELSE COMES CLOSE》中体现为协助女主的父亲律师，不是女主职业。
- `Divorce`：在《Wrong Ride, Right Lover》所供范围对应父母离婚，不能自动把女主写成离婚人士。原始标签附在整本书上，实际作用人物仍需阅读确认，见[笔记](book-notes/21000015507.md)。
- `Twins`：《Baby Genius: Daddy Is A Billionaire》所供故事涉及八个孩子，不能由标签反向改写事实。
- `Alpha / Rogue / Agent / Hero/Heroin` 等原值需要核实具体含义，不能凭一个词自动加载完整狼人世界或特工设定。

证据：[教授的权力关系](book-notes/31000681047.md)、[双胞胎标签与实际孩子数量](book-notes/31000511405.md)，及前述对应笔记。

新系统保留原始 `source_label` 供追溯，另建明确的 `knowledge_id`。同一名字有多义时先辨义再启用；不要为了“支持90标签”而快速生成90份含义空泛、彼此冲突的提示词。当前已提供一个 Romance 与十个 Tag 的完整 Markdown 编辑样例，其余先作为研究候选。

H5 的合法发行 ID 是第三层身份，不能直接拿源站英文标签做 ID。无精确映射的元素仍可指导创作，但不会被自动导出为非法分类。详细规则见[整体方案](../../design/genre-tag-studio-v1/README.md)。

## 5. Synopsis 应怎样设计

这里的 Synopsis 是读者简介，作用类似本系统的 `publication_copy.spoiler_free_blurb`。它不等于包含结局的故事地图，也不等于章节介绍。

已见到几种不同方法：

1. **关系循环**：先让读者知道两人为什么互相吸引又抵触。《Rude Awakenings》的简介承诺与五个文件中的关系循环较贴近。
2. **价值被否认—主角采取行动**：用离开、离婚、追回生活决定权组织简介。《I Quit Being a Stepmother》的方向成立，但简介与正文谁先提出离婚并不一致，定稿应修正这种责任与行动错位。
3. **双方立场对照**：《The Billionaire’s Fight For Redemption》用两个声音出售爱与怨的矛盾；免费正文尚未兑现简介中的意外消息，应标为远期承诺。
4. **未来名场面预告**：《Billionaire’s Substitute Bride and Her Secret Child》的孩子推动团聚对白主要是后续承诺，所供开篇先建立生产危机、失去支撑与重逢。分析不能用简介代替未读正文。
5. **泛化邀约**：有些简介只有“进入这段冒险”的泛邀，主要信息靠书名和开篇承担。这是样本中的弱例，不建议将其写成系统默认。

证据见上述笔记，以及[未来团聚承诺](book-notes/31000101092.md)、[泛化邀约](book-notes/31000675787.md)。

推荐让模型回答四个创作问题，但不限定四句话的格式：谁正在失去或争取什么；为什么这段关系/规则让事情特殊；人物会采取什么有代价的行动；什么关键选择仍未解决。可以使用独白、双方对照或具体对白切入，也可提炼首章的关键转折；要避免逐事件复述而丢失关系承诺、直接复制原段落、只列标签、把所有结局说完，或为了刺激承诺成稿没有的事情。

总体方案采用后生成简介草案，作为作者判断故事卖点的辅助；完稿时使用既有出版文案阶段重新对齐真实正文。正式书籍简介保持唯一发布字段，避免 UI、EPUB、H5 各自保存不同版本。语料没有证明某一个固定字数或对白比例最优，继续遵守现有语言与长度合同即可。

## 6. 初步分析 Kit 的主要问题

完整核对见[审计报告](preliminary-kit-audit.md)。最关键的不是哪条建议措辞不够好，而是推断层级混在一起：

- Kit 的 `chapters_read` 合计597，另有末免费文件分析，不能代表1,743文件通读。
- 200份生成任务卡都套入完全相同的前三章节奏。这是分析工具施加的模板，不能反过来说200本原作都如此。
- 最后免费文件有时是停更通知、广告或未来番外。对“作者谢谢大家”的结尾提出更强剧情钩子，是先把材料角色判错了。
- 部分资料包含跳章、重复段落和作者所称重复发行；200个书籍条目不自动构成200个互相独立的故事样本。
- 有些书籍实际是短篇集；一个条目的几个文件可以属于不同人物故事，也可以只是同一场面的连续分段。导入分析须区分叙事单元，不能直接把所有角色拼成一本长篇人物网。见[多组故事](book-notes/31001069714.md)和[同一场面的连续分段](book-notes/31000532599.md)。
- 从免费开篇推断完整追妻、原谅或婚姻修复，以及依据总章数推荐新书80/100章，均缺少足够依据。
- 八词不重复只能是有限文本信号，不能证明新故事具有独立人物网与因果结构。

这些问题不会使原 Kit 完全无用。书籍索引、原标签统计与提出的研究问题可以保留；固定情节、年龄假定、比例和因果结论需要撤下或重新标为待验证建议。

## 7. 研究如何进入系统，又不引入新的昂贵评议

研究层保存原文位置、观察、反例和不确定性；知识层只有经过编辑的 Genre/Tag Markdown；单书层只保存作者选项和本书采用的实现。三层不互相堆叠。

| 用户目标 | 系统动作 | 验收看什么 |
|---|---|---|
| 更有故事感和情绪回报 | 在现有讨论、骨架、章节与编辑请求中，落实人物目标、压力、选择、代价及阶段性价值 | 看具体场面是否可感、对白是否有不同目的、反击/温柔是否成立 |
| 同类小说不再换皮 | 知识提供变化轴；总体方案改变关系权力、行动或回报；参考创作隔离原作独特事件链 | 同组合两部方案是否拥有不同主要因果，而非换姓名职业 |
| 作者选择真正影响作品 | 冻结一个Genre和多Tags，记录版本与本书实现，按阶段投影到同一生成管线 | 工程核对传递；编辑核对移除标签后关键选择是否仍完全不变 |
| 更低成本、更稳定 | Markdown 编译不调用模型；来源分析一次复用；去掉完稿逐章M3；保留既有章节编辑和连续性 | 同预算请求是否更少、恢复是否复用、实际模型耗时与输出是否可观察 |

不让标签验证再次变成“全书读一遍—语义修复—再读一遍”的循环。文学表达弱在已有编辑步骤内处理；真正漏传、非法引用、导出格式错误由确定性代码定位。结构完整不等于文学质量已经通过。

这批语料足以改进开篇、关系发动方式、简介和标签含义，但不足以证明完整长篇的中段、结局修复和商业留存。后续其他Genre仍按同一研究Skill完整读取所供范围；真实生成验收使用少量新的构想与开篇，避免把已经研究过的200本称为未见过的测试集。
