## 已实现的系统边界

作品库和命令面板已改用新的持久查询模型。HTTP 列表不再调用旧的全书加载、正文统计、封面历史或恢复校验。旧 `/api/projects` 仍保留兼容行为，现有作品详情、下载、恢复、晋级与出版质量门保持原有权威入口。

| 模块 | 实现内容 |
| --- | --- |
| `api/library_catalog.py` | 作用域化 SQLite 摘要、持久变更队列、组件缓存、删除墓碑、epoch/generation 防护、SQL 筛选和游标分页、changes/navigation |
| `api/library_indexer.py` | 旧书只读发现和回填、受限后台轮转、分域版本缓存、有效章节计数、外部修改补偿、衍生缩略图 |
| `api/library_runtime.py` / `api/library_routes.py` | 应用生命周期、按 root/workspace 隔离、分页 API、ETag、上下文作用域、只读缩略图响应 |
| `core/projection_events.py` | 权威提交前后的持久失效通知；观察者失败不改变已保存小说的结果，后台补偿负责恢复 |
| `api/jobs.py` | 单次、脱离可变对象的运行态快照；root 局部 revision、启动 epoch、有界变更历史 |
| `web/src/lib/libraryResource.ts` | 有界共享缓存、在途合并、取消/超时、服务端分页与筛选、增量同步、失焦暂停、退避、跨路由保留 |

分页默认 20、最多 50；changes 默认 100、最多 200。列表、筛选计数、游标与 ETag 使用同一个运行态快照；磁盘里的历史 running 不等同于当前进程仍在工作。未知、旧或重启前的变化游标要求重新同步。卡片进度变化不会使普通分页游标失效，集合成员变化会明确要求重新查询。

前端在后台更新时保留已加载的多页窗口和滚动位置。删除墓碑、请求代次、持久版本和运行版本共同防止迟到响应复活已删作品或覆盖新状态。对不可比较的版本组合会重新校对，而非确认一个被丢弃的更新。命令面板能搜索尚未加载的作品页。

## 数据、质量和删除语义

- 回填通过安全的只读文件接口读取快照，不实例化会建目录/锁文件的 StoryState 或 ArtifactStore，不给旧书创建身份文件。
- 原文、细纲、检查点、讨论记录、原始封面、ZIP 均保持原样。卡片中的简短说明仅用于展示，没有替换模型的故事输入。
- 计数缓存按有效 Final/revised/draft 来源及计数策略版本绑定；英文显示词，中文显示字。`final_count` 表示存在 Final 来源，不宣称已经获得质量审批。
- 任务、章节、封面、交付、来源各自缓存及失效；单个域损坏保留已有可用内容及诊断，一本坏书不阻塞整个作品库。
- 提交通知先保存失效记录；扫描补偿 CLI 修改、外部修改、通知丢失和中断。摘要与指纹必须来自同一份核验快照，不能在核验后用新文件指纹标记旧内容。
- 删除先提交持久墓碑再删权威数据，清理摘要内容、组件和缩略图。迟到的索引和图片渲染不能写回旧 epoch；中断清理可重试。删除记录写入失败时，尚未提交的作业封锁会回滚，完整作品仍可继续操作。
- 成功的新作品初始化会显式打开新的目录 epoch。扫描器没有权限复活删除中的旧书；创建入口也不复用残留旧文件的目录。

删除清理指应用可见行和衍生文件，不承诺擦除操作系统缓存、SQLite 历史空闲页/WAL 或用户已有备份。

## 配置与迁移

SQLite API 默认在原数据库中增加 `library_*` 表，其他表不删除。Postgres API 可继续使用原 URL；查询目录使用独立 SQLite，默认 `novel_os.library.sqlite`，也可用 `NOVEL_OS_LIBRARY_DB=sqlite:////data/library.sqlite` 指定位置。缩略图放在查询数据库旁的 `<数据库名>.library-cache/` 下。

应用启动后后台发现旧书，先提供占位卡片，再分批补齐摘要。GET 缺索引时返回 rebuilding，不回退同步读取整书。可以通过版本化 API 和前端版本进行分阶段切换；回滚旧软件不需要覆盖或删除小说数据。首次回填成本、旧缓存失效和异常域在页面上有可见状态。

本轮完成批准方案 A–D。阶段 E 的持久作业租约、独立创作 worker 和全书完整性核验批处理仍是后续工程；本次没有把现有 JobRunner 改成多进程，也不通过减少质量校验提速。

## 回归与性能证据

最终后端 23 个影响集文件 **419 项全部通过**，耗时 103.96 秒，记录在 `output/library-performance-implementation-20261114/backend-junit.xml`。覆盖旧 API、任务取消/恢复、制品、交付版本、封面、删除、分页、作用域、重启、读后变化、身份、损坏单书及异步响应竞争。前端全量 **749 项**通过，最终展示改动相关 **45 项**通过；TypeScript/Vite 构建、修改文件 ESLint、Python编译检查及 `git diff --check` 通过。

性能测试均使用隔离数据，不向线上模型或生产 API 发请求。以下不同层的测量不能合并成线上端到端结果，也不能据此计算相对现场旧接口的精确提速倍数。
