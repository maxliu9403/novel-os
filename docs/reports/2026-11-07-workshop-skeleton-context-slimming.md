## 实现

持久化骨架继续是一份完整 Markdown。请求构建使用 `workshop-delivery-context.v1`，由纯函数生成阶段视图，不改写文件、作者选择或 Genre/Tag 原文。

| 阶段 | 读取内容 | 消除的重复 |
| --- | --- | --- |
| 全局故事设计 | 原骨架全局各节、全部章节标题、组织形式、完整对话、作者设定、参考资料、当前阶段的冻结 Genre/Tag 说明 | 章节正文规划延后到下一阶段读取；发行分类由代码按作者选择绑定 |
| 完整章节规划 | 每章原文全部保留、新完成的全局设计、全部用户原话、最近模型回复、已采用提案、待定事项、参考资料、当前阶段的冻结 Genre/Tag 说明 | 不重发旧全局设计、旧故事地图与早期模型探索回复；它们已由前一阶段读取 |
| 交付整合 | 已通过结构校验的全局设计和全部章节 | 代码本地组装，不再让模型复制整份骨架 |

早期模型消息使用明确占位保留原索引，避免作者引用索引改变。投影会告诉模型当前阅读范围、哪些内容由下一阶段接手、以哪份全局设计为准；不能假装每一次请求都包含完整材料。未决假设和待定问题不转为已确认事实。

只对系统生成、完整可识别的六节 `story-first.v1` 骨架启用：章节连续、章节总数与头部一致、两段终端 JSON 合同合法且无额外尾文。未知格式、扩展标题、缺章、重复 JSON 键等保持完整上下文，宁可明确超限，也不猜测删除内容。首次交付没有已有骨架时沿用完整输入。

超限使用 `GatewayInputLimitError → LLMInputLimitError → input_limit` 分类，页面明确显示输入字节数、连接上限、请求未发送以及保存结果仍保留，不再误报为“请检查模型配置”。设置页同步上限说明。
