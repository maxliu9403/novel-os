# 参考续写规划与 Genre / Tags 全库升级

日期：2026-11-06。已部署到 http://localhost:5174 。本次未启动真实模型请求或小说创作。

## 用户可见行为

1. 新的参考资料分析在最后一次阅读或汇总回复中，输出独立的续写提案：总体走向、建议结局、3–6 个戏剧单元，以及少量需要作者决定的大方向。每个单元包含叙事视角、原文依据、具体核心剧情、看点／爽点、伏笔与兑现、末尾钩子。它们不是固定章节数，也不替代后续头脑风暴确认的完整骨架。
2. 已完成的旧分析可点击“生成续写规划”，复用已保存的分析与覆盖记录补充一次规划；若需要模型重新读取原文，明确选择“重新读取”。失败和暂停仍保留检查点，不自动追加调用。
3. 分析结果按 SHA 保存为不可变版本；重新分析不会覆盖旧成果。用户可选择历史分析创建多个讨论，即使新一轮分析尚在运行，也可使用已保存的有效版本。每个讨论和作品冻结自己的来源版本。
4. 参考资料展示关联讨论、未完成作品和已完成作品的数量与链接；作品库卡片展示参考资料入口。没有来源绑定的历史作品不猜测补关联。
5. Genre / Tags 默认显示“阅读预览”，随后是“编写 Markdown”和“版本记录”。历史版本可通过“使用 vN”重新启用，保留所有版本；现有小说与讨论的冻结资料不变。

## 创作边界与知识升级

按用户确认：原创及新增人物全部 18+；原故事保留已有角色的年龄事实，亲密互动仅限成年人。不会把来源中的儿童静默改为成年人。

40 个 Tag 均已升级启用。其中其余 35 个完成实质性生成式重写；此前优化的 Action、Dark Romance、Possessive、Badboy、Age Gap 保留机制并统一创作基调。用户已确认的 Romance 说明保留主体内容，补入共同基调。

共同基调包括女频／女性向情绪回报、主角主体性与情绪掌控力、成年人之间非露骨的高浓度张力。主角仍可受伤、犹豫、求助；甜宠、喜剧、悲剧等按自身情绪契约兑现，不强制统一结局。

各 Tag 保持独立的故事功能，不再要求固定前十章节拍。背叛不等同于必然复仇，后悔不等同于必然复合，二次机会需要核心关系的实际重建。发散机制供模型设计，不是所有作品逐项执行的剧情清单。

稳定 ID、名称、别名、Genre 关联及公开分类元数据保持不变。外部原始文件未修改；升级前 41 份资料归档在 `resources/knowledge-imports/romance-all-tags-before-20261106/`。逐项版本与哈希证据见 [启用证据](evidence/2026-11-06-reference-planning-tags.json)。

## 实现与模型输入

- `core/source_planning.py` 定义续写提案合同与提示词；事实分析和未采用提案分别存储。提案明确进入头脑风暴输入，作者可改方向，不能自动当作来源事实或已确认骨架。
- `core/source_study.py` 新分析使用 `source-study.v3`；普通新分析将规划合并进最后阅读／汇总调用，不独立增加一个常规规划步骤。旧中断任务保留 v2 的请求绑定、提示词与恢复协议。
- v3 每组原文预算由 120,000 调为 100,000 字节，给协议与规划输出说明预留网关空间；临近阈值的大资料可能增加分组。不能把“合并规划步骤”解释为任意资料的总调用数绝不增加。
- `core/source_versions.py` 校验来源、源文件 SHA 和结果完整性，保存不可变结果，拒绝越界路径和损坏收据。选择历史结果无需重新调用模型。
- `core/source_provenance.py` 只向作品列表投影轻量来源信息，按文件路径、修改时间和大小缓存，避免列表携带章节或完整分析。
- `core/creative_types.py` 在现有并发版本校验与原子保存流程中启用历史版本；不复制伪造版本，不改写历史。
- `core/creation_mode.py` 仅对携带新提案的来源添加提案边界；没有新提案的历史策略保持不变，避免已有请求指纹漂移。
- Tag 导航摘要只影响界面，不删减 Markdown 或模型实际读取的内容。阶段投影继续使用已有版本化编译器。
