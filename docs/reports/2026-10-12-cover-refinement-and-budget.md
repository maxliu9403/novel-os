# 单张封面修复预算与原图精修

交付时间：2026-10-12 00:01，正式环境 `http://localhost:5174`。

## 修复原因与范围

候选 2 的 `semantic_repair` 请求为 441,576 字节，超过 384,000 字节预算。单图修复把已保存方向的完整证据账本嵌进补丁基底，同时又发送权威账本，重复携带 96,444 字节。这是长骨架／大证据集触发的通用请求构建问题，与该本小说的情节或图片模型无关。

现在先校验证据副本与权威账本完全一致，再删除可重建副本，然后生成补丁基底哈希。首次、格式修复和语义修复使用同一归一化基底；保存方向时恢复完整账本。原文、全部证据、四个方向及独立整体审核均保留，没有增加预算或截断内容。

真实记录离线重建：候选 2 从 441,576 降至 345,132 字节，候选 3 从 440,414 降至 343,970 字节。完整 67,306 字节来源、200 条证据和四方向逐值保留。其他真正超限请求仍会明确阻断，不能保证任意长度都能放入当前模型预算。

## 使用方式

1. 在候选封面点击“精修这张”，查看参考图，填写 1–2000 字的优化要求，例如保留人物和主构图，调整光线、色调、表情、背景或标题布局。
2. 点击“制定精修方案”。文本模型只修订所选候选，并按完整故事来源审核；其余方向保持原样。用户要求不能变成新故事事实。此阶段会产生文本模型用量，不调用图片模型。
3. 方案完成后确认“批准并精修这 1 张”。使用实际原图作为参考进行一次图片编辑，生成新版本，再进行质量审核。刷新／切页仅恢复原任务，不重新提交。

不要求图片先有质量阻断，已选中或被拒绝的来源绑定候选也可主动精修。原候选、其他三张、已选交付封面及历史用量保留，新结果不自动被选中。失败不会自动重试或增加图片调用。

## 实现合同

- 项目与头脑风暴复用持久 `cover.repair` 任务；`kind=refinement`，保存原优化要求、原图描述与待批准提案。
- 原图 SHA、用户要求摘要、父批次、具体候选、来源及新方向均绑定；审批前、执行前和图片客户端冻结字节时检查完整性。
- API 用 `/images/edits` multipart 传原图；本次初版 Codex 用图片附件和 `referenced_image_paths`。后续已改为结构化原图附件以修复容器文件沙箱兼容问题，当前实现见[原图精修通道修复](2026-10-12-cover-reference-transport.md)。服务不支持编辑时明确失败，不能悄悄降级为文字生图。
- 组合排版封面编辑保留的无标题原画，然后按新批准布局合成标题；原生标题模式编辑原成品图。新的 A/B 质量审核绑定新原画和新成品。
- 编辑结果保存操作类型、参考图 SHA、传输方式及实际编辑提示摘要。模型身份仍区分请求配置与可验证的供应商报告。
- 同一批准仅保留一次图片调用额度；无效引用、丢失持久检查点、篡改提案、变化来源或不支持的客户端均不能绕过检查。新图片可能连带改变其他细节，不承诺像素级不变。
- 缺少原画、完整来源绑定或带独立导入／排版修订绑定的历史候选仍需沿用原验证流程，不伪造可编辑来源。
