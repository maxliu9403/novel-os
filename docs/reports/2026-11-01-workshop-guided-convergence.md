# 选项式共创与主动收束：交付和工程验收

2026-11-01，分支 `codex/novel-quality-optimization`，基于 `afdf518` 的工作区改动。已部署 http://localhost:5174/。本轮未启动真实模型、未升级作者已有讨论、未自动生成骨架或正文。设计见[批准方案](../design/2026-11-01-workshop-guided-choices-and-convergence.md)。

## 已实现的作者体验

- 新讨论启用 `guided-choices.v1`。关键分岔展示2–3条有具体选择、代价和后果的选项，推荐不默认勾选；通常1组，至多2组。明确局部修改无需凑选项。
- 作者选中方案后可补充任何想法，点击「按所选继续」一次提交。可只写自由文本、清除本次选择、仅保存选择与补充，或主动要求换一组。点击选项本身不调用模型。
- 四项全书设计覆盖折叠显示，优先从主线推进至转折、高潮和结局。已有作者依据、没有核心未决时提示「生成完整骨架（推荐）」；作者也可继续打磨，不强制轮数。
- 建议不改变 `ready_for_confirmation`。生成骨架仍是明确的 `deliver`；生成按钮会带入未发送的补充及所选方案，下载和启动正文保持独立。
- 旧讨论显示「启用选项式共创」，空闲时明确启用后从下一轮生效。消息、已采用方案、版本记录和所选类型快照保持。读取历史不会自动迁移。

## 数据与执行约束

`api/workshop_guidance.py` 独立解释可选建议；基础讨论格式保持兼容。服务端分配方案/分组身份，检查互斥组、引用范围和作者精确原话。没有作者证据的已定项降为提案；格式异常保留原回复和可用旧方案，提示未评估，不追加调用。精确引文有效不代表其语义解释必然正确，界面以「已有作者依据」而非文学质量认证表述。

决定与补充在原会话锁下同修订保存，持久 `operation_id` 防止重复提交。网络失联沿用原请求标识与修订；明确的409/422拒绝允许刷新后以新操作重试。重复已完成请求不会追加调用，进程重启后也不会把旧 HTTP 重试当新任务。已有修订决定继续沿用作者笔记，改选同组方案保留旧账目并明确替代。

新版建议与选项在原有模型回复中一并返回，没有新增成熟度评审模型调用；完整作者对话未截断，模型/推理设置未变。选项差异、合理收束和耗时改善仍须真实样本验收。新增私有记录受到 H5 元数据过滤；分类版本、字段和出版合同没有改动。
