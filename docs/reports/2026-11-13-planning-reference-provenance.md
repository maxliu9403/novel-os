## 已证实的原因

错误不是上下文被截断，也不是应当取消原文引用校验。保存的完整路线回复把模型全书设计里的叙事约束填入了 `source_anchors`，但该字段要求作者采用原文中的逐字引文。

原回复有三条此类引用，全部逐字来自已保存全书设计的 `opening_investment.protected_long_range_discoveries`。后续格式纠正只修复了第一条，仍留下第 4–5 章与第 6–8 章使用的两条。两份完整回复、全书设计和原文均已保留。根因是引用合同缺少模型设计来源类型，通用格式纠正又无法自动解决来源混用。

## 实现

### 原文和生成设计分别建模

- `source_anchors` 继续严格校验原文逐字引文，不做模糊匹配、相似度放行或自动换引文。
- `planning-design-references.v1` 保存模型设计的完整字段文本、类型化路径、种子与原文摘要、稳定引用 ID 和明确的模型来源。
- 新路线请求选择已有设计字段路径，由程序验证并绑定引用；无需模型重复抄写段落、生成摘要或计算哈希。
- 原始完整设计仍按现有上下文合同提供。目录传输只增加可选根字段说明，不重复发送整本设计。每段输出只附加实际用到的引用。
- 引用表示来源，不代表作者明确要求、已发生事件、人物已知信息或不可修改的约束。原文与当前通过审稿的设计约束执行，不能凭历史引用重新引入已经被修正的解释。

### 旧任务从原检查点恢复

恢复仅在错误引文与冻结设计中一个允许引用的完整字段唯一、精确相等时发生，且必须满足：

1. 不重定义先前的原文引用，不接受额外不明引用字段。
2. 所有受影响章节仍保留真实的原文依据。
3. 引用 ID 的每处结构化使用均能完整迁移；没有未解释的使用位置。
4. 所有章节情节、因果、情绪、看点、保留信息和结局字段不变。
5. 纠正后的候选仍通过原来的结构与原文校验。

派生结果单独保存映射、依赖和校验摘要；原请求、原响应、旧检查点保持不变。复用时重新从原候选与证据计算派生结果。文件损坏、证据缺失、歧义或写入失败不能触发旧稿覆盖或额外模型购买。

### 完整纠正链与下游传递

只沿已验证的同一任务模型继承链查找纠正稿，核对原请求全文、输入与响应校验。已经发出的较晚纠正优先，不能因旧回复现在可以通过而倒退；存在不同完整结果时保留分叉。尚未完成的纠正回到原请求会话处理未知或明确失败，不跳过请求，也不另造技术对账入口。相同绑定请求在新模型命名空间完成后，可以关闭旧命名空间里的同一未完成记录。

设计引用从路线传入细纲、发布校验、章节执行与审稿上下文。细纲省略该字段时继承本章的完整引用；显式删除或交换引用被拒绝。发布器不能剥离注册表。独立保存的完整种子依据防止仅凭自洽哈希伪造引用来源。已有无此字段的任务维持原有输出行为。
