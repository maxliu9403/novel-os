# 整书路线实现与验收

状态：业务实现和工程回归完成；随后按作者明确授权，于 11 月 12 日凌晨将 `118153b` 部署至 5174 并恢复原任务，见[部署与恢复验收](2026-11-12-source-routes-deployment.md)。分支 `codex/long-form-planning`。本文的开发阶段工程验收使用临时资料、实际持久层与模型替身，没有让真实作品重新分析或迁移运行任务。

## 完整业务流程

资料库与新建头脑风暴的资料上传/选择共用路线工作台和后端 `SourceStoryDesign`。首次默认生成三条整书路线，后续可修订指定方案或追加其他方向；来源纠错会回读原文。自然语言中同时包含修订、保留和追加要求时，模型在现有生成请求中返回有作者原话依据的后续动作，宿主按依赖执行并保存动作记录，无额外固定分类调用。

路线围绕全部已提供正文的因果和人物处境设计，包含具体第一幕、完整因果推进、高潮与结局、人物关系变化、情绪期待/场面/选择/代价/变化/兑现、故事看点、长线悬念与回收、创作假设和路线差异。三种原有创作模式保留；续写的共同终点依据有序正文，附录预告不能推进终点。缺少原著付费后续本身不阻止新故事开发。

推荐使用真实有效题材目录的身份。作者可以调整频道、一个 Genre 和一至两个 Tags；已有作者选择优先。交接保存具体版本、实际题材与补充原话，直接开启围绕所选方向的首轮讨论。选择方向只为故事地图的 direction 节点提供作者动作证据，不能让模型把全部提议当成作者已经确认。新建表单已有构想保持原文，路线不会自动填成作者的话。

## 业务模块

| 入口或模块 | 职责 |
|---|---|
| `core/source_route_prompts.py` | 作者商业主编版共同提示、三种模式、首次/修订/追加/纠错/研读/整合/讨论提示 |
| `core/source_story_design.py` | 完整研读、路线版本、混合意图、容量分批、请求回执、继续执行 |
| `core/source_evidence.py`、`source_routes.py`、`source_design_store.py` | 精确来源区间、观察和路线合同、追加式持久层 |
| `api/source_routes.py` | 工作区隔离、当前模型连接、目录版本、任务状态、暂停与恢复 |
| `api/workshop_source_handoff.py` | 幂等选择交接、作者输入和题材冻结、首轮讨论、完整证据与封面副本 |
| `core/source_route_context.py` | Workshop 与后续创作共用的完整证据读取和容量协调 |
| `core/source_request_recovery.py` | 区分结构化 HTTP 失败、本地未发送与真正未知的请求 |
| `web/src/components/SourceRoutes.tsx` | 两入口共用的路线比较、情绪详情、修订追加、历史与可修改题材 |

新增 HTTP 入口为 `/api/source-books/{id}/route-runs`、对应运行的读取/暂停/恢复、`route-sets` 及版本读取，以及 `/api/workshop/source-route-handoffs`。旧分析接口继续有效。新来源讨论生成 `creative-handoff.v5` 后由现有小说执行引擎接续，旧版本不被隐式升级。

## 提示词与文学质量边界

核对[批准的提示词](../design/2026-11-11-source-story-routes-prompts.md)共同正文全部 3,180 字符原样包含于运行时 `COMMON`，附加范围说明区分题材尺度、局部阅读和创作权限。各操作共享此基线；Workshop 的承接提示冻结到新讨论，后续修改代码不会替换已冻结规则。

输出合同要求具体情绪场面、人物选择、关系变化、看点与完整结局，没有加入情绪分数、固定刺激次数或商业成功率。机械校验负责完整结构、来源身份、有效题材与修改范围；模型负责因果和戏剧设计。测试可以验证信息传递与恢复，不能证明模型理解没有遗漏，亦不能据此承诺真实小说的读者吸引力或商业成绩。

## 全部资料与小上下文

原文以完整快照、代码生成的证据 ID 和精确字符区间保存，简介、正文和补充材料保留各自来源。能容纳时采用一次完整输入；超限时按实际请求大小分批研读，完整保留观察、原文和原始响应，不将递归摘要作为唯一记忆。

路线生成和整合读取完整证据覆盖，跨段依赖可以按给定 ID 取回。候选发生变化后重新覆盖早期依据，不能用旧候选的检查记录为新候选背书。输出截断按完整路线或完整叙事字段分页重建，不拼接损坏 JSON，也不要求缩短情节换取通过。必要的作者要求、候选或不可拆的关联证据仍超过连接容量时，保存并明确报告，不能静默删掉内容。

交接将完整证据包和封面保存到讨论自有目录，启动新作品后再复制到其私有目录。删除资料库来源不会切断已交接讨论的依据。完整性校验覆盖来源包、候选、覆盖记录及已付费响应；文件路径不会冒充模型已读内容。

## 历史与恢复

新数据位于来源的 `story-design` 目录，旧 `study` 分析和付费结果不改写。路线和理解版本追加保存；修订保留路线稳定身份和父版本，追加保留已有路线。未完成的新反馈也可以随旧方向进入讨论，并明确尚未反映进旧路线。

交接先保存准备记录、完整来源与题材版本，再创建讨论和提交首轮。重复提交、响应丢失、准备后中断使用原操作身份恢复，避免重复创建。目录在中断后发生变化时，已接受交接仍使用其冻结题材。明确切换已有讨论的方向会保存旧地图与待答问题，重新协调模型设计。

确定返回的 HTTP 401/429/502 等错误保存结构化失败证据；瞬时失败允许一次自动恢复，修复连接后普通恢复可继续。真正未知的超时/中断保留原请求；仅当适配器实际提供结果查询时取回原响应，不凭猜测重复付费，也不要求填写技术对账表。生产通用 `LLMClient` 当前没有统一的远端结果查询能力，因此不能承诺所有未知请求都能自动找回。
