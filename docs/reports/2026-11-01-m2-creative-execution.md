# M2：采用设计到正文的执行接入

日期：2026-11-01。分支：`codex/novel-quality-optimization`。状态：本地实现；未部署、未推送、未使用真实小说调用模型。工程验证不代表文学收益已经证实。

## 结果与范围

新头脑风暴启动创作时，完整已采用骨架、已采用的方案及作者修改意见、所选题材资料的冻结版本，会进入同一个执行上下文。全书转换、分批章节规划、逐章规划、正文写作、编辑、连续性检查、风格整理和现有定点修订共用该记录。没有新增独立评议调用，也没有改变现有 H5 格式或新增文学分数门。

兼容发生在 RunSpec 的一个明确边界：没有 `creative_handoff` 的旧任务继续原流程，不自动补资料、迁移或换提示词。新 Workshop 启动使用现有 `evidence_v1`，因为增强流程需要真实发布的正文版本；程序调用若手动传入 handoff 却仍选旧质量模式，在启动前明确拒绝。普通旧 CLI 创建方式仍不隐式启用增强功能。

## 数据与权限关系

- `creative-handoff.v1`：完整骨架 SHA、会话/修订来源、当前明确采用项、类型完整快照和四种阶段投影。自然语言决定通过最终骨架保留，不要求补点方案卡按钮。
- `creative-execution.v1`：本次 run / project identity、handoff、固定规则和系统提示词，保存在 `outputs/runs/<run-id>/creative-design/lock.json`。Manifest 保存启动标记及锁 SHA；缺失、改动或错绑不能静默升级到新版本。
- 新版本启用、修改草稿、以后编辑 Agent 系统提示，都不热更新这个 run 的冻结资料与系统提示。
- 采用骨架优先于历史方案；修订方案的作者意见优先于原方案。未采用/拒绝的备选不进入交接。类型资料是创作参考，不能决定人物事实、角色知情、系统行为或发布分类。

## 每章实际读取什么

1. 已确认的全局设计，以及当前/相邻章节的完整规划。附 foundation SHA、包含及省略章节编号；明确标记这些是计划，不是已发生事实。不会截取大纲前若干字符冒充完整上下文。
2. 本章之前已提交的 canon 更新报告。与真实正文分开标记，报告的陈述仍要与正文核对；不会读取后续章节更新作为当前事实。
3. 最近两章已经发布的完整正文。读取 `canonical_revision_id` 指向的不可变 final，验证 blob；不用较新的未采用 final head、候选、草稿或计划摘要替代。
4. 第一章已发布正文的开头/中部/结尾整段样本，附版本、原文 SHA、字符区间、样本范围。用于叙述距离、注意对象、对话策略、节奏、意象的参考；不是模型提炼出的权威风格画像，也不代表通读第一章。首章尚未存在时明确缺失，按骨架风格建立声音。
5. 当前阶段适用的所选资料与采用意见。全书设计、分批章设计、写作、审核分别使用对应投影，格式纠正沿用原阶段。

现有新流程用上述上下文替换混合规划/推导状态的旧 context pack；原流程保持原 pack。章节 Architect 不重复粘贴全局 foundation。当前候选正文仍在原阶段提示中完整提供。

这解决的是来源和时间层次的可辨认性，不能单靠代码保证模型绝不提前泄露秘密。更早正文以提交记录提供，并未宣称每次请求都通读全部已写章节。

## 写作与编辑规则

新流程取消“每场景至少三种感官”及“每章主要转折必须由主角发动”的机械要求。编辑顺序明确为：场景因果和动机 → 关系/情绪发展 → 冗余、对话、视角和语言。保留安静场景、必要内心活动和反派推动的变化，仍需有可理解的因果和代价。规则采用新增执行策略，未直接改动旧 Agent prompt 文件。

## 请求、恢复和交付

- 每个实际请求保存完整上下文、系统/用户提示 SHA、字节数、响应状态及完整原始回复。`adapter_started` 仅证明本地开始调用；`response_received` 仅证明收到回复，不等于质量验收。
- 回包前后检查锁、骨架和章设计/前章依据。模型处理中来源被修改时，保留回复供排查，但不把它当作新来源下的有效产物。
- 模型上下文采用 2 MiB 的工程字节上限；超出停止并说明，不截断。这不是模型 token 容量承诺。不会因接入 M2 自动增加重试、评议或修订次数；原流水线的显式恢复/网络重试策略保留。
- 规划缓存身份包含创作锁；请求缓存绑定实际发送的上下文。章节检查点只绑定前章来源，不把本章/未来章的状态变化当成输入漂移。
- 私有交接、锁、请求和回复均不属于交付文件。H5 验收额外拒绝 `creative_handoff` / 锁元数据以及对应私有 schema，即使被伪装成公开 JSON 也不放行。

## 验证

新增专项使用假模型，覆盖冻结版本更新、完整前章和未采用版本隔离、未来内容排除、整段风格样本区间、请求/响应哈希、来源改变、失败回执、预算、旧记录默认关闭、API 启动交接、真实 Orchestrator 的两条写作入口及编辑/风格请求、证据模式暂停恢复和章节发布。

同时扩展现有分阶段全书端到端测试：使用真实 Orchestrator、基础规划/结局门与假模型，分别验证原流程和增强流程；H5 坏包测试验证私有元数据不可发布。

最终后端全量：**4123 passed、1 skipped**，271.26 秒。跳过项需要外部 `H5_ZIPIMPORT_SOURCE`，本轮没有再次执行外部 H5 Go 校验器；H5 本地坏包/来源合同回归通过。此前受限沙盒中有 24 项本地端口/进程权限相关失败，对应文件获得所需权限后 128 项通过，最终全量也通过。另修正一条旧测试的过期预期：作者生成超时应沿用有界执行的停止语义，不自动重试；生产重试策略未修改。

全量后，针对启动前校验的小幅收尾调整再执行创作执行与 Workshop API 测试，**45 项通过**（9.66 秒，包含新增的启动拒绝用例）；Python 编译与 `git diff --check` 通过。未改前端文件，因此未重复前端构建或 UI 验收。日志保存在本机 `/private/tmp/novelos-m2-final-regression.log` 和 `/private/tmp/novelos-m2-host-regression.log`。
