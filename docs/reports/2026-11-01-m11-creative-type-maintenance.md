# M1.1：可维护作品类型与头脑风暴接入

2026-11-01，分支 `codex/novel-quality-optimization`。本地开发和隔离验收完成；未部署、未推送、未调用真实模型。本次交付 M1.1，不代表 M2–M5 或文学效果验证已完成。

## 用户现在可以维护什么

正式路由 `/creative-types`，侧栏入口「作品类型」。沿用已锁定的浅蓝紫、白色面板、圆角和全宽布局。五个标签页分别编辑核心体验、故事机制、人物与文风、检查与融合，以及模型预览与版本。支持新增、复制、编辑、保存草稿、启用、停用、历史版本恢复为草稿；所有模型预览都是确定性本地编译，不付费调用模型。

内置资料位于 `resources/creative-types/v1.json`，共 55 份：

- 25 份专题参考，包括狼人、悬疑、复仇、家庭情感及扩充的女频主题。
- 30 份保留旧类型选项的通用起点，明确标记为「通用起点」，可由用户继续完善。
- 女频内容包括婚姻背叛、出轨与双面生活、离婚重建、破镜重圆、关系修复、契约婚姻、熟龄爱情、豪门家族、母女、婆媳、重组家庭、单亲育儿、生育自主、隐秘血缘、照护责任、女性觉醒、事业成长、经济独立、女性友谊、疗愈及狼人伴侣。类型不替作者决定离婚、复合、生育或结局。

这些是可编辑的初始资料，新增主题不需要新增 Python 分支。通用参考的存在不表示该题材的文学表现已经经过读者验证。原型中的未启用赛博修真演示没有作为生产内置内容导入。

## 真实链路

1. 类型库以稳定 ID 保存草稿；启用后生成不可变版本与完整来源 SHA-256。每次写入检查修订号，原子替换文件，线程与进程锁防止覆盖。
2. 头脑风暴基础设定改为读取启用列表，支持搜索、多选、显式主辅作用、自定义补充。精确旧别名可绑定资料；歧义需要显式选择，不猜测。旧静态选项继续服务历史入口和兼容标签，生产头脑风暴不会从它拼出新资料。
3. 创建讨论时冻结完整选择及内容。资料库之后编辑、启用或停用都不改变这份快照。
4. `brainstorm`、`story_design`、骨架内的 `chapter_plan` 分别投影适用条目，组合规则只在双方均被选择时加入。没有把整个库放进每次请求，也没有自动总结或截断。
5. 既有讨论可查看版本和具体字段差异，明确采用新版只保存后续上下文，保留骨架、作者决定和历史；不会自动推理。旧骨架需要显式更新后才能重新交付。
6. 修改基础设定时，待采用版本在保存时就冻结；确认从头推导前，模型与旧讨论不变。资料库再次变化也不会偷偷替换待采用版本。
7. 每次适配器调用保存实际阶段上下文、上下文/系统/用户请求哈希及字节数。`adapter_invocation_started` 仅证明准备调用适配器；`response_received` 表示适配器已返回，不是上游账单或文学质量证明。失败请求不因此自动重试。

实际维护数据存放在 `<projects-root 的父目录>/creative_types/<workspace-id>/library.json`。默认 Docker 项目根为 `/data/projects`，因此资料自动落在现有 `/data` 持久卷中。备份应包含整个 `creative_types` 目录。启用版本、操作回执和讨论快照均保留。目录已从 Git 和构建上下文排除；读取内置资料不创建用户存储。损坏文件显式报错，不用默认值覆盖。

## 合同边界

- Pydantic 校验字段、枚举、长度、条目 ID、引用、阶段、重复选择和发布映射。草稿允许内容不完整，启用必须具有名称、简介与有效说明。
- 每份完整规范资料上限 24 KiB，阶段类型上下文 96 KiB；超限报告实际字节及各类型占用，不截断、不启动模型。带类型快照的最终完整请求另有 2 MiB 工程防线；它不是模型 token 上限或适配器可接受大小的保证。
- 编译保留条目投影清单，来源 SHA 与实际请求 SHA 分开。预览统一标记 `preview_only: true`，不能当作真实发送记录。
- 类型说明作为参考数据，不是小说事实、系统权限或新的输出协议。系统规则要求优先遵循作者意图和既定事实，继续主动提出取舍方案，保持讨论/明确交付的边界。
- 创作 ID 与 H5 分类 ID 分离，维护页只允许当前 H5 字典中的映射候选。候选不自动成为发布分类，原 M0 的 V4/EPUB/PNG-JPEG/分类/哈希/大小校验门继续执行。
- 复用现有本地单用户和工作区路径边界，没有增加生产登录鉴权，不应把隐藏按钮视作多用户权限控制。
