# 资料设计请求执行与恢复修复

范围：`codex/long-form-planning` 本地开发。未部署、未重启服务、未恢复生产任务或重发真实模型请求。对应[原始只读排查](2026-11-12-source-route-pending-unknown.md)。

## 问题与实现

原流程把本地超时、远端结果未知、工作线程退出混成同一种停止状态；临时 CLI 输出退出后删除，普通继续依赖实际并不存在的查询能力。本次将这些职责收进共同模块，资料库、新建头脑风暴及路线交接后的证据读取复用同一请求边界。

- `core/source_request_session.py`：统一回执校验、执行、恢复、失败证据和显式重执行。兼容原设计 `status/raw` 与证据链 `state/response` 格式，保留各自原有哈希规则。输入身份继续由完整 system/user/payload 绑定，不因切换模型或容量而截断。
- `core/llm_attempt.py`：每次实际执行有独立目录。正常完整回复在交回业务层前持久保存，回执绑定身份与内容校验；恢复只读这些证据，不另发模型请求。CLI 最后消息、标准输出/错误，以及 SDK 已收到的公开正文分别私有保存。部分输出、JSON 恰好可解析、进程被终止均不等于完整结果。
- `core/llm_client.py`：通过可选执行上下文接入共同保全与安全诊断，既有未接入调用保持原接口。OpenAI/Anthropic 返回需有明确正常结束标识才可提交完整回执；Gemini 两个适配器维持原终止校验并补充已接收正文保全。输入、模型参数与全文质量合同未削弱。
- 已确认的 `length/max_tokens` 继续进入原有完整来源与完整字段分页，保存部分回复但不将其晋级为候选；恢复时不重复购买同一过大的整体输出。SDK 晚到的正常完整回复只归回原尝试，不能覆盖新尝试或通知过期界面。
- `core/source_request_recovery.py`：分别记录本地超时/取消/输出不完整与远端结果。识别进程期限及 SDK 类型化超时，界面文案由固定模板生成，不透传异常中的密钥、URL、文件路径或推理内容。没有证据的旧记录如实显示未知，不虚构 900 秒诊断。
- API 将设计未完成与作业成功区分；不会再因为业务函数保存错误后正常返回就显示设计成功。GET 状态只读，不迁移、重写或自动重发旧请求。
- 共同 `SourceRoutes` 界面按真实恢复能力展示操作。已保存完整回复可直接继续；结果无法找回则提供“重新执行未完成步骤”并说明可能增加模型费用，无技术对账表单。资料库和新建头脑风暴共用此行为。

## 重试与历史边界

确认失败且可重试的 HTTP/连接故障维持现有一次自动重试边界；未确认结果不被改称失败。显式重执行绑定来源、运行、请求身份、当前回执 SHA 和稳定操作 ID；授权只消费一次。重复点击、丢失 HTTP 响应、后台正在执行或已推进后再次提交同一操作，都不会新增模型调用。

重执行前将旧回执原字节归档，原尝试仍保留未知状态和本地诊断。新尝试使用当前模型设置，原输入及作者要求保持原样。换模型本身既不伪造旧请求结果，也不绕过未确认记录。完整回复缺失/损坏、身份不符、篡改哈希等情况阻断重购；有严格验证的完整执行产物才接回。

旧分析、历史讨论、小说正文、大纲、检查点及运行中的其他任务均未改动。既有新旧设计回执原位兼容，无全库迁移。后续部署前需另按作者指令执行安全暂停/切换流程，本报告不构成部署授权。

## 仍然明确的限制

旧请求当时未保存的输出和诊断无法补造。此任务仍需部署本修复后，由作者选择重新执行未完成步骤才能产生新结果；本轮没有替作者执行。远端无查询接口时，不能保证原请求没有执行或没有计费。此次修复保证状态、证据与恢复动作一致，不承诺供应商请求永不失败，也不通过缩减原文或降低文学标准来换取成功。
