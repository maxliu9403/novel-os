## 已交付行为

- 「新建小说」直接进入「一起把故事想完整」，移除普通创建前置表单。
- 先选择 H5 分类，再按需组合创作方向。新 `h5_guided.v1` 协议在 API 层校验主类型必选、ID、轴、数量及互斥关系；未标记的历史客户端保留兼容行为，新流程不可降级绕过选择。
- 作者选择进入模型上下文，并由代码在骨架保存/书名/交付阶段重建分类块、派生身份、标签和 Genre 头部。原始模型回复保留，模型不能替换作者分类。既有 EPUB/publication package/ZIP 合同门继续执行。
- 类型维护分类映射前置，使用同一 H5 字典；正文输入 15px、标签 14px，常用三页加模型预览/版本。折叠复杂设置，不删除质量字段。
- 默认三套内置：狼人 v3、婚姻背叛 v2、女性觉醒 v2。完整资料见 `resources/creative-types/curated-v2.json`；旧资源不改、版本哈希不变，用户保存记录优先。生产已有一份自建草稿，因此实际列表四项、启用三项。
- 新讨论引导比较 2–3 条因果走线，至少改变三个实质设计维度，不用换名字冒充多样性，不强制统一结局；没有增加额外模型调用、文学分数门或全库扫描。

设计、可复用模板标准及示例见 [创建标准](../design/2026-11-01-guided-creation-standard.md)。

## 多样性和质量边界

本轮通过可维护机制、选择/代价/回报及讨论路线比较改善设计输入，尚不提供跨作品语义去重。用户可提供旧作作为参照；没有参照时不会声称与全库不同。后续应以真实样本验证题材机制能否影响主冲突和结局，并结合 M3 正文阅读评议与读者反馈调整模板。分类和交付格式由代码保证，文学吸引力不作未经验证的承诺。
