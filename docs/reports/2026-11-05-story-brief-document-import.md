# 故事构想文件导入

2026-11-05，已部署至 http://localhost:5174。用户在「一起把故事想完整」的「故事构想或已有框架」旁点击「导入文件」，预览提取结果后确认填入。已有文字默认追加，也可以明确选择替换；预览文字和确认后的构想均可编辑。

## 实现

- `StoryBriefInput`集中管理文件选择、提取等待、取消、错误、可编辑预览、追加/替换及成功提示。待确认时禁止进入下一步或保存基础设定；只读历史设定不能导入。取消、卸载或新请求使旧回复失效，同一文件失败后可以再次选择。
- `POST /api/document-import`是无持久化的本地提取接口，不创建讨论，不调用模型。文件仅暂存于私有临时目录，完成/失败后清理；只有作者确认后的文本进入原有`premise`链路。
- TXT/MD支持UTF-8、带BOM的UTF-16和GB18030。保留Markdown文字结构，只统一换行和移除首尾空白。
- DOCX读取正文、表格、脚注/尾注；接受后的修订文字进入预览，删除文字排除。图片、页眉页脚、批注不导入，界面明确提示。XML拒绝DTD/实体；不解压到外部路径、不执行宏或访问外链。
- DOC由本地antiword转换；PDF由本地Poppler提取文字层，读取全部页面。空白/未提取文字页提示具体页号，纯扫描版明确要求OCR；不伪造或自动猜测缺失内容。复杂版面由作者在预览中核对。
- 单文件10 MiB、提取20万字符、PDF最多500页；超限明确拒绝，不静默截断。DOCX解压总量限制32 MiB、2000项。每个解析使用独立进程，15秒CPU/25秒墙钟/512 MiB Linux内存/2 MiB输出文件限制；最多2个并发解析，超时结束整个进程组。解析器不继承模型凭据和应用设置。
- Docker加入poppler-utils、antiword，Python加入defusedxml。应用前端视觉保持现有浅蓝、圆角白色面板；没有第二套资料分析或模型任务流程。
