# 正文大纲请求超限修复：3dca3ffb8137

## 现场与根因

任务在 `planning.global_design` 本地输入检查失败：133,531 字节 > 128,000 字节。请求收据只有 start/failed，间隔约 1 毫秒，输出为零；不是 Gemini 思考超时，也不是上游返回了长度拒绝。当前连接是 `gemini_openai` 网关适配器，其限制包含 1,024 字节封装预留，不等同于 Gemini 官方模型的 token 窗口。

保存请求的用户部分 121,436 字节，系统部分 11,071 字节。完整骨架约44.7KB、Genre/Tags约41.8KB、原作分析约16.6KB。分类与篇幅合同在骨架尾部、结构化 brief、immutable_contracts 重复；7份资料还含字节完全相同的472字节公共段落。此前工作坊的骨架减重没有覆盖正文大纲执行链路。

## 实现

1. `core/planning_context.py` 为请求生成无损表示：只在值完全一致时，将 brief 重复字段和已识别六节骨架的末尾工程合同归并到 immutable_contracts。请求记录明确引用关系；故事正文逐字保留。未知布局、尾部扩展或不等合同不移除。
2. 结构化 Genre/Tag 中长且完全相同的段落只发送一个定义，并在每个原位置明确引用；差异内容、作用位置、身份和版本保持。自由 Markdown 不拆分、不摘要。只在体积确实下降时使用，冻结文件和活动资料库不改写。
3. 格式纠正继续提供原始故事依据、作者决定及完整已返回结果，省去用于首次创作的重复 Genre 写作指导，保存指导哈希和用途说明。仍只有既定的一次格式纠正，不变更故事或放宽结构检查。
4. Gemini 大纲核查在发送前计算完整请求大小。一次可容纳就沿用一次核查；超限则按容量二分成窗口，每组保留完整全局候选、完整章序路线及相邻章对象；原骨架按既有章节投影读取，所有章节均被覆盖，边界相邻章共同核查。不是新增正文阅读评议。
5. 全部分组预检完成后才调用模型；每组持久化并绑定完整候选与请求哈希，恢复不重跑已完成组。全部组完成且无问题才合并通过，任意阻断仍阻断。不可分的单章和依赖仍超限时明确停止，不截断。
