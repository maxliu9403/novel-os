# 通用书名设计与提示词维护

## 实现

命名仍发生在作者确认完整骨架之后，不启动额外故事分析。保留当前头脑风暴模型和推理设置；正常一次调用返回五个候选，只有输出合同无效时最多修正一次，共用原截止时间与取消机制。没有逐个标题的多轮评审，也没有自动采用书名。

默认创作提示见 `resources/system-prompts/title-design.md`。突出具体人物关系、关键选择、冲突、反差和情绪回报，避免抽象标题和同义词换皮。五个候选的切面按故事决定，没有固定句式配额，没有硬编码 Romance、前夫、霸总、特定受众年龄或结局。作者与本书的语言、市场、受众要求优先。

## 作者验收后修正：直白命名 v2（2026-11-08）

首轮真实候选仍以三四词隐喻表达，v1“简洁、不设固定词数”不足以引导直白叙事。v2要求书名自身呈现可识别的人物关系、具体行动和冲突反差，默认英文优先8–15词、中文10–15字；长度下限是软目标，已经清晰的短标题可以保留。不要为了凑长度加空话或为了点击编造剧情。成熟读者偏好作为表达指导，不硬编码年龄/Genre/婚姻题材。

程序对每个新候选校验最多15单位：汉字逐字、英文按词、混排相加；标点不计，英文撇号留在词内、连字符分词。超限进入现有最多一次格式修正及共享截止时间，不截断或添加额外语义审稿。手动最终书名保持原有自由输入规则，已保存候选不追溯作废。

验证：112项相关后端测试通过，含15/16边界、中英混排、全角、撇号、连字符和超长有限修正；隔离无网络镜像烟测通过。任务空闲后仅发布`api/workshop_titles.py`及默认提示文件；运行文件SHA与源码一致，5174页面和API健康接口200。活动工作区已通过修订校验保存v2，原v1完整保留；18,905份已有讨论、来源、作品和类型JSON未变。未启动真实模型，作者需重新推荐验收文学效果。回滚镜像`novel-os-backend:before-title-clarity-20261108`，提示词回滚独立于镜像，通过编辑器显式保存历史内容。私有证据`/private/tmp/novel-title-clarity-20261108/`。

`core/title_context.py` 只投影命名所需的完整段落：六节骨架的故事承诺、人物关系、全书走向、伏笔/结局边界、第一章；旧十七节骨架的读者定位、梗概、限制、人物/关系、结局和第一章。结局与回收内容标为私有防剧透边界。保留所有作者命名要求及局部打磨的起始标题，仅去除连续重复要求；前轮候选只保留书名供比较。

不传完整逐章细纲、原始构想、全部讨论、Genre/Tag 说明全文、旧推荐理由、错误日志、分类和导出合同。不重写保存的完整骨架，也不为缩短输入调用另一模型。大于 64,000 字节的命名资料会在调用前明确拒绝；未知且过大的骨架结构不会被盲目截断。

## 编辑入口与版本

作品类型（Genre 与 Tags）页面右上角 → **书名设计提示词**。

- 阅读预览、编写 Markdown、版本记录；自由 Markdown，无须 Genre 关联或 YAML 元数据。
- 未修改不显示保存按钮；保存成功使用系统弹窗反馈。
- 载入历史/内置版本只改变编辑草稿，保存后追加新版本，不覆盖旧版本。
- 工作区独立保存，修订号防并发覆盖、操作标识保证丢失响应后重试幂等、原子替换避免半写文件。
- 首次真正用于命名时冻结内置版本；以后升级应用不会静默替换工作区已使用版本。
- 提交命名时冻结故事资料及提示词版本/正文/SHA；编辑不影响排队或执行中的请求，也不自动产生模型费用。

数据路径：`<data>/system_prompts/<workspace>/title-design.json`。
接口：`GET /api/system-prompts/title-design`、`PUT` 同路径（`markdown`、`revision`、`operation_id`）。提示词限制 12,000 UTF-8 字节，避免重新变成过重的说明书。

## 代码约束

模型输出固定五项 `title / angle / reason / source_ids`。代码检查非空单行书名、长度、规范化重复、短说明和来源 ID，不让可编辑提示词改变结果形状。来源 ID 的存在验证不是语义真实性证明；事实与防剧透仍需模型遵守来源，以及作者最终确认。

结果带输入字节、原骨架字节、提示词版本/SHA 和尝试次数，存于命名请求的 `metrics`。旧建议、作者要求、历史骨架在失败时保留。原有确认流程继续验证最终书名，并同步骨架顶部、封面交接与启动命令；不覆盖系列总名、章节名或正文。网页其他设计阶段不再注入命名专用参考。
