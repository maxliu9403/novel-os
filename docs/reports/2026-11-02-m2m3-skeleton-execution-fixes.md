## 1. 结局阻塞的根因与修复

样书 `A Night of Her Own`，讨论 `b3f80487de8a`，正文运行 `f249a13144d5`：12 章 final 已提交，但结局检查比较了两个不同概念：

- 正文状态：主冲突 `resolved`。
- 旧结局合同：`required_status=resolved_with_bounded_autonomy`。

后者是带有本书语义的结果说明，不是状态解析器接受的生命周期值。以它直接比较 `resolved`，会把已经完成的结局判为未解决。

实现：

1. `core/plot_thread_contract.py` 统一状态词表；新生成的经典 / 分阶段规划合同在写章节前校验。具体选择和后果仍保存在原有语义字段，不能混入枚举。
2. `core/ending_quality.py` 对旧合同明确报告 `main_conflict_status_invalid`，区分协议错误与故事未完。
3. `core/ending_evidence.py` 扩展既有追加式证据记录，支持 `main_conflict` 复核。必须绑定原合同、项目身份、已经 resolved 的 canonical 状态、已批准 final 的原文位置 / SHA / revision / promotion receipt，且包含结局窗口证据。不能改写原合同、把 active 强改成 resolved，或仅凭 `resolved_` 前缀放行。

复核仍是编辑判断。代码验证的是身份、来源和状态边界，不能仅凭引用存在便证明“有限自主”等语义已兑现。

样书验证在独立项目副本中完成：初始唯一 critical 为上述状态合同错误；引用第 11–12 章已批准正文、记录对有限自主及其资源代价的复核后，结局检查通过。原项目 859 个文件的哈希保持不变；副本的 canon、原骨架、foundation、原结局合同也未改写。

实际样书仍保持 `paused / ending.review`。本轮未提交该证据记录到真实项目，也未触发编译、导出或模型调用。新增记录须使用新版代码读取；未来部署后应先重新核对来源，再通过既有证据存储和正常恢复流程执行。不能通过删除旧合同或批量修改状态来“恢复”。

## 3. M2：把改进真正接入各阶段

`reader-investment.v2` 增强全题材通用方法，并沿既有冻结快照进入讨论、骨架、规划、写作和编辑：

- 已展示过的规则只在限制变化、争议或新增代价时再展开，减少程序说明反复出现。
- 重大决定让作出决定的人呈现具体欲望、顾虑或依恋；程序正确不等于人物动机清楚。
- 区分最初造成伤害 / 损失的事件与后来的应对决定，防止回顾时改变因果。
- 能力变化与重要离场提供最低必要交代，不把所有小说变成手续清单。
- 依据本书题材兑现自主、认可、发现、信任、公平、喜剧反转、能力或苦乐交织的释放，保留安静余波；不强制每章打脸、复仇、胜利或复合。

代码检查发现一个真实接线问题：`outline_planner` 的创作方法一直使用全书设计阶段。新版执行锁现分别冻结并选用 `story_design / chapter_plan / review` 的 system，准备回执、实际调用和字节统计采用同一份提示。测试验证模型适配器实际收到对应阶段内容，而不只是检查提示词常量存在。

未新增模型调用、并行大纲、文学分数门或无限重试。旧执行锁不重建、不热升级；旧规划的指令哈希保持一致。新方法不会自动改善已经写好的样书段落。

## 4. M3：区分错误、缺口和编辑意见

既有只读评议增加兼容字段 `finding_type`，界面沿用原视觉显示：矛盾、衔接不足、重复、人物动机、回报兑现、表达建议。旧报告缺少字段时仍可读取。

阅读阶段要求保留“谁作何选择、何时导致什么代价”；摘要不能把后来决定改成早先伤害的原因。综合阶段区分明确矛盾与缺少解释，避免把未描述的医疗 / 行程 / 法律流程直接判为事实错误。

代码对“矛盾 / 重复”要求至少两处不同的已核实原文；跨章判断仍要求不同章节。两份转述或同一证据重复引用不足以通过。原文匹配只能验证出处，结论是否成立仍需要内容判断。

M3 仍由用户显式启动、只读且有预算，未新增自动全书调用。私有作者合同后置检查仍标注 `not_performed`，没有真人反馈。报告驱动定点改稿属于后续 M4，**本轮未实现**。评议实现指纹变化后，旧的在途评议不可混用新实现续跑；已有报告仍可查看，需要按现有显式机制启动新版评议。
