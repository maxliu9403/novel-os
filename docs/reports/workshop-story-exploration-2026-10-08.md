# 头脑风暴 Skill：主动剧情设计验证

日期：2026-10-08

## 本次调整

Skill 先区分作者硬限制、已确认决定和可拓展草纲，主动提出具体剧情，再按反馈推进
全书因果走线。每轮不强制提问，不要求先填完细节表，也不强制重新生成整份骨架。
人物心理聚焦欲望、恐惧、行为风格、关键选择与代价；对白、措辞及不影响因果的细节
交给正文阶段。用户要求收敛时停止新增无关分支。

Web 装载新增的 `story-exploration.md` 和 `creation-path.md`，将创作规则放在交付参考前。
保留现有 JSON 传输、完整 17 节骨架、严格结构校验、全格式命令、暂停与上下文保存。
探索稿放在 Markdown 回复中；`prompt_md: null` 保留上一完整稿，未定稿时不允许启动。

## 验证方式与边界

- 从真实 Web `_skill_bundle` / `_complete` 路径捕获系统提示和三个虚构作者输入。
- 三个独立模型会话各完成两轮，按实际 Web JSON 协议输出；没有提供预期答案。
- 人工检查剧情差异、选择与后果、新信息、硬限制、细节层次及收敛行为；六份输出均由
  `_parse_response` 接受，均未将探索稿误作完整交付稿。
- 这是六轮故事策划模拟，不是三本完整小说的正文评测，也未通过用户配置的外部模型
  路由调用或启动真实作品。不同模型的创作表现仍需实际使用观察。

## 三类输入与观察

| 场景 | 作者输入与第二轮 | 观察到的行为 | 结论 |
|---|---|---|---|
| 只有一句构想 | 替家人经营旅馆三十年的女人发现家人准备在她生日卖店；随后选择推荐路线，要求家人不集体悔悟、新店不能立即成功 | 首轮提出争取旧店经营权、追查家族旧债、交接离开后三种不同走线，推荐第三条；第二轮新增客人不跟随、免费服务造成亏损、擅自接单伤害合伙、返聘诱惑和有限交接，推进自主与责任之间的冲突 | 有主动发散；选择后继续发展，无须作者逐项安排剧情 |
| 已有完整粗纲 | 24章现实职场成长：林宁的建筑设计被周屿冒名参奖，初稿靠偶然录音和曝光解决；随后采用主推路线，要求只预览全书走线、人物变化和伏笔，暂不导出 | 用“拿回过去署名但仍无未来决策权”形成中段；补偿诱惑→争取实权失败→离开失去收入→接案受挫→拒绝再次隐身→有限付费委托。第二轮收敛为六个阶段及伏笔回收，没有新增全书分支、追问对白或生成17节交付稿 | 保留身份、现实题材、女主不犯罪、不靠新恋人解救及职业自主结局；能够收敛 |
| 中段重复 | 40章奇幻：许遥修记忆钟必失去自己的记忆，中段反复躲追兵找新钟；第二轮只说“继续” | 首轮改为救回有罪证人→失主与姐弟发生分歧→对手扣人夺证→主动入宫。第二轮新增主谋以真实归钟和补偿获得信任、盟友因利益分裂、假签收被揭穿、对手因此转移钟藏，最后由前期有限合作支撑高潮 | “继续”得到新的因果发展；没有免费恢复记忆、增加抹掉代价的新能力或重新询问作者想写什么 |

三个案例的首轮问题数分别为 1、0、0；第二轮均为 0。问题数量仅记录观察，不是新的硬配额。
探索回复约 2,000–2,800 字符，主要用于事件、人物选择与全书后果，未展开章节正文。
