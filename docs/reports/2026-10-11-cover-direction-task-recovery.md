# 封面美术方向：切页恢复修复

日期：2026-10-11。范围：作品与头脑风暴封面工作室的「创建美术方向」。

## 问题与原因

原接口在 HTTP 请求内同步执行规划，只保存最终方向。页面用组件内的 `busy` 表示「规划中」，离开后状态随组件销毁；返回时只读取已完成方向，无法发现仍在执行的规划，也无法接收离开期间的失败结果。

修复前，真实 `CoverStudio` 卸载/重挂载测试稳定失败：规划请求未完成，「创建美术方向」已经重新可点。正式前端的隔离浏览器复现也得到同样结果；创建请求由本地路由拦截，没有调用真实模型。

## 修复内容

- 新增项目与讨论各自的 `POST /covers/direction-tasks`、`GET /covers/direction-tasks/latest` 和按任务 ID 查询接口。POST 返回 202，由现有 `JobRunner` 在后台执行。
- `outputs/covers/direction_tasks/` 保存任务标识、来源分析、候选数量、来源策略、时间、状态、方向 ID 和错误。讨论使用自己的封面存储目录；记录不复制骨架正文。
- 页面挂载时读取任务，运行中每 1.5 秒同步。完成后重新读取方向和费用；失败或中断保留原因。读取失败时继续重查，状态未确认前禁止重复提交。
- 同一所属作品或讨论的活动任务合并，不因双击、第二个标签页或不同数量参数再次调用模型。已有同步接口保持兼容，封面 UI 的来源绑定与旧版事实确认入口均改用后台任务。
- 服务重启后没有执行器的活动记录显示「已中断」，需要用户主动重试；不会自动重放付费请求。已完成、已失败记录可以跨重启读取。
- 保留完整骨架、审核可用性与来源新鲜度校验，派发前与执行前检查，来源绑定方向生成后再次验证。保留封面费用归属与项目删除保护。

沿用项目目前的单进程 `JobRunner` 架构。关闭页面不会取消后台任务；停止后端进程仍会中断正在执行的任务。
