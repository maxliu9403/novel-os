用户在四张图片全部失败后点击生成，被拒绝为“本方向的整批出图额度已使用”。

不能直接称为 OpenAI 图片服务限流。宿主文本模型有完成记录，图片实际模型没有回执。
本次没有修改模型配置或声称解决该远端错误。

此次不需要重新分析骨架或重新规划方向。

## 新行为

用户显式点击生成，使用新的请求 ID 创建独立批次，继续复用有效的已批准配方。
失败、部分成功或成功后的新批次均保留旧图、历史失败和费用记录。
旧 `batch_reserved` 不清零，新的 `batch_reservations` 追加服务端任务 ID、批准哈希、数量和时间。
每个批次仅消费一次；新候选核验其批次记录。单张修复额度保持独立。

API 持久化请求 ID 与方向、批准哈希和数量的绑定。同一个请求在运行中、完成后、失败后
以及重启后都返回同一个任务。不同标签页在活动期间合并的请求也保留别名，避免延迟重放
再次收费。旧未携带请求 ID 的调用保留原一次性规则，不静默扩张旧调用的授权。

前端把未确认的请求 ID 按作品、方向、批准哈希和数量保存在 sessionStorage；网络响应
丢失后复用同一个请求，刷新只查询状态，不自动 POST。收到任务或其请求别名后清理待确认意图。
失败/中断且方向匹配时显示“重新生成 4 张封面”。保留当前系统视觉样式。
非 localhost HTTP 环境使用 `crypto.getRandomValues` 作为 UUID 的安全替代。

源变化、批准失效、单张批准用于整批、同一批次重复消费和不同活动任务仍被阻止。
