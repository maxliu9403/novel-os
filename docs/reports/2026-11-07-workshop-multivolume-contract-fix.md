# 分卷骨架响应校验修复

## 问题与处理

任务 `52482a7186d0` 在生成48章分卷骨架时，阶段响应校验抛出 KeyError，被界面误报为模型配置错误。此前线上未保存阶段原始回复，不能确认旧响应具体缺失哪一项；本次没有补写或伪造历史回复。

在 NarrativeFormat、VolumeSpan、LongFormSuitability 的反序列化边界统一验证字段结构。缺失字段和错误类型一起报告为受控 ValueError，经 DeliveryError 进入现有有限格式修正流程。字段路径包含数组索引，例如 `narrative_format.volumes[0].structural_role`；不回显模型字段值。不把 null、数字或对象转成故事文字，不补默认分卷剧情。既有卷连续性、章节覆盖、模式、系列身份与哈希检查继续执行。

阶段提示明确要求 `narrative_format` 位于阶段 JSON 内，消除与最终 Markdown 标记块的混淆。修正只针对结构字段，保留有效故事、作者决定、章数与已批准卷边界；沿用整轮最多两次格式修正及原超时预算。

新增私有 `stage-responses/<revision>-<attempt>.json`：在解析前保存完整最终答案及输入/输出哈希，再记录验证状态、具体合同错误或内部异常帧位置。文件权限0600，目录0700；原文不会进入公共进度/API或后续故事上下文。写入受会话版本和 job 身份保护。单条上限4MiB；存储失败直接停止，不默默截断或追加调用。仅已校验的业务检查点可复用。

内部 KeyError/TypeError/AttributeError 不再归因到模型配置。遥测区分内部处理与存储故障；原始响应与诊断保存在独立位置，不记录连接密钥、请求头或私有推理流。
