# 全局大纲来源定位与分卷高潮校验修复

## 现场与根因

任务 `3dca3ffb8137` 的 Gemini 格式修正请求已经正常返回，不再是输入容量错误。

- 初次全局回复 43,008 字节，60 章、3 个来源引用，其中一处将两段原文拼成一个非精确引文。
- 修正回复 42,948 字节，已修好该引文；但两份回复都有 56 个 `source_anchor_ids: []`，不是字段丢失，也不是修正时删掉了引用。
- `_global` 按顺序抛出首个错误；初次先看到不精确引文，唯一一次修正后才暴露空列表。普通恢复会复用这两份回复，原样恢复不能补齐引用。
- 继续跑完整校验又发现潜在阻塞：第二卷范围 21–45 章，已确认高潮在 32 章；旧格式检查强制高潮位于末尾 35%，会要求违背故事顺序去适配模板。

这是全局执行大纲的工程合同问题，不证明模型没收到请求，也不能靠重新生成整部故事解决。

## 实现

### 代码负责章节定位

`skeleton_projection` 将已存在的严格 Markdown 章节边界解析提为共享模块逻辑。六节新骨架及十七节骨架必须有完整、顺序唯一的章号；忽略代码围栏内伪标题，排除整书补充记录。未知布局、缺章、重复章号、空章节、未闭合围栏不会产生推测位置。

`planning_source_anchors` 提供统一的全局引用绑定与章节继承：

- 全局章节引用缺失/为空，且能准确找到同章原骨架时，添加带 `kind: chapter_locator` 的确定性定位记录。保留原文标题、章号及原文字符区间，ID 绑定原始骨架哈希。
- 定位记录只是阅读入口，不是语义证据或文学质量结论。它不重写故事，也不假称模型已经逐章引用或核查。
- 原有有效引文和非空引用保留。未知 ID、错误类型、重复 ID、定位 ID 冲突、被篡改的定位区间均拒绝，不用任意现存引用“凑通过”。
- 章节细纲若漏填引用，只继承本章已经验证的全局映射，避免后续阶段重复发生同一机械故障。
- 不改变规划身份/提示词哈希，不删除原回复、不重新生成全局设计、不增加自动修正次数。恢复时仍验证快照、缓存依赖与内容哈希。

### 文学节奏与格式正确性分开

`validate_volume_contracts` 保留整数、锁定卷范围、章数、身份、独立承诺、回报和跨卷衔接等要求；高潮只须属于该卷。原末尾 35% 规则迁移到 `long_form_quality` 的 `early_volume_climax` 警告，提醒检查余波与读者回报，不移动已确认事件。全书语义核查及最终基础校验仍运行。
