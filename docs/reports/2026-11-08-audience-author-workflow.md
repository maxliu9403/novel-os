# 频道、标签组合与作者修订优先级实施记录

2026-11-08。实现依据：[确认方案](../design/2026-11-08-audience-genre-tag-design.md)与[原优先级审查](2026-11-08-author-revision-priority-audit.md)。本文件记录工程行为与验证边界，不能作为真实小说文学质量已经通过的证明。

## 实现

- 新建讨论统一 `genre_tags.v2`：作者明确选择男频／女频、一个 Genre 与一至两个 Tags。前后端共同检查频道、数量、启用版本、原文散列；Genre 与 Tags 不再有选择外键。频道不决定人物性别、性向或视角。
- 资料新增独立 `audience-guidance.v1` 模块；原文件完整字节和 SHA 保留。界面维护频道与指导，保存新版本。`selection-snapshot.v2`／`knowledge-compiler.v5` 只编译原说明和选中频道指导；不发送另一频道的新增指导。
- 首轮在原有模型调用中要求给出整体故事选项，解释所选 Tags 的具体作用、人物选择、代价与回报；沿用方案单选与开放补充。代码绑定标签身份与名称；缺少组合说明时标记待补全，保留故事提案，不增加自动重试。
- 最新明确作者修正优先于冲突的旧决定，兼容要求继续保留。共同的 `author-requirements.v1` 保存逐字原话、来源、顺序和 SHA。正文通过 `creative-handoff.v4` 接收冻结要求；命名、封面方案、最终出图及精修共享优先级。模型额外建议与请求结果分开。显式报告的范围冲突保留现有成果，不进入格式重试。
- 精修默认保留构图现在让位于作者明确的构图修改；页面、API 统一支持 5,000 字符要求。封面重新规划从既有持久任务恢复连续偏好，区分未提供与显式清空；手工方向修改也进入后续出图及规划上下文。
- 封面方案从已验证知识快照冻结读者频道，四张图片和后续精修提示明确携带频道；该值表示读者定位，不替换角色性别、身份、关系或视角。方向编辑不能修改频道，旧方案没有记录时不推断。
- 频道由代码绑定分类，进入 EPUB 与交付包并重算相关身份和 SHA。Manifest V4、`novel-h5-import.v1`、`ready` 及大小、封面、章节限制不变。
- 作品骨架页按需显示及下载私有“创作依据”：冻结资料版本、历史采用方案、当时作者修改。无逐字正文证据时明确“正文体现待确认”；损坏的最新任务不能回退冒充旧任务。报告不进入 H5 ZIP。

## 恢复、历史与维护边界

旧讨论保留原快照及协议，不自动升级。改变频道或选中资料时，作者在基础设定明确确认，再按新规则建立待重启输入；运行中的请求仍用原快照。源文档中的组合示例不是自动加载额外标签的指令，也不自动增加公开标签。

冻结执行合同继续绑定作品、任务、骨架 SHA 与资料版本。作者要求的传输只共享完全相同的重复文本，保留原位置与顺序；不会用关键词猜测过期要求或截断故事来压缩输入。跨轮自然语言是否冲突、最终文本是否真正实现要求，仍需模型理解和实际样本验收。

新增的是共享解析器、要求快照与纯派生视图；没有另建男女频 Agent、独立全书阅读评议、竞争偏好存储或无限修正循环。

## 资料保护

源码 41 份 Genre／Tag 的原文件与 HEAD 逐字核对一致；只追加频道模块。女频指导 41 份，其中 12 份同时补充男频方法。运行库实际升级 39 份、跳过 3 条已删除记录，0 冲突；逐项核对升级前原文字节及全部历史版本未变，没有复活作者删除的资料。运行库与源码种子数量不同是作者删除状态造成的。当前活动库女频可用 1 Genre + 38 Tags，男频可用 1 Genre + 10 Tags。

升级使用 `scripts/upgrade_audience_guidance.py`，默认只输出计划，`--apply` 才逐项执行版本校验后的新增版本。用户正在编辑的草稿、原文不一致和版本冲突明确报告，不能覆盖。恢复迁移见[换机部署](../deployment/machine-transfer.md)。

核对也发现 Romance 原说明末尾带有不完整句和编辑性说明。本轮遵守“不改原文”的限制未清理；频道模块不是修复原始文稿的授权。后续由作者确认是否整理，不能声称原说明已完成全面内容校订。

## 验证与交付边界

工程验收使用替身和合成小说，无真实模型创作调用。覆盖频道筛选、显式升级、快照篡改、旧协议恢复、原文保护、作者连续修正、精修要求长度、命名上下文、私有依据、EPUB／JSON 一致性与 SHA 拒绝路径。

合成男频、女频及历史通用频道交付包均通过引擎生产校验器；未知频道、分类与 EPUB 不一致、SHA 损坏均拒绝。可重建脚本：

```bash
python scripts/verify_audience_delivery.py --output-dir /private/tmp/novel-audience-acceptance
```

样包也在无网络候选后端镜像中验证。外部 H5 未修改或联调；请按[频道交接手册](../h5-audience-channel-handoff.md)独立验收。局部工程通过不代表故事爽感、男女性读者喜好或模型逐条语义服从已完成实测。

## 合并前补充：封面状态查询只读性

随后执行完整后端回归发现，上述已发布的状态投影锁会在空作品目录创建 `.mutation.lock`，也可能让列表查询等待执行锁。当前源码已改为无文件锁读取原子回执：若任务状态在读取后结束，在判为中断之前重新读取该任务的持久结果；不为查询创建目录或文件。

任务提交使用进程内短期发布标记，只在仍在执行的提交尚未写入 `job_id` 时暂不展示预留记录。标记在 `finally` 中清理；提交异常、失败结果写盘异常及真实孤儿仍可显示中断，不靠隐藏所有空 `job_id` 记录来掩盖错误。模型执行不占此内存标记的保护锁。

并发测试覆盖正常与失败终态、提交发布窗口、提交异常、写回失败、旧进程及同进程孤儿，并校验查询前后文件字节和修改时间不变。此项是提交前新增修复，**尚未部署**；上文 18:33 的运行 SHA 一致性只描述当时发布，不代表服务已加载这项后续修改。本轮合并不重启服务。
