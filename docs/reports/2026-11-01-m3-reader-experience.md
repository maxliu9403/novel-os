# M3 独立阅读评议实施报告

日期：2026-11-01。分支：`codex/novel-quality-optimization`。状态：本地工程已实现，未部署、未推送；全部验收使用虚构正文与假模型，没有启动真实小说评议或改写。文学判断准确性和读者吸引力尚需真实样本校准。

## 用户可用流程

作品概览新增「阅读评议」，保留既有五个顶层标签和浅蓝紫、白色圆角视觉。用户选择完整正文或连续章节范围，补充目标读者、公开简介，先预览来源版本、缺章、段数、模型和预算，再明确开始。历史评议保留独立入口；章节列表只为已有完成报告覆盖的章节显示入口，一次读取摘要索引，不逐行请求正文。

后台串行阅读所有选中原文，综合后显示值得保留的优点、最多五个优先问题、八个可折叠维度与不确定性。没有总评分。引用打开评议时的完整章节快照，可定位高亮；正文来源变化后保留旧报告并提示历史版本。

切页或刷新不丢失任务。支持暂停、显式恢复；暂停等待当前本地 SDK 线程退出后才释放任务占用。重启后丢失进程的任务显示中断，GET 不发起、恢复或迁移任何模型任务。预算用尽后保留结果，不自动扩容或重新出图、改写、重跑正文。

## 模块与合同

- `core/manuscript_reader.py` 从 API 抽出原有只读正文选择器，阅读器和评议共用同一权威顺序。存在但为空的 final 仍是权威，不能复活旧草稿。旧格式不迁移，不创建 artifact/项目身份。
- `core/prose_sanitize.py` 复用既有评论/状态块正则，线性生成完整 raw/body 区间映射；不会对重复文本进行模糊匹配。来源保存原始 SHA、清理正文 SHA、清理器版本、稿件版本、来源标识和 Unicode codepoint `[start,end)`。
- `core/reader_experience/{models,sources,prompts,store,runtime}.py` 是独立评议模块。`reader-experience.v1` 私有记录位于 `outputs/quality/reader_reviews/`；同项目短事务锁位于既有 `outputs/state/.reader-reviews.lock`。目录描述符与 `O_NOFOLLOW` 限制写入边界；原子替换、fsync、校验和及不可变快照防止部分响应冒充完成结果。
- 已有项目绑定 project instance；尚未建立身份的历史项目绑定目录实例，正常读取/导入随后初始化身份不使历史报告失效。已有身份发生 fork 则不能复用原报告。
- `api/reader_reviews.py`：POST `preview`、创建、`/{id}/pause`、`/{id}/resume`；GET 列表、详情、`/{id}/source?chapter=N`。通过 ProjectService 授权项目范围，JobRunner 登记工作线程以阻止并发删除。幂等标识持久保存，网络中断后重复 POST 不重新调用模型。
- `ReaderReviewPanel`、`ReaderReview` 与 `useChapterReviews` 提供概览、预览、报告/原文、章节入口。费用沿用正文分类，新 `reader_review` 子项只拆分、不重复加总。

## 阅读与核查边界

1. 章节/段落顺序分段，默认约 8,000 参考 tokens；超长段落完整切分，无随机抽样和正文截断。
2. 每段原文独立提交，首读不包含私有骨架、作者计划、未来事实或此前的批评/分数。前文只提供有长度上限的事实摘要，并明确标为有损上下文。
3. 每段保存事实、阅读观察和准确引用。引用必须匹配所在输入段；重复引文要求明确位置。不存在的引用不会被认证。
4. 所有分段的事实和观察进入全局综合；过长时按顺序分组归纳，必须保留完整覆盖 ID 和有效证据引用，不能无进展地循环压缩。原始观察和完整响应一直保留。
5. 公开标题、公开类型、用户提供的公开简介和目标读者在综合阶段才用于期待比较。没有读取作者私有合同来替正文解释。
6. 报告八维度是情节、人物、文字、世界、主题、情绪、阅读动力、期待。跨章结论至少有两章原文引用；纯局部证据不能证明全书没有某事件。代码验证引用，不保证模型语义判断正确。
7. 完成任务、正文覆盖完整性、整部小说是否齐全、引用核查和真人反馈分开记录。原文阅读完成不等于文学质量通过。

本轮没有启用额外模型回看请求（上限为零），依赖已保存的原文证据；无法支持的判断应标记依据不足。未执行作者私有合同评议、自动修订、正文晋升或真人盲评。它们不伪装成 M3 已验证效果。

## 预算、恢复与费用

默认单次 300 秒、总时限 30 分钟、串行调用；界面可明确调整总时限、调用次数、参考输入/输出限制和可选人民币预留预算。总时限包含等待/暂停，恢复不增加额度。预览显示最少调用数；若各次都接近超时会超出总时限，提前提示缩小范围或增加授权预算。

每次调用前保存完整请求、摘要和额度预留；返回后先保存完整原始响应，再解析与核查。已保存响应可恢复解析；失败/未知请求仍占用次数与预留。全任务最多一次格式/引用纠正、最多两次综合调用；摘要归纳也消耗同一调用上限。没有自动重试传输失败。

模型路由、连接标识、语言、公开期待、价格/汇率、实现与 tokenizer 版本冻结。恢复不能换用当前新价格、模型或资料。凭证仍从现有配置解析，不写入评议快照。新 SDK 实例传入 cancellation event，因此 SDK 自动重试关闭。LLMClient 新增可选本地线程 drain 查询，旧调用者的取消行为保持。

新增 `tiktoken`，使用 `cl100k_base` 实际 BPE 分词进行参考预算，不能把它声称为所有服务商的原生计费 tokenizer。未用 UTF-8 字节数冒充 token。Docker 构建预缓存公开分词表；本地首次使用需已安装依赖及缓存，缺失时不能降级为猜测计费。

人民币为冻结单价/汇率下的参考估算，不是实际账单上限。未知用量不释放已预留金额；已观测费用超出预留时会计入后续预算判断。没有完整单价时拒绝设置人民币预算，可明确只设置次数/时限。Codex CLI 内部不可辨认的上游重试、无法严格约束的单次输出和远端计费仍是限制；页面明确披露，不能声称提供供应商层的硬扣费上限。
