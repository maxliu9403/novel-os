# Workshop 无重大分歧后的推进修复

日期：2026-11-12。分支：`codex/long-form-planning`。本轮开发与离线验证，不部署、不重启、不重发生产请求。

## 真实故障

讨论 `847538cc7dca53ceaa833f0022b14ca0` 已成功保存第 10 版。原回复没有重大问题，故事地图通过校验，模型建议生成骨架；但页面没有无输入推进动作，骨架按钮又受到未确认篇幅的门禁限制。

三个独立问题叠加：

1. 前后端均只允许输入文字或提交待选方案；没有待选问题时，用户必须编造新输入才能继续。
2. 篇幅校验只查会话/设定，未查本轮确实发送的来源资料及选中路线。真实回复中 6 处合法引用因此被拒绝，候选与具体原因未进入下轮修订上下文。
3. 旧推荐规则仍要求章数、每章字数等基础字段完整，与先设计故事、再确认篇幅的流程冲突，将模型的生成建议降为继续完善。

“没有重大分歧”与“作者已确认篇幅”仍是不同事实；修复没有取消作者确认或文学质量检查。

## 实现

- `workshop_next_step` 只读推导讨论、决定问题、规划篇幅、选择篇幅、生成、等待和恢复等步骤。所有返回会话的 API 使用同一投影，不将界面状态写入历史数据。
- 新增有明确范围的 `advance=develop_story|plan_capacity` 操作，要求幂等 ID；无文字也可提交，不能与采用方案或交付混合。暂停/错误状态保留原恢复入口，不能以空操作替换现有可恢复任务。
- 前端显示实际下一步和骨架禁用原因。已有有效篇幅先进入选择；无方案时可直接请求规划。补充内容继续完整提交，不自动采用推荐方案。
- 来源收据只由成功的宿主请求创建，绑定讨论修订、来源上下文和完整证据包。已有小上下文证据协调流程完成覆盖后才能扩展引用范围；拒绝跨版本、错源、篡改与模型伪造的收据。
- 普通规划及重新分章均保留来源收据。旧容量合同的 `source()` 指纹结构不变，不使已有确认失效。
- 无效篇幅完整保留为候选，记录安全的结构化原因，并在下一轮修订请求中传递；不额外自动调用模型。来源引用只证明出处，不代表作者采用模型设想。
- `author_text` 统一区分作者原话与系统推进指令。新动作中的 `author_note` 才可作为作者证据，控制指令不能令故事节点变成已确认；传统消息保留既有解释。操作回执使用简短文案，完整消息仍保留在历史中。
- 故事优先模式不再受旧可选字段阻塞；地图缺项、重大待选、因果缺口、问题与冲突仍阻止系统推荐生成。

## 验证

先建立失败回归，再修复。覆盖无问题空推进、幂等、重大选择保护、暂停恢复、原子篇幅采用、来源伪造、候选保留、作者证据、真实 worker 的来源规划与重新分章。

真实任务仅在内存副本重放保存的模型回复：原来的 6 处错误引用全部通过验证；22 个场景、22 章、86,500 字的原始篇幅方案原样保留，状态转为可选方案。对话和创作决定保持。校验前后 106 份来源任务文件 SHA 完全一致，未调用真实模型、未写回原任务。离线通过证明此次范围错误已修复，不是文学质量的自动认证。

测试与离线验收记录位于 `output/workshop-next-step-20261112/`。前端全量 69 文件 / 689 项通过；审查增量后的受影响 3 文件 / 91 项通过，构建、类型和修改文件 Lint 通过。后端 Workshop、容量、作者证据、来源交接等 47 个模块最终 672 项全部通过（137 秒），见 `backend-final.xml` / `backend-final.log`。独立最终复核未发现本轮范围内的残余阻塞项。

## 运行边界

现有服务仍使用前次发布镜像，本轮未上线。旧分析、讨论、骨架、检查点和正文未迁移或改写。现有任务在部署后可使用新的显式推进入口；离线恢复出的方案没有擅自写回生产，也没有替作者采用或生成骨架。
