# Genre / Tag 自由 Markdown 导入与编辑

## 原因与设计

用户的《黑暗浪漫.md》是合法 Markdown。旧 `novel-knowledge.v2` 把正文组织方式作为程序合同：拒绝第一个 H2 之前的正文，启用必须匹配六个固定标题，编译又只选取已知标题。只取消导入报错会导致自定义说明未进入模型。

本次将作者编辑入口与冻结协议分开：

- 新建资料只填写名称、Genre/Tag 和 Tag 所属 Genre；程序生成稳定 ID 和文件头。作者编辑器只显示正文。
- `POST /api/creative-types/prepare` 是无写入、无模型调用的导入准备接口。识别已有元数据；没有身份的普通 Markdown 请求界面补充，或明确选择替换已有资料。不会按文件名猜测覆盖对象。
- 准备新文件或编辑正文时使用 `novel-knowledge.v3`，标题、层级、前言、重复标题、表格、代码块均由作者决定。仅生成/升级元数据封装，不重写正文。
- 导入既有 ID 先进入编辑预览，作者点击保存并启用后才更换活动版本。新资料先保存为草稿。保留版本历史、并发修订校验和操作幂等性。
- 旧 v1/v2 与原始 Tag 方言继续按原编译规则读取，保持已有冻结快照的模型输入。新的自由文档使用 `knowledge-compiler.v4`；编辑旧文档后才形成新自由版本，不自动迁移活动库。

## 模型读取与限制

自由文档正文完整进入头脑风暴、故事设计、章节规划、写作、审稿、简介和封面七阶段；不重复发送分节解析副本，不因标题不同丢掉内容。混合选择中的旧文档仍按其原规则投影。

v4 的解释规则将说明应用到当前阶段，保留 Genre/Tag 组合、作者已确认事实和示例非固定节拍的原则。作者说明中的“系统定位”不获得系统权限，也不能替换引擎输出协议；方法说明和状态结算不混入读者正文。这些是创作指导，工程验证不能保证模型逐项执行或作品文学质量。

身份、Genre 关联、公开分类、哈希与大小检查仍有效。启用须有非空正文；单份文件上限24 KiB、组合上下文上限96 KiB，超限明确拒绝，绝不截断。公开 H5 元数据保持独立，私有正文不会被导出为分类定义。
