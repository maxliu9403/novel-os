日期：2026-11-06。分支：`codex/novel-quality-optimization`。适用于新建并冻结 `story-first.v1` 策略的讨论和正文任务。本轮没有部署、重启、修改现有小说或启动真实模型调用。

后续发布记录：同日设置/Gemini任务中已检查全部任务空闲，并将此工作流一并部署到5174。运行源码一致性及健康检查通过；未启动真实模型测试。详见 `2026-11-06-settings-gemini.md`。

## 已实现

### 创作起点与来源继承

新入口提供原创构想、原故事推演、改编重写。`core/creation_mode.py` 统一来源意图，讨论、骨架交付、正文冻结交接与参考封面使用同一语义。原故事推演继承已提供人物、关系、事件和规则，允许专业设计后续秘密、支线和场面；新提案与已读事实分别表达。已存独立参考创作不会被静默改成续作。

`source-study.v2` 增加最后已知事件、人物状态、知情边界、未决线索、世界规则和资料缺口，按原章节顺序汇总。旧完整分析仍可读取，但它没有新版本的续推状态字段；重新分析需要显式启动，不能声称历史结果已经补齐。中断的旧版本请求不能混入新协议缓存。

### 头脑风暴与骨架

讨论要求具体场面、人物行动、关系变化、阶段回报和由事件引出的钩子；章卡采用叙事视角／核心剧情／看点与情绪回报／章末钩子或余韵，可附伏笔与回收。不开固定情绪或复仇配方，也不把细节都交给作者选择。

新讨论地图支持绑定 `base_revision` 的变更节点，保留未变节点；旧版本变更不能覆盖新地图。模型提案不会自动变成作者确认。有完整建议且不存在未决大选择、重大假设时，可以建议生成骨架；真正交付仍需作者操作。

`core/story_design.py` 是骨架合同与编译入口：全局设计和完整章卡保存后，代码确定性生成六部分骨架。取消新流程的六次模型整合；不再让模型重复抄写分类、封面 JSON 和机器协议。作者篇幅方案仍绑定相同总词数、章数及每章分配。分卷／系列配置在保存全局阶段时校验，避免最后整合才发现缺失。

章节正文规划读取骨架已有场面，在一次全局转换和章节批次中补齐执行合同；通过全局一致性检查后，逐章由代码投影合同和场面，不再每章调用模型重新规划。六部分骨架已接通作品详情和完整骨架封面规划，不依赖旧封面交接 JSON。

### 正文与审稿

新主路径：已批准章节设计 → 写作 → 联合审稿 → 通过后原样定稿。有必要问题才进行有界修订和对实际修订版本的再次审稿。

联合审稿覆盖故事、连续性、文风、读者体验。`core/chapter_review.py` 校验四项完整性、正文 SHA-256、原文引用及具体修订要求。它验证审稿确实对应当前稿，不把格式正确解释为小说优秀。通过的正文不再经过一次无条件风格重写。

最终审稿提供本章实际成立的状态更新；canon 不再混入已被修订覆盖的初稿事件。已有不可变版本、来源绑定、状态提案、定稿凭据、结局检查和 H5 交付校验继续生效。暂停、超时、无效报告与“明确要求文学修订”分开，前者不会自动触发额外编辑请求。

## 调用数量与边界

| 范围 | 新流程正常路径 | 说明 |
| --- | --- | --- |
| 从讨论交付骨架 | 两次语义整理，零次模型组装 | 全局设计、完整章卡；代码生成骨架。 |
| 正文前准备 | 全局转换、章节批次、全局核查 | 仍有模型调用，不宣称整个规划阶段零调用。 |
| 普通通过章 | 写作、联合审稿两次应用调用 | 已用两章假模型集成用例验证控制流。 |
| 需要修订的章 | 每次增加修订、复核两次调用 | 受原任务修订预算限制。 |
| 发行文案、封面 | 原有独立流程 | 不包含在正文两次调用计数中。 |

这里没有真实 token、模型内部重试、计费或耗时的测量；问题章不保证比旧流程更便宜。没有更改用户设置的模型、推理档位或超时。没有恢复 M3 全书阅读评议。

当前讨论的可读章卡仍保存在讨论记录，交付时整理成唯一的全局设计与完整章卡检查点；尚未把每轮讨论直接维护为完整结构化章卡库。长篇按故事段逐批交付章卡仍需后续完善，不能把当前一次完整章卡请求宣传为无限篇幅能力。

## 代码整理

- 将来源语义集中到 `core/creation_mode.py`，移除各阶段相反的参考创作要求。
- 将公共分类绑定归入 `core/publication_taxonomy.py`，删除仅属于 API 层的 `api/workshop_classification.py`；核心编译器不反向依赖 API。
- 骨架序列化、联合审稿合同、来源策略各自拥有明确入口；复用现有任务和凭据存储，未增加第二套运行系统。
- 历史冻结任务显式走原协议；新任务按版本选择新流程。未用本书 ID、人物名、异常文本或失败后猜测字段来切换行为。

## 下一步质量验收

部署后先用同一构想、同一 Genre/Tags、同一模型与推理档位比较整体故事提案和开篇关键场面。检查具体场景、代价、情绪变化、早期回报和自然续读期待，再查看实际调用时间与用量。文学收益需要作者评判实际文本，不能用本轮工程测试或模型自评分代替。
