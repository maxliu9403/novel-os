## 1. 新作品的完整流程

1. 新建单本连续章节作品时，章数和平均章长是初始偏好，可留空。
2. 先通过已有共创轮次确定主要故事走向。模型在同一回复中给出按场景估计的容量建议，列明读者价值、来源原话、现场或概述、区间和理由。
3. 提供 1–3 个篇幅或分章方案。各方案保留已采用故事，不通过暗删支线满足原始数字。用户可展开分章分配，采用一个方案并直接请求生成骨架。
4. 代码检查来源引用、场景分配遗漏/重复、连续章号、范围、总量、正文语言与计量单位。作者确认后冻结方案；骨架组装及后续章节规划使用相同分章目标。
5. 既有最后交付检查同时返回可定位的骨架修订建议。界面并排显示原文和建议，默认选中建议；作者可以一次采用选中项，或保留原稿，无需提交理由。
6. 保存修订不调用模型：校验原文版本和位置、应用修改、重验完整结构、保存新版本和历史。命名及启动准备使用作者最终处理过的骨架。

容量建议不是新的逐场景问卷。作者仍只决定宏观走向和交付篇幅；模型负责专业细节。没有增加独立自动文学评分或反复评审调用。

## 2. 实现边界

| 模块 | 职责 |
| --- | --- |
| `core/story_capacity.py` | `story-capacity.v1` 的严格解析、算术/分配校验、确认合同与 SHA |
| `api/workshop_capacity.py` | 冻结策略、同轮建议、采用、过期处理与骨架绑定 |
| `core/skeleton_review.py` | `skeleton-review.v1` 的章节原文定位、局部修改、历史检查说明 |
| Workshop API / 组装器 | 在锁下保存与持久幂等；复用最后组装请求；原子发布完整版本 |
| `core/outline_planning.py` | 从采用骨架读取确认分配，绑定章节目标，沿用检查点恢复 |
| 两个新界面组件 | 篇幅方案、原文对照、采用/保留、过期/失败/已保存反馈 |

局部建议覆盖开篇投入、因果、阅读价值、人物关系、场景容量、结局回报六方面；最多 8 项高影响修改和 6 项非局部说明，不要求凑数。涉及人物事实、结局或全局重写的决定只能作为说明，不能伪装成局部补丁。代码限制修改区域，不允许修改组装器拥有的篇幅和协议数据。

保存修订后，第 17 节明确当前采用结果，并保留原检查为历史，不再把旧的“待修改”原样展示成当前完成结论。精确引用、结构校验不等于语义判断正确，作者仍需要查看修改意图；正文阅读效果没有在本轮验证。

## 3. 失败恢复与兼容性

- 双击或网络重发使用持久请求标识，不增加同一请求的模型调用；版本和来源变化拒绝旧建议。
- 修改故事或基础设定使容量建议过期；修改前完整快照先归档，再更新当前状态。历史方案保留。
- 已采用篇幅后生成失败，确认合同保留，显式重试可继续使用，不要求重新选择。
- 无效的辅助建议保留有用的讨论或完整骨架，明确提示本轮建议不可用，不把数据缺失当作质量通过，也不自动追加调用。
- 旧任务没有 `length_planning=story_first` 时保持旧协议、冻结策略和请求指纹，恢复不会隐式升级。
- 第一阶段支持短篇/长篇的单本连续章节。分卷、系列继续走原路径；自动重排已写作品的剩余篇幅尚未实施。
- 私有容量和复核记录不进入 H5 公共包；增加泄漏检查，现行 Manifest、分类、EPUB 和 ZIP 校验合同不变。
