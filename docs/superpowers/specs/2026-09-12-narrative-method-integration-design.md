## 1. 决策摘要

采用 **Novel OS 原生创作方法增强**，不是把两个引擎嵌套运行。

保留现有 Workshop → 合同 → 全书流水线 → 候选 → 质量检查 → Promotion → Final → EPUB/H5 ZIP。借鉴外部方法，重新适配英文、当前受众和已有合同，进入受控的阶段输入与评审。

第一批只做两件事：

1. **英文功能性表达评审**：识别没有叙事功能的身体反应、重复情绪解释、旁白替读者下结论、人物对白趋同；允许有功能的直写与静止。
2. **免费窗口兑现评审**：确认关键选择由适当人物作出，核心回报真实发生，下一步阅读期待来自具体后果，而非只延长羞辱或拖延揭示。

随后补长篇上下文覆盖、三方知识可见性、跨章声音索引与偏好作用域。

**产品决策不变：**作者决定语言、受众、篇幅、卷数及章节范围；引擎可以建议，但不静默替换。当前用户的英文、欧美女性受众与少复杂财务推演，在确认的范围内保留，不成为所有项目不可覆盖的默认设定。

## 2. 目标、非目标及成功标准

### 2.1 目标

- 人物因处境和立场而行动，不是每段加一次握拳、抿嘴或呼吸停顿。
- 免费期交付可感知的局部价值，形成诚实且有吸引力的付费桥。
- 长篇每卷有完整阶段作用，久远线索可召回，人物不提前知道秘密。
- 每条影响发布的判断都能定位到正确版本、合同与相应证据。
- 方法更新可追踪、可比较、可关闭；减少循环修复，不再靠堆提示词控制质量。
- 保持既有 H5 数据格式及行为合同；新作品后续更新保持书章身份、阅读进度与章节权益关联。

### 2.2 本轮不做

- 不整体安装 oh-story 的 setup、hooks、agents 或第二套 tracking。
- 不引入向量库或对标原文的运行时召回；不把创作变成参考小说改写。
- 不迁移对方的数字绘画封面规则；当前人物、摄影、故事冲突和回退链保持原样。
- 不重构 H5、阅读计费、分类字典、EPUB 格式或 ZIP 协议。
- 不为改造前作品实现迁移器、历史补审、旧 run 恢复或旧内部 schema 双读链路；现有资料保持原样。
- 不替换模型接入，不用方法改造掩盖 401、容量、网络或超时问题。
- 不在本功能中建设分布式调度器或跨书共享 canon；前者单独立项，后者需独立授权模型。
- 不宣称“AI 检测分数下降”就是文学质量或销量上升。

### 2.3 成功分两类衡量

**工程验收是硬条件：**无串书、无未审稿晋升、无过期证据复用、章节/卷/Introduction 映射无退化、审计文件不进入公开包。

**读感验收是试验条件：**固定输入 A/B 盲评，观察自然度、声音差异、因果清晰、局部满足、继续阅读意愿。模型自评分只是辅助，真人英文编辑与目标读者是最终判断来源。

## 3. 领域术语（拟议，批准后再纳入根目录词汇表）

| 术语 | 含义 | 不等同于 |
|---|---|---|
| Method／创作方法 | 可复用的观察或创作技法，如功能性细节、因果与兑现归属 | 故事内容、题材模板或新 agent |
| Method Pack／方法包 | 有适用条件、版本、来源与评审规则的资料集合 | 自动执行的插件 |
| Method Policy／方法策略 | 作者选择的启用范围、模式和修订权限 | 书籍 canon |
| Run Method Lock／运行方法快照 | 某次运行冻结的策略、方法内容和配置依赖 | 会随系统默认值变化的配置引用 |
| Guidance Packet／指导包 | 引擎装配后实际传给一个角色的少量方法及来源记录 | 所有 references 的全文 |
| Critique／评审建议 | 对特定候选版本的可审查判断 | 已获授权的 blocking finding |
| Reader Promise／读者承诺 | 故事已许诺的情绪或事件回报 | 所有伏笔都必须立即揭露 |
| Payoff Ownership／兑现归属 | 谁作出关键选择、承受后果、获得应有回报 | 主角必须独自完成每个动作 |
| Knowledge View／知识视图 | 在特定叙事位置，读者或人物有依据知道/相信的内容 | 作者完整设定 |
| Review Coverage／审阅覆盖 | 某类检查实际获得哪些正文区间、事实和依赖 | 模型已理解全文的证明 |

### 不变量

1. 正式事实只经现有 proposal → promotion 路径改变；派生索引随时可重建。
2. 文风偏好可覆盖默认表达方式，不覆盖已批准事实、POV、合同、字数范围或交付协议。
3. 正文中的错误信念与客观真相分别保存，误信不自动改写世界事实。
4. 引文存在证明“模型指的是这段”，不证明“模型判断正确”。
5. 方法选择只能影响已批准范围；新系统中已晋升的 Final 不因方法升级自动重写。

### 4.1 Module 与 Interface

`NarrativeMethods` 是一个有少量调用入口的 Module，不建立通用插件总线。

拟议 Interface：

```python
compile(request: GuidanceRequest, snapshot: RunMethodSnapshot) -> GuidancePacket
validate(request: CritiqueRequest, raw_response: str) -> ValidatedCritique
```

- `compile` 不调用模型、不写文件、不修改状态；输出指导文本与装配记录。
- `validate` 不修改正文、不推进章节；输出有效建议、无效证据、覆盖状态和策略结论。
- PipelineRunner 负责调用、预算、持久化与 checkpoint；ModelRouter 继续负责 provider、模型和推理强度。
- Workshop Adapter 将方法转为 Section A–E 的建议；Runtime Adapter 将方法转为阶段指导/评审。二者共享同一方法定义，分别面对交互设计和无交互执行，避免创建没有实际差异的抽象层。
- `off` 是确定性的空行为；不隐式发模型请求，不读取第三方资料。

Interface 必须公开：输入版本、适用范围、错误类型、预算、只读保证、输出是否完整。内部资料排序、原文定位和白名单规则集中实现，调用方不各自拼一套提示词。

### 5.2 MethodDefinition 的必需信息

`method_id`、版本、适用语言/体裁/章功能、目标角色、必需输入、允许输出、指导与评审文件 SHA、规则 ID、默认处理级别、覆盖要求、来源 commit/路径、适配说明、许可证声明。

- 只使用内置 allowlist 中的资料路径；不执行资料内 shell，不动态下载 main。
- 原始上游文件留作研究依据；运行时使用已审阅的本地适配文本。
- source hash 说明来源，adapted hash 说明实际使用了什么，两者分别记录。
- 以选定语言匹配，未知语言不静默用中文包代替；显式启用但不适用时在启动前报告。
- 方法包不内置“所有故事必须出轨”“所有女主必须五十岁”或固定反击场景。
- 对包做总预算，不只是各文件长度检查；用户事实优先于方法资料。

### 5.3 首批规则

| 规则 ID | 判断 | 默认处理 |
|---|---|---|
| `prose.nonfunctional_reaction` | 身体/语气反应只是重复已有情绪，没有新作用 | 建议 |
| `prose.emotion_restatement` | 对白、动作、旁白连续解释同一件事 | 建议 |
| `prose.unearned_commentary` | 叙述者代替读者得出未被场景支持的结论 | 建议 |
| `prose.voice_convergence` | 关键人物对白策略、关注点和措辞趋同 | 建议，需比较原文 |
| `prose.mechanical_scene_execution` | 把细纲逐点改写成流水清单，缺少因果衔接 | 建议 |
| `payoff.choice_causality` | 关键选择与局面变化是否有因果联系 | 扩充已有商业评审 |
| `payoff.ownership` | 选择、成本、回报是否落在已承诺的人物上 | 建议，角色身份需证据 |
| `free_window.earned_bridge` | 免费期已有局部价值，后续期待具体且有依据 | 扩充已有免费窗口评审 |

首批不把词频、句长或“AI 感总分”作为新硬门禁。允许自然的重复、沉默、直白情绪句和功能性身体动作；作者明确的声音选择不是错误。

### 5.4 英文词数与证据坐标分开

新方法第一版使用 `en_whitespace_words.v1`：从引擎编译后的正文块取文本，排除章标题、导读标签和导读内容；按 Unicode 空白分隔计词。连字符词、缩写仍遵循这一简单口径，不声称是语言学分词。

原因：当前多个路径已经使用 `split()`，另有启发式正则计数。此次统一新项目的生产验收口径，不处理旧书统计迁移。UI 展示的启发式指标可继续使用，但不冒充权威词数。用户给出 800–900 时锁住原范围，不自行改成 ±15%。超欠长先指出缺失事件/冗余，完整且自然的带外稿可交作者接受，不以凑字数新增事件。

证据仍定位不可变候选的完整 UTF-8 原文，不因计词的正文提取、引号整理、Unicode 归一化或 EPUB 渲染而改变坐标。

## 6. 配置、模式与运行快照

### 6.1 三种模式的精确定义

| 模式 | 指导进入生产 prompt | 新方法输出 | 修改正文 | 新方法阻断晋升 |
|---|---:|---|---:|---:|
| `off` | 否 | 无 | 否 | 否 |
| `advisory` | 否 | 对现有候选的旁路报告 | 否 | 否 |
| `enforced` | 是，按方法/角色筛选 | 报告＋受控处理 | 受 approval_policy 和预算控制 | 仅已批准 allowlist 规则 |

**advisory 不改变任何原有角色 prompt。**这样才能对原流程建立基线；报告展示或额外模型调用会增加耗时，但不改变原有 canon、Final、promotion receipt 或 H5 ZIP。报告丢失/调用失败显示“未评审”，不显示通过，也不阻断旧流程。

`enforced` 不表示把所有建议变成硬门禁。第一批风格项仍为 advisory；在既有已批准叙事合同下核验的事实、身份、POV 或必要回报继续走对应既有门禁。新增硬规则需通过独立误报验证后随 rubric 版本发布。

### 6.2 示例配置（拟议）

```json
{
  "schema": "novel-method-policy.v1",
  "mode": "advisory",
  "method_ids": ["en-functional-prose.v1", "en-agency-payoff.v1"],
  "scope": {
    "kind": "free_trial_window",
    "source": "approved_commercial_contract"
  },
  "repair_policy": "none",
  "guidance_max_chars": 2400,
  "max_methods_per_stage": 3,
  "max_method_repairs_per_chapter": 1,
  "max_post_style_replacements_per_chapter": 2,
  "review_chunk_target_chars": 8000,
  "review_chunk_overlap_chars": 600,
  "max_review_chunks": 8,
  "schema_repair_attempts": 1
}
```

数值是建议起点，试点前可调整；它们不是当前生产设置。`repair_policy` 支持 `none / manual / bounded_auto`；前两种模式强制为 none。`bounded_auto` 只在原 run 也允许 auto 时生效，仍受合计预算约束。

### 6.3 解析与确认

- 策略默认值 → 项目选择 → 本次运行显式选择；最终生效值在启动前显示并冻结。
- 只对新创建项目定义策略，首次发布建议默认 advisory，运营可关闭；正式开启需明确确认。改造前项目留在原目录，不自动进入新链路，也不自动创建兼容快照。
- 免费窗口从已批准合同读取，不写死第 4 章。没有该合同或免费截止章不明时，请作者先确认范围，不能猜一个用于真实生产。
- 方法若只适用于某类小说，未命中的方法列入 `not_applicable`，而不是自动替换题材。
- 全局设置改变只影响新运行；运行中的快照不变。

### 6.4 Run Method Lock

内容包括：模式、作用范围、完整有效策略、精确方法内容及 SHA、适配/rubric/编译器版本、已确认偏好快照、角色 provider/model/推理强度的无凭据记录、合同 revision、预算。

稳定配置用排序键的 UTF-8 JSON、禁 NaN、SHA-256；时间戳和展示字段不进入配置摘要。资料路径不是内容身份，既记录实际字节 SHA，也保存可恢复副本。

所有创建动作需在实际 run_id 下幂等执行。运行恢复优先读取 lock；缺失已要求的文件时报缺失，不能重新按当前全局设置拼一个“相似版本”。

## 7. 创作与质量流程

### 7.1 Workshop

- 在既有 Section A–E 中说明将应用的两三个方法和适用理由，不新增长问卷。
- 用户已确认语言、受众、篇幅时不重复提问。
- 输出的故事合同仍使用 canonical classification、narrative_format、commercial/ending/cover handoff；方法策略是运行选择，不把研究报告塞进故事正文。
- 吸收方法不等于批准任何新反转、人物或结局；超出已有设计的建议回到相应 Section 确认。

### 7.2 生产阶段如何使用

| 阶段 | enforced 路径增量 | 保护内容 |
|---|---|---|
| Architect | 章功能、选择—后果—回报检查；适当安排低压兑现 | 合同事实、卷目标、揭示时机 |
| Scribe | 1–3 条当前场景适用技法，不要求每段展示 | 英文、POV、人物声线、批准事件 |
| Editor | 删除/重织已有冗余，不为达到清单新增动作 | 因果、承诺、关键证据、字数 |
| Guardian | 事实与知识边界、具体正文覆盖 | 完整事实证据及来源 |
| Style | 声音与自然度，结合近期引用而非泛泛要求 | 作者风格与有功能的表达 |
| Commercial | 扩展因果/兑现归属说明，不重复新建 agency gate | 实际免费窗口和商业证据 |

角色提示采用版本化的明确渲染分支：off/advisory 的渲染结果与基线逐字节相同；enforced 使用已审阅的规则变体，替换冲突的固定配额，而不是在仍写着“必须三种感官”的提示末尾再追加相反要求。测试覆盖所有角色，避免修改一个共用文件就悄悄影响关闭模式。

### 7.3 精确候选检查与有限修订

现有流程在 style 后还可能发生商业修订。因此新方法针对**最新、不可变的候选 revision**工作，而不是对某个可变文件名给永久结论。

1. 原流程生成候选 C0，完成应有的既有检查。
2. advisory：报告绑定 C0；即使后续稿变化，报告也保留 C0 标记，不改写成最新稿报告。
3. enforced：在 promotion 前检查候选当前性、合同/方法绑定和必要覆盖，并生成评审结果。
4. 需要修订且获得权限时，将 C0 作为 parent 创建 C1；C0 与其报告保持原样。
5. C1 完成所有受修改影响的连续性、风格、商业、知识和方法复检。即使只是改一句，也不携带旧正文 offset 或旧 candidate hash。
6. 若 C1 更好且所有必需检查通过，使用 C1 和它的证据进入原 Promotion；否则保留 C1 供查看，不自动替换。
7. 只有 C0 仍满足**当前所有必需门禁**时才可继续采用 C0。若 C0 本身存在必须解决的破坏，C1 失败后暂停待审，不能以“回退”绕过门禁。

**防循环：**单章方法修订最多 1 次；style 之后的商业修订与方法修订共用最多 2 次候选替换预算，恢复后不清零。为方法修订做复检时，不再嵌套另一套自动商业修订循环。预算用尽后产生明确待审结果，不重新运行全书。

#### 候选选择与预算状态机

“最新创建的 revision”与“选定待晋升的 candidate”分开。C0 是 incumbent；C1 创建/评审期间不移动 selection。只有作者批准，或已确认的 bounded_auto 判定成立时，才以 `expected_selection_revision=C0` 做 CAS 选择 C1；其他操作已改变 selection 则报告冲突。保留 C0 不等于把 revision 历史倒退。

修订尝试状态：`reserved → generating → response_saved → validating → selected | retained_incumbent | needs_review | failed`。

- 在发请求前持久化 attempt_id、输入 SHA、预算预占与 incumbent；每个 attempt 只消费一个逻辑修订名额。
- “最多 2 次替换”按**尝试额度**计，不仅计算成功切换。取消、生成失败、校验失败均消费已经预占的名额，避免无限失败重试。
- 崩溃恢复先找该 attempt 的响应与 revision；存在则继续验证，不能重生成。请求已发但响应未知时记录 uncertain，按受限 transport 策略重试同一 attempt；实际请求次数另外计费记账。
- 验证后保留 C0 时重新核对其绑定、必需报告、合同和 selection 当前性；C0 不合法则 needs_review，不晋升。
- “C1 更好”由独立评审步骤判断，非写手自报；比较目标问题是否解决、事件/POV/字数/回报是否保留，并输出 improved/equivalent/worse/uncertain 和引用依据。auto 仅接受 improved 且所有必需检查通过；equivalent/uncertain 默认保留合法 C0。manual 由作者查看 diff 选择，但仍需通过必需门禁。

### 7.4 免费窗口与导读

按已批准的 3 或 4 章等实际窗口整体评审：

- 读者尽早知道冲突的具体含义，而非只读空泛痛苦。
- 主角在窗口内有可见选择或边界变化，回报不全留给付费后；人物及其定位沿用本书已批准设计。
- 窗口结束时出现具体的下一步选择、代价或后果；不靠另起无关谜团续命。
- 允许盟友协助，核心决断和回报按原合同归属；不要求场场公开打脸。
- 每个已要求的 beat 映射 `contract_item_id → chapter revision → exact evidence`。单章未承担某项功能时用 not_applicable，不硬凑。
- 免费门禁继续位于下一章规划之前，并保持对 Final 和 promotion 的绑定。

Introduction 单独检查是否真实预告冲突和阅读价值、是否剧透结局或承诺正文没有的内容；不把它当 Chapter 1，不占免费名额，正文词数不含它。其已有生成/编译协议保持。

## 8. 评审证据与决策权限

### 8.1 Critique 数据

每份报告记录：schema/rubric、book/project_instance/run、章节、候选 revision/SHA、合同 IDs、方法快照 SHA、输入装配 SHA、模型 provenance、coverage、validity、findings、汇总结论。

每项 finding 至少记录：规则 ID、适用理由、模型建议重要度、事实/风格类别、叙事损失、当前原文 EvidenceSpan、需要时的历史原文/合同引用、建议动作、证据校验结果、引擎处理级别与理由。

将三种状态分别展示：

1. `evidence_validity`：原文/引用/绑定是否正确；
2. `semantic_assessment`：模型/人认为问题是否成立、是否有争议；
3. `gate_disposition`：建议、需复核、或按当前策略阻断。

无模型响应、截断输出、无效 JSON 或 coverage 缺失，属于 unavailable/invalid/incomplete，不是文学 fail，也不能自动转 pass。

### 8.2 证据校验规则

- 引擎计算 SHA，不接受模型自行宣称的绑定。
- `start/end` 为完整候选 Python Unicode code point 下标，左闭右开；不是 UTF-8 字节或浏览器 UTF-16 偏移。
- quote 唯一出现时可由引擎定位并记录修正；多处出现、文字不符或缺上下文时交回修证据，不选择第一处碰运气。
- span 必须非空、在界内，且原文切片完全一致；历史证据同时校验各自 revision。
- “没有兑现”“角色从未知道”是缺失性判断：除相关已承诺项外，还需覆盖范围与相反证据检查。没有引文不能通过虚构引文补齐；扫描完整也不自动证明模型结论成立。
- 纯风格项保持建议，即使模型写了 high/major；合法文风不能通过一个高分词被升级成阻断。

### 8.3 复用现有 QualityFinding 时的重要约束

当前 `QualityFinding.blocking` 与已验证证据 + major/critical 联动，因此不得将模型自报的重要度直接原样映射。新 `Critique` 单独保存模型建议；只有 Policy Adapter 认定属于已批准硬规则，才转换为相应 major/critical。其余建议投影为非阻断项并保留原始重要度供展示。

不是取消原来的连续性或商业门禁。新报告聚合器把必要报告、覆盖与策略结果组成精确候选的审阅凭据，补足当前晋升时空 findings 的语义说明；所有 CLI、Pipeline、Studio 手动晋升路径都经相同校验。

Promotion 在锁内从受信的 artifact 元数据读取方法绑定，再验证其 lock 和报告。调用方省略报告字段或自行传 `mode=off`，不改变候选创建时附带的必需策略。

### 8.4 必需报告矩阵与阶段能力

| 模式/情形 | 必需检查 | 失效如何处理 |
|---|---|---|
| off / advisory | 原流程已要求的合同、连续性、商业等检查 | 沿用原处理；额外 critique 失败只显示未评审 |
| enforced 常规生成 | 精确候选/方法绑定、当前合同要求的连续性与商业等检查 | 缺失/过期/覆盖不足时暂停，不以空 findings 通过 |
| enforced 风格/声音建议 | 非必需建议报告 | 报告 unavailable 不间接变成新硬门禁 |
| enforced 自动采用 C1 | 上述必需项＋有效的目标问题复检与 C0/C1 比较 | 比较缺失/不确定则不自动采用 C1，回用合法 C0或待审 |
| 免费窗口合同生效 | 原有窗口 beat/正文/receipt 绑定检查 | 缺必需兑现按已有门禁；新增 ownership 说明默认仍为建议 |
| P3 知识功能明确启用 | 涉及本章已批准知识约束的证据与 POV 检查 | 必需命题来源缺失/冲突则需复核；无关 unknown 不阻断全书 |

P2 先支持能在模型输入预算内**完整送审**的章节，并让普通 Guardian 在这一分支获得全候选而非首尾截取。超过完整送审能力的章明确 needs_review，或由带精确版本签认的人工评审补足；不偷偷降级。P3 再提供自动分块全覆盖。纯可选风格报告的缺块不改变其建议性质。

## 9. 长篇上下文与三方知识设计（第二批）

### 9.1 上下文优先级

1. 当前用户已确认约束、合同与 POV；
2. 本章必需事实、动作前提、承接、到期回报；
3. 本卷长期约束与当前剧情单元；
4. 相关人物状态、跨章关系和声音引用；
5. 方法指导及可选技法。

保留现有 ContextPack，扩展依赖闭包与遗漏记录，不另造竞争的 ContextAssembler。强制事实超预算时分段组织或报告需要调整，不从中间静默截断；可选方法先丢弃。

每次装配记录：required/included/omitted IDs、来源 revision、字段作用域、预算、遗漏原因及派生器版本。记录说明模型获得了什么，不宣称模型一定遵循。

### 9.2 长章审阅覆盖

- 普通连续性 Guardian 的首尾裁剪在主动增强路径替换为场景/段落切块；商业 Guardian 已接收全候选，分别记录各自覆盖。
- 建议每块约 8,000 字符、重叠约 600，最多 8 块，保留全局 offset；正文仅作为不受信数据。
- 每块传当前事实、角色及约束，合并报告去重，追加一次跨块关系/兑现检查；不能只把块摘要当全文证据。
- 有效区间并集应覆盖目标正文 100%；某块失败使此项 incomplete。若需要超过上限，明确扩预算或人工审阅，不隐式降为首尾。
- 覆盖按检查种类分别存储；字符覆盖 100% 是必要输入条件，不是语义正确率。
- 若检索不到必需的久远事实，对应 gate 为 needs_review，不捏造“未发生”的结论。

### 9.3 知识建模

复用正式 canon 的事实/事件身份，新增**版本化的知识观察提案**，不建立外部 tracking：

| 字段 | 含义 |
|---|---|
| `fact_id` | 被认识/误信的命题，不把错误信念写成客观真相 |
| `holder` | reader 或 character ID |
| `epistemic_state` | known / believed / suspected / rejected |
| `proposition_value` | 该持有者认为命题为真、假或未确定 |
| `acquired_at` | chapter＋scene anchor＋章内顺序 |
| `source_channel` | witnessed / told / read / inferred |
| `source_evidence` | 原文 revision、SHA、span |

`unknown` 不是 observation 的 epistemic_state，而是视图查询的 `resolution_status`：`resolved / unknown / conflicted`。没有合格观察返回 unknown；相反且尚未裁定的观察返回 conflicted，不自动选最后写入的一条。

每条观察有 observation_id，可显式 `supersedes` 同持有者同命题的旧观察；按叙事位置与已批准替代关系重放，保留历史。没有替代关系的冲突需要裁定。`source_channel=inferred` 默认只能为 believed/suspected；成为 known 需新增直接证据，或作者明确确认可成立的演绎规则及全部前提，并走知识提案审批。即使人物确信，也不因此把 proposition_value 写成客观真相。

作者计划中的真相/未来揭示仍保留在设计合同，未实际发生不写成已提交观察。章内先获知后行动需按位置排序，不能仅用“同一章”放行全部知识。

提供三类派生视图：Planner 的作者计划＋正式事实；Scribe 当前 POV 的已知/相信＋本章允许发生的获知事件；Guardian 的完整事实、揭示约束和各持有者知识。生成时可传“不得透露的事项 ID/约束”，避免为提醒写手不泄密而把所有秘密原文注入。

知识提案随该候选进入现有 promotion 事务。新项目从创建时采用明确的知识提案 schema；不开发旧项目 New_Information_Revealed 的回填迁移。缺来源或有争议的知识标 unknown，不臆测补齐。新作品后续修订较早章节、改变知识来源时，使依赖它的后续视图与报告失效，已发布内容进入影响评估，不自动批量改写。

### 9.4 多卷与防注水

复用 NarrativeFormat 的真实卷范围，章号连续，不把剧情单元 ID 直接作为 H5 volume_id。

为每卷记录已有主目标、不可逆变化、阶段回报、未结义务和承接条件；卷末检查“本卷已经给了什么”和“下一卷为什么成立”。到下一卷时带入角色/资源/关系的改变，不重置成同一场背叛。

重复性评审看选择、冲突机制、回报结构与新增后果，而非仅比较措辞。允许有变化的呼应和低压生活段；不规定每章高潮或强制最后增加危机。

## 10. 作者偏好与跨章声音（第三批）

### 10.1 偏好裁决

初版只引入三类范围：确认过的工作区默认、单书、单次运行要求。题材偏好属于方法默认，不优先于用户；跨书系列偏好留待真正需要时再加。

同一维度顺序：本次明确要求 > 本书已确认选择 > 已确认工作区偏好 > 适用方法默认。相同层级冲突且没有明确 supersede 时才请求确认，不用“最后写入”猜意图。

记录 preference_id、scope、维度、值、确认出处、active/pending/superseded、有效范围及可选过期条件。聊天中推断只创建 pending；“同意某一段”不自动批准未呈现的设计或建立全局偏好。新运行冻结快照，默认值更新不影响在途项目。

### 10.2 近期声音索引

从已提交 Final 派生近三章的关键对白策略、重复动作候选及其原文位置，按当前角色筛选。远期角色重返时按角色 ID 查询其最后有效快照和原文，不扫描其他书。

索引不是新 canon，不保存未审稿作为事实；任何统计只召回候选，不能按词频自动删除有功能的口头禅。来源变更即失效并重建。

## 11. 运行、恢复、并发、预算与错误

### 11.1 阶段与依赖

旁路阶段使用独立 `chapter.method_review` 标识；主动路径另有按 attempt 标识的 `chapter.method_repair` 和受影响复检。UI 可合并显示，但 checkpoint 分开保存。

输入 hash 包括候选、合同、canon/知识视图、方法 lock、装配结果、rubric 与角色配置。模型或方法变更仅使真正依赖它的未提交阶段失效，不清空整个 run。

advisory 报告不进入旧流程 promotion 的凭据；enforced 报告必须进入候选的版本化检查绑定。已晋升章继续按 durable receipt 对账，报告到达但服务重启时先核实是否已提交，不重复晋升。

新系统的“继续运行”分为两类：同一 lock 的普通 resume 沿用原 run_id；方法策略发生显式变化则创建 continuation run。在项目锁内固定 `parent_run_id / base_canon_sha / first_uncommitted_chapter / committed_prefix_receipt_refs`。新 run 只从首个未提交章生成；已提交前缀引用原 receipt 及其真实拥有者，不复制成新 run 的假 done 记录，也不用新幂等键重新晋升前缀。基础 canon 或 Final head 与快照冲突时先对账，不覆盖。UI 将这一 lineage 展示为同一本书的连续执行，不创建新书身份。

### 11.2 部分失败与错误分层

| 情况 | 处理 |
|---|---|
| provider 401 | 立即显示认证错误；不做文学修复重试 |
| 容量/429/可重试网络 | 沿现有 transport policy 处理一次有限退避链，遵守 Retry-After；各层不叠加重试 |
| 截断 JSON / 无效结构 | 保存原始输出至私有诊断；最多一次结构修正，仍失败标 invalid |
| 引文文字错 / 多处歧义 | 可唯一定位才机器修正，否则 invalid_evidence；不把错误引文记为正文缺陷 |
| 原文在评审期间变化 | stale，报告保留旧版本归属，按新版本重新评审 |
| 方法丢失 / hash 不符 | 启动前或恢复时明确方法资源错误；不动态拉取 latest |
| 风格建议 | advisory，人工可保留功能性表达 |
| 必需语义判断有争议 | needs_review；不能用“引用校验成功”代替语义裁定 |
| 覆盖缺块 | incomplete，不伪造通过；advisory 不阻塞，enforced 必需检查暂停 |

未知模型输出的额外字段保存在诊断区，不传给严字段核心模型；业务必需字段缺失或不合法仍失败，不为了降低失败率丢掉必需检查。

### 11.3 预算

- 第一批 advisory 只审免费窗口，普通短章尽量合并为一次方法评审调用/章；窗口总审复用现有商业窗口，不重复发另一套相同检查。
- 新方法不擅自改变配置好的模型/推理强度，不自动回退至另一个付费 provider。
- 单章最多 1 次方法修订，且与 post-style 替换共用预算；最多 1 次结构修正。
- 长章使用显式分块预算；超预算不是通过，需人工调整范围或资源。
- 每次 transport 尝试、结构修正、生成、语义复检和既有检查的增量调用都记录；不能只报“修了一次”隐藏十次请求。
- token 用量未知时报告 unknown，不推算为 0。耗时和调用次数先完整采集，再决定是否长期增加成本。

### 11.4 并发

沿用项目执行锁与 promotion 锁；方法包只读，运行快照按项目/run隔离，缓存至少含 project_instance、revision、method hash 与 role。

在启用跨项目主动增强前，移除新增路径对进程全局 os.environ 的依赖，配置作为不可变 per-run 值传递。现有全局模型回退也应在这个接入点修正或用进程隔离约束，测试两本不同模型同时运行。

本方案不承诺把 Web 的内存 job 变成持久化 worker；服务重启后仍靠核心 stage manifest 恢复，进行中的模型请求可能重发并产生额外费用，应在 Studio 明示。

## 12. 持久化、Schema、兼容和回退

### 12.1 拟议内部产物

```text
outputs/quality/methods/
  runs/<run_id>/lock.json
  runs/<run_id>/assets/<sha>/...
  assemblies/<assembly_id>.json
  critiques/<report_id>.json
  coverage/<coverage_id>.json
  decisions/<decision_id>.json
```

仅为方法配置/证据/审计，绝不存第二份正式故事状态。快照和报告采用内容寻址、原子写、不可覆盖；API 数据库保存可重建投影，不成为权威。

### 12.2 Schema 演进

- 第一批 advisory 保持基线行为，仅保存旁路报告与显示索引；新项目从创建起显式携带方法策略，不依赖“缺字段猜旧模式”。
- 主动增强统一升级新项目内部 schema，新候选的 `method_binding` 包含锁/装配/检查要求；同一版本的 off/advisory/enforced 都经统一读写器。没有**改造前旧书**的字段回填或 run 转换任务。
- method_binding 必须由 ArtifactStore 受信调用创建，且参与新 revision 身份；模型不填写身份和策略权限。新报告绑定确切新 revision。
- 知识提案属于第二批新项目 schema，所有生产者/消费者和校验器一起更新；明确 schema floor，不让不认识字段的二进制继续执行。
- 内部 schema 升级不直接反映到公开包；由既有编译/交付路径投影到冻结的 H5 schema。方法字段不透传。
- 同一本新作品已经形成的 receipt 仍不可变，补审或正式修订创建新记录；这属于新作品生命周期，不是旧书兼容开发。

最小版本支持矩阵：P1 起的新项目带明确的 `project_schema_family=narrative_methods` 与版本。P2 必须能读取/继续执行 P1 家族项目的冻结策略；只为新创建候选写新的方法绑定，不改 P1 receipt。P3 同样读 P1/P2 家族，未启用知识功能时保持原行为；启用时建立显式知识起点，无证据的历史观察为 unknown，按需要补证据/确认，不批量推断回填。新版本 reader 支持本功能已发布家族版本，旧 reader 不承诺读取新版本。

这是首次发布以后对新用户作品的最低生命周期支持，区别于对改造前无此家族标识的旧书兼容。实验期未发布的合成 fixture 可重建，但不能把已经正式使用的新作品当作可丢弃 fixture。

### 12.3 适用项目与运行中的新作品

| 对象 | 行为 |
|---|---|
| 新书，首次功能发布 | 默认建议 advisory，启动前展示策略 |
| 改造前已有书和 run | 不迁移、不补审、不承诺继续执行；文件保持原样，不在本轮范围 |
| 改造后正在运行的新作品 | 保持已冻结策略；后续方法升级不自动重启任务或改变剩余章规则 |
| 中途想切方法 | 在章节安全点结束旧执行段，创建有 lineage 的新运行/策略段，从最后已提交状态继续；未完成候选保留或明确废弃 |
| 新作品完成后继续润色 | 明确章节范围，生成新候选并显示跨章影响，确认后晋升/重打包；H5 仍识别同一本书 |

中途切换需校验剩余篇幅和既有已提交承诺。不能只把在途 lock 改成 off 后继续沿用已过期的阶段记录。

#### 较早章节修订后的发布状态

新作品第 N 章修改先进入 `impact_pending`。有完整依赖索引时核验所有依赖项；首版采用保守策略，N 至最后已提交章的必需连续性/知识/回报检查均重新核对，再跑受影响的免费窗口、卷末和终局检查。后章文本没有变化也可产生新审阅记录，不必重写正文。

状态为 `impact_pending → revalidating → ready_to_publish | needs_review`。只有 ready_to_publish 的一致性快照可以编译/打包新发布版本；有未解决影响、缺覆盖或过期必需报告时，保留上一个完整交付包，不导出部分更新。需要变更后章正文时分别创建新候选，仍受作者批准与晋升协议控制。原 receipt 不修改，新审阅/发布快照记录其引用及有效范围。

### 12.4 两类回退

**功能回退：**停止增强用于后续新运行，保留报告；对未晋升改稿丢弃候选即可。已晋升改稿恢复旧内容时，也创建新 revision，并重新对齐它与后续事实、合同、证据及 canon；旧字节不是天然合法的新正式状态。

**程序回退：**优先使用支持当前 schema 的功能关闭版本；若回到不认识新 schema 的旧二进制，先停止相关执行并恢复与程序匹配的完整项目快照，不为此建设旧书转换器。若没有匹配快照，则停留在能读当前数据的版本并关闭增强；不得仅回滚若干 Python 文件继续执行新版元数据。现有封面专用回退工具不适用于本功能。

## 13. Studio 交互及内部 Interface

### 13.1 用户界面

1. 新建/启动页展示“创作方法增强”：关闭 / 仅评审 / 启用；列出实际方法、语言、范围与修订权限。
2. 章节页新增“写作评审”：当前候选版本、覆盖、建议与证据、原文高亮；明确“未评审/证据无效/需复核/存在建议/必需检查通过”。
3. 操作包括保留该表达、请求有限修订、查看 diff、查看历史。接受建议不等于自动晋升；晋升保持现有作者审批与检查流程。
4. 长篇页显示卷目标、阶段回报、带入下一卷的义务，以及 knowledge/coverage 缺口；不是再做一个自由编辑 canon 的入口。
5. 设置页只修改新运行默认值，明确列出正在使用旧快照的任务。

### 13.2 拟议内部路由

- `GET/PUT /projects/{id}/method-policy`：读取/更新未来默认值，写入使用 expected revision / If-Match。
- `GET /projects/{id}/runs/{run_id}/method-lock`：只读运行策略。
- `GET /projects/{id}/chapters/{n}/method-reviews`：按 revision 展示，不只按章取最新结果。
- `POST /projects/{id}/chapters/{n}/method-review`：只读补审指定 revision。
- `POST /projects/{id}/chapters/{n}/method-repair`：显式请求候选修订，传 expected candidate revision 和 report ID。

这些只是设计路由；实现时遵循现有路由前缀和鉴权。使用现有项目访问控制、mutation gate、幂等键；过期输入返回 409 类冲突。模型完成后若项目已删除或候选改变，结果不得落到其他项目，也不得覆盖新稿。

修订入口的权限由服务端从受信候选 binding / run lock 读取：必须为 enforced、repair_policy 非 none、作用范围匹配，且符合原 approval_policy 和剩余额度。按钮、report ID 或请求体 mode 均不授予修订权。off/advisory 的方法修订请求返回明确 policy_conflict，并引导在安全点创建确认过的新策略段；原旁路报告永远不转换为旧候选的硬门禁凭据。基线系统原有的人工编辑功能不受这一新方法开关接管，但手工编辑仍遵循既有候选/晋升流程。

## 14. H5、封面和发布兼容

**用户明确要求：旧书可不考虑，但 H5 接口和导入行为必须兼容。此项是独立发布硬门禁，优先于内部实现便利。**

本功能不要求 H5 改字段、升级解析器或重新对接，不主动修改 `ai-novel-h5`。内核可以重构，输出继续使用当前交接文档 [H5 ZIP 导入合同](../../h5-import-handoff.md)。

- 正文依然从 EPUB 解析，MD 不成为新的导入源。
- Introduction 保持独立，正文章号、免费额度和卷范围不平移。
- `meta/novel-classification.json`、`meta/h5-import.json`、serialization 与现有 manifest 合同保持。
- 书籍/章节身份保持；实际正文修订自然更新其内容摘要，不伪装为“同一正文”。分类未改则分类摘要不变；只换封面仍走既有独立更新逻辑。
- 新增的内部方法、原文批评、知识秘密视图、偏好出处和诊断报告不进入公开 ZIP、EPUB spine 或 metadata；打包继续使用显式 allowlist。既有 serialization 策划字段保留原合同，不在此轮删改；它们继续限运营后台使用，不能当读者目录文案。
- cover-set、选图关系与现有摄影策略不被方法配置影响。
- 重打包后继续校验 EPUB MIME、源 href/item ID、SHA、无重复路径与章节映射。

### 14.1 冻结的对外合同

| 对象 | 维持的版本/行为 |
|---|---|
| `package-manifest.json` | `schema_version: 4`，files 描述、路径/role、书身份、整包摘要算法不变 |
| `meta/h5-import.json` | `novel-h5-import.v1`，`body_source: epub`，有效正文包 status 为 ready |
| EPUB 内嵌章节映射 | `novel-epub-map.v1`，正文/非正文显式区分 |
| 分类 | `novel-classification.v1`，`novel-types.2026-09` 字典及既有标准 ID 不变 |
| 分卷/系列 | `novel-serialization.v1` 与 `narrative-format.v1`，不改变 multi_volume / series_installment 语义 |
| EPUB 类型 | `application/epub+zip`，JSON/图片也使用既有固定 MIME |
| 封面 | cover-set 的候选 ID、排序、选中关系、路径与 keep_existing/replace 语义不变 |

复用现有 exporter，不实现另一个同名 JSON 打包器。新增内部枚举或知识字段不能直接进入外部分类字典。未真正变化的值和数据类型不能因内核重构而改名、改 null/空字符串约定或切换 ID 算法。

### 14.2 身份、章节与更新语义

- 首次新建书分配 project_instance；其外部 `book_id` 沿用现有 `novel-os:<project_instance_id>` 规则，后续重跑、修订、换封面和打包都不重新分配。
- `chapter_id` 沿用同书全局章号生成规则；每章通过 EPUB 的 item_id/href/zip_path/spine_index/xhtml SHA 定位，不通过 MD 路径或标题匹配。
- Introduction 的 spine 位置不影响 `number`；卷内章号不代替全局章号计算免费额度。
- 由于当前 chapter_id 与章号绑定，本轮不提供已导入后“中间插章/删章并重排”的发布操作；这需要独立迁移合同。正常改稿保持章序和 ID。
- 相同内容结构的两本新书仍有不同 book_id；结构摘要、方法版本和标题都不作为书身份。
- 同一正文只换封面：正文/章节/卷身份不变，封面及相关包摘要按原算法变化；H5 不应误判成无更新或新书。
- 只改分类：分类及包含它的相关导入/包摘要按实际文件变化，不能一概声称 EPUB 摘要不变（EPUB 可能内嵌分类）；逐章正文身份及未变化的正文内容保持。
- 新方法只新增内部评审、没有改正文/封面/分类等公开资料：重新打包不因方法报告而改变公开内容版本。

### 14.3 发布前必须通过的 H5 验证

使用现有三份样包锁定当前 importer 合同，不重新生成它们来掩盖基线差异。新增合成包用实际新流水线的 Final/compile/package 路径生成，避免测试只验证手工拼 JSON：

1. 短篇＋Introduction＋免费截止第 3 章。
2. 同类结构、免费截止第 4 章（免费策略仍是 H5/已确认合同的产品输入，不凭卷号猜）。
3. 48 章、4 卷、每卷 12 章；另保留现有 80 章/4 卷基准。
4. 同书只换封面，再次重复导入该包。
5. 同书单章文字修订、分类修改、卷标题修改，分别核对更新域。
6. 不同书同样结构/正文，确认不合并。
7. 损坏摘要、错 MIME、重复路径、章节映射不一致，确认原数据保持且返回明确错误。
8. 对 ZIP 成员、EPUB 元数据及公开 sidecar 扫描，确保新增方法/秘密/偏好资料不泄露。
9. 执行 A→B→A 历史包重放：按既有 H5 合同标记 history replay 或进入明确恢复确认，不把旧包当新更新静默覆盖，也不重建书/章。
10. 仅修改 Introduction：front_matter 及相应 EPUB/导入/包摘要变化，正文 content_sha256、章/卷身份、免费计数和权益保持。

每个用例保存 before/after：manifest/import/各组件摘要、book/chapter 主键、卷绑定、收藏/进度/解锁记录。预期摘要按既有算法列成断言：封面单改保持 EPUB/content/front_matter/分类/分卷；导读单改保持 content/分类/分卷/封面；文字单章改保持书章身份及未变章节 XHTML；分类修改只要求实际未变的组件摘要稳定，不错误要求内嵌分类的 EPUB 整体 SHA 恒定。

引擎侧独立合同测试通过后，还需用 **H5 当前使用的校验器/导入器版本**做联调并留下版本、包 SHA 和结果。可使用 H5 团队提供的测试程序，或由团队在测试库执行现有导入流程；不靠改 H5 来适配新包。不具备该验证条件时，只能标记“引擎合同测试通过、H5 联调待验收”，不得宣称整体兼容已验收。

正式放行证据包括：书/章/卷数量正确，导读独立，免费计数正确，仅换封面不新建书，重复导入幂等，已有收藏/进度/解锁记录保持。这里用的是新测试书的更新生命周期，不要求迁移改造前旧小说。

## 15. 验证计划

### 15.1 工程测试矩阵

| 类别 | 必测场景 |
|---|---|
| 模式隔离 | off 不多发请求；advisory 不改 production prompt/canon/Final/receipt/ZIP |
| 策略与版本 | 系统默认变化不影响新系统已启动的 run；方法文件同名改字节使 hash 变化；恢复缺资源不取 latest |
| 字数/证据 | 英文缩写、连字符、弯引号、emoji、组合字符、重复引文、UTF-16 UI 定位、Introduction 排除 |
| 质量授权 | 模型声称 major 的风格建议不阻断；真实已批准关键约束仍生效；序列化不恢复未验证权限 |
| 修改与复检 | C0/C1 不混引文；style/商业修改后旧报告失效；修订失败保留合法 C0；不合法 C0 不晋升 |
| 恢复 | 报告写后崩溃、候选写后崩溃、晋升成功但响应丢失；预算与幂等不重置 |
| 竞争 | 同书两个修订请求、评审过程中手改、两书不同模型、项目删除后迟到结果 |
| 知识 | 读者知道而 POV 不知、人物误信、同章先后获知、视角切换、旧章改动影响未来 |
| 长篇 | 12→13 卷界、早期伏笔后期回收、低压有效呼应、同冲突换措辞、长章中段关键证据、缺一块 |
| 交付 | 导读＋多卷；只换封面；只改分类；同结构不同书；无内部方法文件泄漏 |
| 兼容 | 新项目 off/advisory/enforced 全部使用同一对外 H5 合同；P2/P3 支持 P1 起已发布的新项目家族；改造前数据不在范围；不兼容二进制不误读新 schema |

先写 Interface 行为与失效/故障注入测试，使用 fake ModelRouter，不消耗模型。API 投影测试和完整现有回归随后执行；新测试不通过时不靠放宽既有门禁过关。

### 15.2 英文 A/B 试点

建议设计 3 组独立合成输入，每组 A/B 各 3 次：

- A：现有 off 基线；B：固定版本增强；总计 18 份候选窗口/片段，不只是 18 个单章。
- 组一：免费截止第 3 章的短篇窗口；组二：截止第 4 章且家庭对白密集的窗口；组三：多卷交界与历史伏笔回收片段。
- 固定设计、语言、模型、推理强度、字数与输入事实，不以挑选最好样本代替比较；真实模型实验单独申请预算，当前设计阶段不启动。
- P2 前的 B 组由隔离试验 harness 使用 compiler 和已审阅的 prompt 变体生成，仅保存实验候选、不晋升到真实项目；它不需要先把生产默认值改成 enforced。第三组按明确测试章范围运行，不冒充免费窗口。
- 两名独立英文编辑匿名评审，分歧保留；另邀请目标读者验证阅读意愿。先评事实/覆盖，再评自然度、声音、因果、局部满足与继续阅读意愿。
- 建议试点放行标准：9 组配对中至少 6 组增强版获得编辑综合偏好；任何新增严重 POV/因果/关键承诺破坏都阻止放行；不能以缩短漏剧情换读感。此阈值用于工程试点，不宣称统计显著或真实付费提升。
- 附加记录中位/p95耗时、模型请求数、可得 token/费用、修订次数、错误率与人工推翻率。建议常规短章全链路中位耗时增幅不高于 30%；超过则先削减冗余调用再评审，长章分块单独核算。

商业上线后若要判断完读/付费变化，需要独立运营实验并控制题材、封面、投放与免费窗；这不由本次代码测试代替。

## 16. 实施顺序与小提交计划

| 阶段 | 交付物 | 放行条件 |
|---|---|---|

| P1：旁路评审 | 锁快照、只读评审、证据与覆盖、Studio 报告、成本日志 | advisory 隔离及证据测试通过 |
| P2：主动增强 | 按角色装配、版本化候选绑定、统一晋升检查、有限修订与复检 | A/B 收益＋故障恢复＋完整回归通过 |
| P3：长篇增强 | 分块全覆盖、知识提案及派生视图、卷界检查 | 新项目多卷/POV/历史依赖与 H5 验证通过 |
| P4：长期维护 | 偏好作用域、近期声音索引、受控方法升级 | 不串书、不污染 canon、升级可回退 |

建议提交粒度：

1. 模式/默认值/失效规则测试与类型。
2. 英文方法资料及固定来源，独立于运行。
3. 只读 compiler / validator 与证据用例。
4. run 快照、旁路报告与预算记账。
5. Studio 只读评审展示与人工保留动作。
6. 独立 A/B harness，保存全部结果而非仅成功案例。
7. 新项目内部 schema 与统一读写/验证；对外 H5 合同冻结测试。
8. 主动候选绑定、统一 promotion gate 与 post-style 修订预算。
9. 主动指导与修订/复检，默认仍保持 advisory。
10. 长篇覆盖和新项目知识 schema 分开提交；每项单独测试，无旧书迁移。
11. 偏好/声音索引与文档；完整回归、打包检查和部署说明。

每阶段都可独立停止，不要求先完成全部功能才验证读感。P3/P4 不成为 P1 免费章试点的前置大工程。不在设计阶段承诺上线日期或声称已完成实现。

H5 合同回归贯穿所有阶段，并非到 P3 才检查。每个拟部署版本都需通过其涉及的现有样包与更新用例；任何改变生产生成、晋升、编译或打包路径的正式发布，都以第 14.3 节的当前 H5 导入器验收为放行条件。

## 17. 风险与处理

| 风险 | 处理 |
|---|---|
| 规则越多越像模板 | 每阶段最多 3 个方法、总预算、功能性判断、作者声音优先 |
| 新评审再次高频暂停 | 主观风格先建议；分离无效报告与小说缺陷；有限修订和人工出口 |
| 知识索引自身错误 | 来源证据、unknown、提案晋升、不自动把旧摘要转事实 |
| 大规模文案去味破坏剧情 | 小范围候选、不可变原稿、必要事实与回报复检、失败不晋升 |
| 规则更新使恢复漂移 | 冻结实际内容和角色配置、依赖 hash、旧章 receipt 权威 |
| 同一模型自评乐观 | 确定性证据校验＋独立英文编辑/目标读者；不以模型分数当销量 |
| schema 让代码回退失效 | 标明新项目 schema floor、使用兼容关闭版本或匹配完整快照；不建设旧书迁移层 |
| 方法文本与样本泄露 | 审阅本地资料、原作隔离、打包 allowlist、诊断/配置不含凭据 |

## 18. 评审与批准范围

建议先批准整体架构及 **P0/P1** 的实施范围：英文功能性表达＋免费窗口兑现，只出报告，不改正文、封面或 H5。P2 开始前展示真实对照结果、额外成本和失败案例，再确认主动修订。

本设计不恢复当前暂停的小说创作，不创建新的小说 run，也不授权重启服务、提交或推送代码。用户可直接指出需调整的章节或策略，无需重新完成需求访谈。
