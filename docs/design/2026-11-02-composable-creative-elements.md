# 创作元素分层、故事组合与作者意图落实

日期：2026-11-02。状态：**已被用户否定并取代，仅保留历史。** 最新采用讨论方向是 [四组必填与标签 Markdown](2026-11-02-tag-guided-workshop.md)，不再维护五层选择或组合方案。

用户补充确认：**五个创作层中的已选设定，都必须直接影响作品输出。** 此项是明确需求，不再作为可选设计建议；具体实现方案仍处于设计阶段。

本轮根据作品类型维护页面反馈，核对现有选择、资料投影、头脑风暴及执行交接代码，提出总体质量方案的增量设计。当前正文继续使用冻结配置；本方案不修改运行任务、骨架、资料版本或 H5 交付协议。当前作品的全书质量复盘仍按此前约定，待正文完成后进行。

## 1. 痛点与现有行为

用户面对的主要困难不是类型数量本身，而是不同用途的信息都被称为“类型”：发行分类、创作资料分组、故事主题、世界规则、人物成长、情绪和表达方式混在一起。很难判断选择的作用、优先级和冲突，也很难知道模型最终是否落实。

| 当前对象 | 已核对的实际作用 | 不应推断成 |
| --- | --- | --- |
| 维护页“关联 H5 题材” | `publication_mapping` 表示资料适用的分类；新建页匹配时显示“题材相关” | 勾选“恐怖”就给所有使用该资料的作品添加恐怖剧情 |
| 新建小说中的 H5 分类 | 作者的本书分类，传入设计上下文，并由代码绑定骨架分类区块及后续发行链路 | 仅供展示、模型可以任意修改的标签 |
| 维护页“创作维度” | `dimension` 是资料分组；随资料进入模型作为分类描述，筛选下拉框本身只改变列表 | 用户又选择了一条额外的剧情或一套固定组合 |
| 本书选中的写作资料 | 冻结版本与 SHA，按阶段投影读者期待、机制、人物、文风、检查说明 | 资料中的每个例子都已经成为本书事实 |
| 本书资料作用 | 已有主导故事、辅助情节、氛围与表达、未指定 | 已经完成了不同元素之间的语义协调 |

代码依据：

- `core/creative_types.py`：`Profile`、`TypeRef`、`compile_snapshot`。投影保留名称、维度、简介、适用范围和阶段说明，**不包含 publication_mapping**；组合说明只在关联资料同时选中时纳入。
- `web/src/components/CreativeTypePicker.tsx`：适用分类匹配、按维度分组、选择作用。
- `api/workshop.py`：本书分类标签进入输入，资料版本形成快照。
- `api/workshop_design.py`：已有 `genre_roles`、机制、移除影响及不同因果路线的指导，并非完全没有融合设计。
- `api/workshop_delivery.py`、`api/workshop_classification.py`：作者分类进入交付上下文，代码绑定准确的发行 ID。
- `core/creative_execution.py`：冻结的创作交接继续进入章节规划、写作与评议。

现有底座可以复用。需要改善的是：资料仍偏完整主题包，作用主要靠文本理解；当前分类、资料作用和本书落实情况没有统一、直观的组合视图。加入更多标签不能自动保证融合与质量，也不意味着每个组合都要维护一个新大纲模板。

## 2. 总体模型：分类、元素、组合方案、本书设计分开

**发行分类**决定 H5 如何检索和上架。**创作元素**描述可复用的写法与阅读承诺。**组合方案**保存常用元素和作用配置。**本书设计**是模型与作者确定的独有人物、事件、关系、选择和回报。

组合方案只引用元素版本，不复制整套提示词，不包含默认成立的人物或固定章节。使用相同组合方案可以创作不同小说。

用户提出的“婚姻 → 情感 → 背景 → 情绪与风格”适合作为选择体验，但底层不做单一父子树。婚姻、恐怖和狼人可以交叉，女性觉醒也不限于婚姻；采用独立可组合的层次更合适。

| 创作层 | 回答的问题 | 示例 | 选择方式 |
| --- | --- | --- | --- |
| 故事主轴 | 这本书主要围绕什么关系或冲突展开？ | 婚姻背叛、家庭秘密、复仇、争夺继承权 | 普通模式先明确一个主轴；确有双主线时明确各自作用 |
| 题材与世界 | 什么叙事承诺、能力或社会规则改变故事？ | 狼人、悬疑、现实心理恐怖、超自然恐怖 | 按主导或辅助使用；未确定时让模型提出路线 |
| 人物与关系走向 | 重点探索什么变化？ | 女性觉醒、信任修复、母女重新理解 | 可选，不因选中就预定离婚、和解或恋爱结局 |
| 故事背景 | 人物受到什么环境条件影响？ | 现代都市、封闭小镇、旧宅、宫廷 | 可先宽泛，必要的具体化由模型提出 |
| 阅读感受与表达 | 希望读者怎样感受，文字怎样呈现？ | 压抑后释放、甜中带刺、紧张；克制对白、贴近人物视角 | 同一 UI 区域内区分“读者情绪”与“文风”，不混为一个字段 |

“恐怖”是题材承诺；“紧张”是阅读感受；“短句、贴近感官”是表达方式。三者相关，但不能相互替代。狼人也不能仅被解释成背景里的称谓；作为核心元素时应改变能力、处境、选择或主要关系。

同一元素可以有跨层作用，但应指定主要用途，而不是到每层复制一份资料。“婚姻背叛”有情绪建议，不等于它必须永久绑定虐心、都市、离婚等所有选项。

### 2.1 五层都是输出要求

作者在本书选择的五层设定都属于必须落实的创作要求，不得仅显示在 UI、写入元数据或作为模型可忽略的参考。允许某层暂未选择；一旦选择，主导/辅助等作用只影响份量与呈现范围，不允许将其作用降为零。资料库中的可选机制和例子仍是参考，不因选择该元素就全部变成本书事实。

| 创作层 | 对骨架与章节设计的直接影响 | 对最终正文的直接影响 |
| --- | --- | --- |
| 故事主轴 | 确定核心矛盾、主要行动、升级、高潮及其回报 | 关键场景围绕主轴推进，人物行动持续改变局势 |
| 题材与世界 | 确定相关能力、限制、社会秩序或题材叙事机制，改变可行选择与后果 | 规则在行动、发现、冲突和应对中真实起作用 |
| 人物与关系走向 | 规划欲望、关系起点、转折依据、选择与变化轨迹 | 通过对白、行动、犹疑、代价和关系后果体现变化 |
| 故事背景 | 将时代、空间、资源、社会习惯、信息传播等与故事相关的条件纳入场景安排 | 环境影响行动机会、信息获取和互动方式，并有一致、具体的生活细节；只换地名不算充分落实 |
| 阅读感受与表达 | 安排开篇情绪触发、信息差、节奏、阶段回报，确定视角与文风准则 | 实际叙述、对白、感官、留白、句段节奏体现所选表达与情绪设计；不能只追加“她很愤怒”等情绪词 |

每个已选项沿同一条链传递：**作者选择及版本 → 本书具体设计 → 章节/场景安排或全局表达准则 → 实际正文 → 落实证据与问题。** 复用现有采用记录、故事地图、骨架和执行交接保存关联，避免另造一份事实来源。

后台阶段输入组装必须覆盖全部已选要求；没有进入当前章节任务的要求，应能从全书分配中看出作用位置。章节按场景功能落实，不要求每章重复所有设定或始终维持同一种情绪强度。全局的时代、世界边界和叙述方式仍须保持一致。

代码检查选择是否丢失、版本是否一致、具体设计与承载位置是否存在、引用能否定位。缺失或损坏的传递不能标记为已落实。模型和阅读评议检查实际内容是否体现；有段落引用不等于效果成立，目标读者情绪也不等于真实读者已产生该情绪。

如已选设定相互矛盾或与后续作者要求冲突，应明确指出并在既有重大决定流程中解决，不能自行忽略某层、改分类或暗改已确认故事。语义弱化进入有依据的修订建议，不增加无限模型重试或每章独立多轮检查。

## 3. 作者怎样选择：保留必需选择，其他逐步展开

保持之前确定的入口与视觉：新建小说直接进入“一起把故事想完整”，同一个白色面板、现有字体与紫色强调。

1. **先选 H5 主分类**，保证发行身份明确。其余 H5 字段沿用原有上限和冲突约束，不新增重复标签来源。
2. **选择故事主轴并填写构想**。系统根据已有选择推荐相关创作元素；推荐不等于自动采用。不要求用户先懂专业术语。
3. **按需补充世界、成长、背景、阅读感受**。允许暂不确定或明确委托模型推荐。普通界面不展开整库复选框；复杂配置折叠为“进一步设定”。
4. **在原本的首轮头脑风暴内给出 2–3 个可比较方案**：故事一句话、开篇事件、主要人物关系、融合方式、预期感受和主要取舍。作者采用一条并可补充自由文本，复用现有重大决定入口。
5. **显示“这本书的创作设定”摘要**，标清作者已选、模型建议、尚待确定。本轮只解决影响故事身份的问题，不让作者决策手势、道具或普通转场。

选中元素本身不立即生成骨架，不为每个元素单独调用模型。修改组合也不默认推倒全书：先说明影响哪些已定内容；作者确认重大变更后只重做依赖内容。已经启动正文的作品保持冻结，不能热更新资料。

普通作者可以从保存的组合方案开始，再调整一两项。专业作者可以自选各层。二者最终形成相同的本书选择记录，不维护两条创作流水线。

## 4. 用“婚姻背叛＋恐怖”检验设计

以下仅为方案说明，不是内置固定剧情。

| 路线 | 两个元素如何共同推动情节 | 需要明确的取舍 |
| --- | --- | --- |
| 现实心理恐怖 | 丈夫长期利用夫妻共同秘密维持控制；妻子查明背叛的每一步，都让原本安全的家庭空间变得危险 | 无超自然设定，恐怖来自持续威胁与关系失真；不能只有一段抓奸再贴上“恐怖”标签 |
| 超自然恐怖 | 婚姻中的背叛与某个超自然承诺有关；真相既改变夫妻关系，也改变主角摆脱威胁的办法与代价 | 必须建立超自然规则及限制；不能无依据加入鬼怪，也不默认血腥内容 |
| 婚姻故事＋紧张氛围 | 重点是共同生活的裂缝、逐渐揭露的秘密和人物选择，用紧张文风表达 | 若不足以兑现恐怖题材承诺，就应建议作者采用悬念情绪，不能仍把“恐怖”当已落实 |

第一、第二条可以形成不同恐怖小说。第三条适合只想要气氛的作者，但若本书已经明确选择 H5 恐怖，须由作者调整分类或强化题材承诺，系统不能暗改 ID 或暗中降为氛围。

模型在提出方案时应说明“为什么必须同时有这几个元素”。对主导元素，检验移除后主要选择、转折或结局是否明显变化；对文风元素，检查叙述方式和阅读体验，不要求它改变情节。不能对所有层使用同一条“必须改变高潮”的规则。

## 5. 维护内容：少量清楚的说明，完整的结构数据

建议页面显示名改为“创作元素与方案”，保留现有单面板布局。一级页签只有“创作元素”“组合方案”；H5 分类作为固定标准入口，不允许自由创建发行 ID。

每个元素常用编辑区只展示：

1. **定位**：名称、所属层、一句话作用，适用/建议 H5 分类。
2. **读者看点**：希望读者获得什么；哪些特征体现这个元素；怎样进入行动、关系、发现与回报。
3. **变化与边界**：几种可选实现方式、常见俗套、不能擅自添加的设定、可组合的机会和可能冲突。

文风元素显示声音、视角、节奏等适用字段，不要求填写能力代价；世界元素显示规则、限制和后果；成长元素显示选择与关系变化。完整模型预览、阶段范围和版本历史放在高级区。简化作者操作，不删掉底层质量信息。

“关联 H5 题材”改为 **“适用的 H5 分类”**，直接解释“用于推荐这份资料；不会替本书选分类”。维度筛选改为“资料分组”，不再像作者必须完成的额外设定。

不是为所有组合维护独立系统提示词。提示组装保持统一：

**通用创作方法＋已确认作者要求＋选中元素的阶段说明＋本书已采用设计＋当前阶段任务。**

每个元素存结构化写作指导，统一编译器组织输入。未选择的例子、未采用方案、H5 适用候选不得变成本书事实。保留目前按版本、哈希、阶段投影的能力。

最初迁移现有三套资料：狼人以世界机制为主，婚姻背叛以关系冲突为主，女性觉醒以人物成长为主。保留各自有价值的读者体验和写法，不强行删成一句标签。先验证少量元素有效组合，再扩充其他题材；不一次填满几十套薄模板。

## 6. 精确落实：让作者看见选项如何成为故事

在已有故事地图旁增加简洁的“设定落实”视图，复用现有采用记录与骨架证据，不另建一套相互冲突的事实库。

| 作者选择 | 适当的落实依据 | 不足以证明落实 |
| --- | --- | --- |
| 狼人主导世界 | 特有能力、限制或群体规则改变人物困境与转折 | 人名旁多了 Alpha、Luna 等称谓 |
| 婚姻背叛主轴 | 一个共同承诺被破坏，发现与行动改变信任、利益或生活安排 | 某个配角口头说丈夫出轨 |
| 女性觉醒 | 人物对自身愿望的认识，付诸行动并承担后果 | 结尾说一句“我自由了” |
| 恐怖题材 | 持续、具体的恐惧来源和升级，人物应对使局势变化 | 仅有阴天、暗房和紧张形容词 |
| 克制文风 | 实际对白、动作、视角与留白形成效果 | 骨架中写着“文风克制” |

同轮设计回复说明每个选项的作用、具体承载点和未决事项；骨架交付引用真实节点；正文检查引用实际段落。只在适用环节检查，例如未有正文时不能声称文风已经兑现。

代码负责：身份与版本正确、作者决定不被暗改、选择不被遗漏、引用可定位、阶段状态清楚、H5 产物符合协议。语义问题及阅读效果依靠设计和正文证据评议，不能由 JSON 字段齐全或模型自评分保证。

引用到了一个节点，并不等于它确实表现了题材。若出现核心选择与设计矛盾，明确解释问题并交给作者处理，不能让模型自行标记“不适用”来跳过选择。风格强弱、艺术解释等建议不增加自动失败门或反复审查循环。

## 7. 降低同质化：变化发生在故事因果中

分层选择提高控制力，但不能仅靠随机组合标签产生多样性。相同“狼人＋婚姻背叛＋女性觉醒”仍可能重复“受辱、离开、遇到更强救星”的故事。

采取四层措施：

- **资料保持开放**：提供阅读承诺、机制原则与可选办法，不规定每本都从公开羞辱开始，也不规定某个结局。示例默认不采用。
- **方案有因果差异**：在作者未锁定的范围内，改变主人公追求、权力结构、对手策略、秘密的作用、能力限制、失败代价或最后选择。名字、职业和地名不同不算充分差异。
- **组合产生交互**：例如背叛导致狼人能力或族群保护条件变化，而非前半本婚变、后半本另开一条无关狼人支线。并非每个元素都要占同等篇幅；次要元素不抢走主轴。
- **积累可比较的故事设计摘要**：后续可为已采用故事保存主要冲突、关系结构、关键转折和高潮选择；新作仅检索本工作区相关摘要，提示相似点并提供不同路线。没有足够历史证据时，不宣称去重；也不设置相似度自动驳回或把旧书细节抄进新书。

开篇通过具体人物处境引发关切；中段带来关系与局势变化；高潮检验选择；结尾回应核心阅读承诺。情绪可以是愤怒、同情、心动、惊惧、好笑、惊奇，不把所有题材写成同一种受苦反击结构。

“规则、选择、代价”是帮助故事成立的工具，不是正文条款清单。优先让人物在场景中经历这些内容，保留亲密、魅力、幽默、奇观、行动和余波；不要求每章重复解释机制。

## 8. 开发顺序与验收

| 阶段 | 增量工作 | 验收重点 |
| --- | --- | --- |
| A 语义与选择体验 | 明确适用分类、资料分组、创作层；组合摘要；分层推荐；保留旧快照 | 作者能解释自己选了什么，不会把维护页映射误认为本书分类 |
| B 组合与落实 | 元素数据与组合方案；编译阶段上下文；复用首轮方案卡、采用记录与故事地图 | 已选版本、角色及作者要求真实进入请求；骨架具体承载核心选择 |
