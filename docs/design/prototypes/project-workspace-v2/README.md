# 作品详情 · 交互设计稿

**状态：用户已于2026-10-24确认并锁定视觉与交互 v1.0。** 后续实施以[设计基准](../../2026-10-24-project-workspace-design-baseline.md)和 `design-baseline.json` 为准。JSON的业务化展示方案已确认，尚未实现，不要把当前原文折叠展示误认为完成此功能。

这是供确认布局与信息结构的离线设计稿，入口为 `index.html`。沿用 Novel OS 当前的蓝紫配色、白色玻璃面板、无衬线字体和圆角控件；不连接模型，不修改作品，不执行生成或导出。

## 页面结构

| 标签 | 主要内容 | 解决的问题 |
| --- | --- | --- |
| 概览 | 故事简介、创作进度、任务状态与下一步操作 | 进入作品先看到当前情况，而非大面积空白 |
| 章节 | 编号、标题、状态、字数、骨架章节介绍；搜索和展开详情 | 用可扫描的列表取代大卡片，知道每一章讲什么 |
| 故事骨架 | 主线、结构和原始骨架入口，注明采用来源 | 让已确认的创作设计在作品中可见 |
| 人物关系 | 人物介绍、核心处境、骨架明确记载的关系及原文依据 | 替代空头像和“暂无人物关系”，不凭共同出场推断关系 |
| 费用与交付 | 分阶段人民币估算、token用量、导出入口 | 将运营信息集中展示，缩短其他页面 |

顶部始终保留书名、封面、基本进度及主要操作。标签切换不改变作品数据，正式实现会保留当前标签并按需加载相应数据。“素材集”“设定库”从本页移除，历史数据保留。

## 交付包与阅读全文补充

新增 `library.html` 作品库配套稿，以一部真实作品演示卡片点击进入详情、搜索以及“导出交付包”。详情页顶部与费用交付页也有同名入口。三个入口正式接入时共享封面工作室的 `book-package.zip` 及交付状态：就绪可下载，更新中显示进度，缺失或失效说明原因并提供生成/更新入口。不会通过 GET 静默重新出图。项目列表/详情接口需要携带轻量交付状态，避免为每张卡片请求完整封面工作室数据。

顶部主按钮调整为“阅读全文”：正式实现提供只读的全书阅读页，完整目录、章节跳转、上一章/下一章和连续阅读；按需加载完整已生成正文，不以骨架简介替代内容。未生成章节明确显示状态。编辑作为单独入口；打开阅读页不生成、修改或自动提升稿件版本。现有生产 `ChapterView` 是单章编辑器，打开缺少 Final 的章节可能自动提升草稿，不能直接当作只读阅读页复用。此轮仅补充设计，阅读器尚未实现，原型按钮有明确演示提示。

## 本稿内容与边界

示例为《Boots by the Door》：20章，17,692字，作者 Audrey Ellingford，使用现有选定封面。「章节」标签仍取前三章演示正文列表；「故事骨架」已包含完整17模块和20章细纲；「人物关系」标签选取 Riley、Kaleb、Lily 和 Marisol 展示交互，全部明确关系可在骨架第6节阅读。中文导读与来源原文分别标记。

这是设计快照，进度不会随后台任务变化。费用不以虚构金额冒充实际账单。无法取得的内容应说明原因，不能由页面自行补造。

## 性能方案（尚未部署）

当前作品库的主要瓶颈已定位：为每一章反复解析整部作品的版本记录。预备修复改为每部作品集中读取一次。17部作品、471章的本机服务层测量由约3.05–3.92秒降至0.38–0.81秒，列表响应内容保持一致。这里是本机服务层测量，不等于最终页面加载时间；正式接入后仍需测量运行实例。

作品详情会分标签加载骨架、关系、费用等较重内容，首屏不再同时请求所有模块。
