# 开篇设计：让读者进入冲突、在意人物并期待后续

状态：2026-11-01，用户已确认本设计并强调必须带入读者情绪；未实施、未部署。补充[故事地图与重大决定](2026-11-01-workshop-story-map-and-decisions.md)与[小说质量总体方案](2026-10-31-novel-quality-optimization-master-plan.md)。本次只更新设计和独立交互稿，不修改真实讨论、已采用故事或模型任务。

适用范围：这是总体方案 §1.1–1.2 所定义的**系统级创作方法论在开篇的应用**，对所有题材和作品生效。读者投入贯穿全书与各创作阶段；下面的狼人故事仅为解释示例，不是生产提示词模板、启用条件或实现范围。

## 1. 核心要求

开篇吸引力成为故事设计的重点。模型必须设计一个能实际写成场景的入口：发生了什么、谁在乎什么、为什么冲突此刻无法回避、题材如何参与、读者得到什么以及接下来想看什么。只有“开篇很炸、制造愤怒、女主被欺负”这样的意图，不构成完成的设计。

强烈来自读者看得懂的冲突与反差。一次亲密关系中的选择、一次荒谬又可信的失控，都可能比陌生人物遭遇大量灾难更有力。应尽早让读者感到局势已在改变，而不是先读完世界设定与人物履历才进入故事。

设计同时追求三件事：**有事发生、有人值得在意、有一个具体后续值得等待。** 愤怒、同情、怜悯、荒诞好笑、紧张、心动、惊奇均可成为入口；不要求每本书同时刺激所有情绪，也不将所有题材改成受辱后反击。

用户确认的重点是读者的情绪参与。人物冷静处理不公时，读者依然可能感到愤怒；人物故作轻松时，读者可能感到心疼。因此模型需说明具体事件怎样使读者理解、在意并期待人物的下一步，不能用人物大哭、发怒或旁白宣称“令人心碎”当作效果证据。情绪设计贯穿开篇投入、中段累积与变化、高潮选择、结局回应；首章建立的关切应在后续持续发展。验收需回到实际正文中的触发、反应与后果，模型意图和读者实际感受分别记录。

## 2. 把情绪写成发生的事情

先根据已选题材、创作方向、读者与故事事实，推荐一种主要情绪及其后续期待。复合感受允许存在；它们是写作目标，不是固定枚举或情绪分类考试。

| 希望引发的体验 | 必须设计的可见依据 | 希望产生的续读期待 | 应避免的替代品 |
| --- | --- | --- | --- |
| 愤怒、替她不平 | 具体付出与具体不公相撞；谁获益、谁被要求承担代价清楚 | 她会怎样应对，能否改变关系或处境 | 连续辱骂、全员恶人、无限延迟反应 |
| 同情、心疼、怜悯 | 一个可理解的愿望受到阻碍；人物仍有能力、尊严或矛盾 | 她能否保住在意的东西，获得真实援手或选择空间 | 堆创伤、只展示可怜、靠路人救走主线 |
| 荒诞、好笑、替她尴尬 | 意图与现场结果反差；各方按自己的利益行动却让局势失控 | 她如何应付，错误会带来什么新关系或代价 | 无关段子、人物突然降智、让受苦本身充当笑料 |
| 紧张、担忧、好奇 | 能理解的危险或矛盾；必要线索可见，未知问题具体 | 能否避险、解释矛盾，答案会改变什么 | 信息全藏、专名过载、用混乱冒充悬疑 |
| 心动、向往、惊奇 | 具有吸引力的人或世界在互动中显出规则、障碍和代价 | 关系是否靠近，愿望能否实现，又要付出什么 | 只有外貌描写或世界奇观，与主线无关 |

情绪必须有落点。先心疼后期待自主、先好笑后担心后果、先心动后发现立场冲突，都比重复同一种刺激更能支持后续设计；并非强制每章完成同一条情绪曲线。

## 3. 一份开篇方案应包含什么

这份资料由模型主动完成，作者不逐字段填表。对用户默认显示前四项，其他内容折叠到“为什么这样开篇”。

| 内容 | 设计需要回答 |
| --- | --- |
| 开场场景 | 从哪个正在发生的事件切入？谁在场、想做什么，什么正在阻止？ |
| 情绪与代入 | 希望读者先感到什么？哪个具体欲望、关系细节或损失让人能够理解？ |
| 核心冲突与选择 | 双方各要什么？主角有什么回应空间、筹码与限制？为何不能无代价解决？ |
| 首次回报与后续期待 | 首章实际给出哪个答案、行为、关系变化或情绪收益？因此留下什么具体期待？ |
| 题材作用 | 狼人规则、悬疑信息差、关系机制等怎样改变此刻事件？删去它，选择与代价是否仍完全一样？ |
| 视角与信息释放 | 读者从谁的感知进入？现在必须知道什么、哪些解释可以晚一点提供？ |
| 全书连接 | 开篇提出的关系、目标或问题如何进入中段，并由高潮和结局回应？ |

不把所有材料塞进首段。最开始建立清楚的处境与情绪抓手，随着场景展开再揭示必要规则、人物复杂性和行动后果。正文首屏、首个场景、首章是不同范围；没有统一字数或百分比能保证它们成立。

主角可以受制、犹豫或暂时无法反抗，但需有可辨认的欲望和判断；不强迫第一段就赢，也不能让长时间受辱代替人物塑造。对手的行为需要利益与动机；是否暧昧、是否有善意服从本书设计，不固定“每个恶人都洗白”。

简介、Introduction、骨架里的“首章很有冲突”不能替代正文的真实开场。新增预览只用于选择体验，不自动成为正文或已发生事实。

## 4. 当前狼人故事的示意

以下沿用已讨论的医师救助、共鸣身体代价、姐姐追责、女儿离开等素材，说明新的展示方式。新的句子、编排和开场推荐都是设计示意，不写回任务 `b3f80487de8a`，不替作者确认。

推荐体验：**先心疼她的付出，再为代价被转嫁而不平，继而期待她怎样作出选择。**

> 女儿把出发的行李放在门边时，她的手还在发抖。昨夜，她用自己的呼吸共鸣稳住了被驱逐者的狼形；现在杯底碰桌的轻响，都让她缩起肩膀。
>
> 姐姐替杯子垫上一块布，又把追责单推到她面前。补偿义务一栏，写着女儿的名字。
>
> “她明天就要走了。”
>
> 姐姐把另一张纸放在上面：承诺以后不再接治被驱逐者，这项安排就可以取消。

这段尚不是完整首章。第一场需要继续让女主回应，并让回应改变局势；可以沿现有走线，把她险些要求女儿延期、最终选择自己付出资源的过程写出来，呈现女儿自己的立场。不能停在递纸上，就宣称已兑现第一章。

设计重点：

- 行李体现女儿具体的未来，救治后的感知负荷体现狼人能力的代价。背景通过当前行动进入。
- 同一个姐姐先照顾妹妹、再施加要求，亲情与权力的矛盾在场景中发生。
- 女主也曾依赖女儿牺牲，成长不只是指责外人；女儿有自己的愿望，不只是受害筹码。
- 首次回报可以是女儿保住离开的机会，同时女主失去药库支持。新问题随之产生：没有原来的保障，她如何继续行医？
- 若最终成稿只剩追责手续、轮班和协议，狼人机制仍未充分落实；应让身体能力、共鸣风险和群体归属在行动中改变可行办法，而不是补几处“狼”字。

同一走线可以由模型提出不同入口，作者选择的是主要阅读感受与切入方式：

| 入口示意 | 体验及优势 | 取舍 |
| --- | --- | --- |
| 代价落到女儿身上（本例推荐） | 同情与不平；尽快建立母女、姐妹及职业冲突 | 狼人救治需要具体余波，避免开成纯手续争论 |
| 从救助被驱逐者的关键时刻切入 | 紧张与能力感；先经历狼人机制，再面对追责 | 需迅速建立人物目标，防止陌生规则占满篇幅 |
| 从姐姐的照顾与条件切入 | 亲密与压迫同场，人物关系更突出 | 对白需承载行动，避免静态解释双方立场 |

这是替代入口，不是要求连续展示三次同一事件，也不是让作者逐句选对白。已有开篇方向明确时，模型直接完善，不重复征求一次批准。

## 5. 放进现有共创交互，不增加独立流程

地图改为 **故事方向 → 开篇与前段 → 中段 → 后段 → 结局**。全书初步路线提出时，就让作者看见“故事从哪一幕开始、会有什么感受”；允许开场与结尾共同设计。

在“故事全貌”的前段区域增加“开篇体验”卡：主要情绪 → 具体场景 → 人物选择 → 首次回报 → 接下来的期待。短场景预览按需展开，避免长文本挤掉当前决定。

若确有不同的重大阅读方向，复用“本轮决定”给出2–3张单选卡，保留推荐理由、取舍、自由补充、自定义与范围委托。每张卡用具体事件说明差异，不能只叫“更燃／更虐／更爽”。不把开篇体验另做必填问卷或每轮都必须通过的一道题。

模型自主完成细节、信息释放和场景衔接。改变主线事实、关键关系或主要代价时才回到重大决定。原始构想与已采用决定优先，不能为了更刺激偷偷增加出轨、隐藏子女、死亡、血统或超能力。

当全书走线收束，在同一轮检查“开篇承诺是否得到后续回应”；缺口由模型明确补齐建议或标未决，不追加常驻开篇评审调用。开篇入口与主要回报已有依据即可进入骨架，无需先把首章文风打磨到最终稿。

页面状态区分“开篇方案已定”和“正文待验证”。选择方案不能直接点亮“吸引力已通过”，更不能显示未经测量的留存率或保证。

## 6. 接入 M1、M2、M3 的方式

| 阶段 | 责任与交付 | 不应发生 |
| --- | --- | --- |
| M1 设计 | 在已有轮次内建立开篇场景、主要体验、题材因果、首章回报及长线连接，保存作者选择与版本 | 多开一条强制审批流程；用情绪词代替事件 |
| M2 正文 | 从已采用骨架与执行交接读取这些要求；在章节任务和既有编辑中检查实际场景、人物感知、行动与后果 | 只扩写摘要；Introduction有冲突但第一章仍是履历介绍 |
| M3 阅读评议 | 由用户显式启动，试读实际开篇正文，先记录困惑、投入与期待的位置，再给有原文依据的建议 | 把设计意图交给试读者让其复述；用模拟意见冒充真人反馈；新增自动阻断导出 |

复用现有骨架开篇段落及其合法字段、`opening_contract`、创作执行交接，不并列复制三套真相。实施时先核对规范化读取接口与已有合同；界面展示可用私有扩展，需绑定来源、版本与状态。已有商业合同的 `emotional_jobs` 有固定值域，“好笑／惊奇”等自由体验描述不得直接写成非法枚举；应保留于合法叙述或版本化私有展示字段，不能为迎合标签强行映射。

H5 分类、EPUB、publication package、ZIP/SHA 规则不随此设计改变；私有选择、草稿预览和评议元数据不泄漏进交付协议。正文当然可以体现作者选择的体验。

代码保证操作、版本、来源引用、必需结构与产物协议；模型和真实阅读验证叙事效果。文学评价不新增一个机械的“冲突分数达标”门。既有正文质量流程保持；有明确问题时在现有预算内局部改稿，不因一个形容词没匹配就重建骨架或自动无限重试。

## 7. 验收与多样性

工程验收：开篇卡来自所选版本；未采用入口不混入现行梗概；修改主要结局后相关开篇承诺标待协调；选择加补充仍是一轮调用；旧会话没有字段时不伪造“完成”；首章未写不显示正文验证通过；H5导出不变。

内容验收按证据回答：

1. 只读开头，不看设计说明，能否说清眼前发生什么、谁在意什么？
2. 在哪个具体动作、关系反差或发现处开始投入？如果没有，缺什么？
3. 所选题材是否实际改变事件、选择或后果？
4. 首章给了什么当下阅读价值，又留下什么具体期待？
5. 后续是否承接开篇承诺，还是迅速回到无关的流水账？

可以在同模型、同篇幅与相同原始约束下对照不同开场，采用未知版本的阅读反馈，记录“愿不愿继续及原因”，区分真人、模型试读与同模型自审。没有实际数据时，不宣称已提高留存。

至少以狼人、婚姻背叛、女性觉醒三类加一个轻喜剧情境检查适用性。三套内置资料提供设计工具与边界，不预置统一剧情：改变切入时点、人物欲望、关系权力、信息分布、规则代价与首个回报。不是每本狼人都被拒绝伴侣、每本婚姻都当场撞破、每本觉醒都被全家羞辱。相同情绪可以来自不同且自洽的故事。
