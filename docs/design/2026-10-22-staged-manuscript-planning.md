## 规划职责

1. 冻结完整采用骨架、作者限制、确认的叙事规格和商业合同。将作者已确定事实和允许补足的执行细节分开。
2. 由完整来源建立全局故事基线：人物与关系、因果主线、人物弧线、揭露顺序、伏笔与结局、全书章节功能。
3. 按有界章节批次补齐执行计划。每批使用同一个全局版本与来源，保留场景、主动选择、情绪、不可逆变化、伏笔、钩子及跨批衔接。正文仍顺序创作。
4. 将完整规划交给全局审查，发现问题后只修受影响内容并重新验证。局部修改不能静默改变已确认的全局事实。修复预算有上限；未解决问题保留成果并阻断。
5. 从同一份结构化内容在本地生成可读 Markdown，不要求模型再次抄写。结构化格式必须承载原有文字蓝图的叙事细节。
6. 只有完整结果通过既有解析和质量规则，才交给原 `foundation.commit` 与正文流水线。批次保存不代表正式稿获准。

确认过的叙事规格和商业合同由程序绑定，不要求模型重新抄写其中的评分字段。新规划必须保留适用的结局检查要求；缺少合同或检查输入不能被当作“不适用”。来源事实是否语义忠实仍需全局模型审查与真实作品验收，结构校验不作此保证。

## 执行控制

所有全书模型调用使用同一执行控制模块，覆盖 Architect、Scribe、Editor、Guardian、Style 及相应直接调用。

- 请求有可配置的绝对时限；阶段另有总预算。心跳和上游元数据不重置期限。
- 暂停绑定具体项目、run 和执行实例，防止旧页面停止新一轮。
- 收到暂停后显示“正在暂停”；调用及子进程退出、必要状态保存完成后才显示“已暂停”。
- 暂停、超时和未知远端结果不触发自动重复模型调用。临时错误和格式修复的重试规则分别定义。
- 迟到的事件或输出不得覆盖已结束或替换的执行实例。
- 持久诊断只保留白名单元数据，不包含密钥、完整请求、原始上游报文或私有思维。
- 模型选择和推理档位不因等待自动降级。

## 检查点与兼容

检查点必须绑定来源内容、确认合同、规划格式版本、模型公开配置和依赖产物的摘要值。完整且匹配的检查点可以复用；损坏、来源变更或依赖变更不能静默沿用。

旧任务记录不因加载新版本就被改为另一规划流程。新模式可配置；原运行模式随 run 保存。Workshop 的旧结构化产物只有证明它与最终采用骨架完全一致才允许复用，不能仅凭相同讨论 ID。

本次选择从完整采用骨架转换，不直接复用 Workshop 内部检查点，进度记录明确 `workshop_reuse.used=false`。新任务默认 `staged`，旧 manifest 缺少模式字段时继续解释为 `legacy`。尚未提交基础和正文的旧 outline 失败／暂停任务可显式选择升级；API 与执行锁内各验证一次，保留升级前 manifest 和旧回复。有故事角色、章节、线程、canon ledger 或 foundation/promotion 事务记录的项目不能走此快捷升级。不可变修订历史中已有正章节稿时，即使正文文件及 head 缺失，也不能升级；只有第 0 章启动合同允许。资格检查只读，损坏记录、孤立 blob 和符号链接均拒绝升级。

完整回复先保存，再进行结构校验；每个步骤最多一次格式更正。更正仍不合格，恢复会复验同一回复，不会继续付费重试。需明确修正来源、配置或相关候选后再处理。章节语义问题允许一次至多四章的定点修复和全书复审；全局来源冲突或超过该范围的问题保留成果并阻断。

保留候选、验证与正式提交的区别。保存中断后恢复应完成本地验证／发布，不重发已完成生成。已提交章节及正式故事状态不随规划功能升级重写。

## 实施接口与限制

- `core/outline_planning.py` 保存全局设计、四章批次、核查和有限更正；`core/orchestrator.py` 负责验证后发布。全局设计和批次详情属于候选，不直接改写 canon。
- 每批收到完整采用来源、共同全局设计／章节走向，以及前两章详细设计；依赖摘要绑定全部前序批次。最终核查看到整本候选。后续单章扩写读取 canonical 全局字段和当前／相邻章节完整详情，不再硬截大纲前 50,000 字符；其检查点同时绑定 `foundation.json`。
- `core/pipeline_runtime.py` 在实际调用时绑定期限、取消和诊断，覆盖已有缓存客户端。默认单次请求 900 秒、业务阶段 3600 秒，分别由 `NOVEL_OS_PIPELINE_REQUEST_TIMEOUT_SECONDS`、`NOVEL_OS_PIPELINE_STAGE_TIMEOUT_SECONDS` 配置。分批规划对各子步骤限时，不把所有长篇章节压在同一小时内。
- CLI `novel run --outline-planning-mode staged|legacy`；`novel resume --outline-planning-mode staged` 是显式安全升级，省略参数保留旧模式。
- `GET /api/projects/{project_id}/tasks/{run_id}` 返回 `progress`、`planning`、`stages` 与精确暂停／升级资格；暂停提交当前 `job_id`，恢复可选 `outline_planning_mode: staged`。刷新只读取状态。
- 诊断持久化到当前 run 的 `progress.json` 和 `requests.jsonl`，只含事件与计数。UI 分别展示在线信号、上游事件、真实内容活动和完整回复，阶段预览取已保存 logline／章节标题，不展示私有推理。
- 本地 CLI 暂停测试验证父子进程退出；HTTP 取消／期限只保证本地停止等待、忽略迟到结果并禁止后续调用，不能保证远端服务立即停止计算。
- 旧执行进程不能通过文件更新获得新进度和取消能力。生产仍有任务时不自动重启服务；本次已由用户明确授权暂停后部署，真实文学质量对照仍需后续完成。
