## 1. 目标与当前问题

新创作统一选择：**一个频道 + 一个 Genre + 一至两个 Tags**。频道决定本书的读者定位，Genre 提供核心阅读承诺，Tags 提供具体故事机制；三者共同进入故事设计与正文执行。

“男频／女频”是作者选择的商业读者定位，不直接等于主角性别、性向、叙事视角或结局。人物设定服从作者决定；不把男性读者全部归为升级打斗，也不把女性读者全部归为婚恋受辱。年龄、市场、语言等偏好仍单独保留。

实施前的只读核对发现（保留问题来源，以下不再表示当前源码行为）：

- 新讨论只有自由文本 `audience`，没有可靠的频道枚举。当前选择是 1 Genre + 1–20 Tags。
- Genre–Tag 关联贯穿文件头、启用、快照验证、页面筛选与删除保护，仅放开页面不够。
- 当前 1 个 Romance Genre 和 40 个 Tags 都含女性向／女主定位；不能批量标为两者通用。
- 自由 Markdown 目前整篇注入。若在末尾直接追加男频方法，模型仍会收到前面的女频要求，且输入继续增大。
- 动态分类生成未传入已有的 `audience_channel`，最终可能落到 `general`。需要连通发行链路，不能只改创建表单。

## 2. 创建交互

保持现有三步与统一面板风格，不增加新向导层级：

1. **故事与素材**：输入故事构想，选择原创／原故事推演／改编重写，导入资料。
2. **频道与题材**：必选男频或女频；选择一个 Genre；选择一至两个 Tags。
3. **篇幅与偏好**：篇幅、每章长度、正文语言、读者年龄／市场等原有设置。

第二步示意：

```text
频道       [ 女频 ] [ 男频 ]
Genre      [ 浪漫 ] [ 悬疑 ] ……       单选
Tags       搜索标签                   已选 1 / 2
           [ 复仇 ✓ ] [ 契约婚姻 ] [ 动作 ] ……

已选       女频 · 浪漫 · 复仇
```

### 选择行为

- 新建时明确选择频道，不按作者性别或旧任务自动猜；恢复草稿保留原选择。
- Genre 和 Tags 都按频道过滤：显示对应频道可用、已启用且方法完整的资料。
- **选择任何 Genre，都能看到该频道全部可用 Tags**。不再使用 `genre_ids` 过滤，不从正文组合建议生成隐藏白名单。
- 选满两个后其余 Tag 禁用，说明“最多选择两个，可先取消一项”；已选项仍可取消。没有 Genre 或 Tag 时不能开始，后端同样校验。
- 两个 Tags 不要求用户再分主次；模型在首轮说明它们如何共同推动一个故事。若回报互相冲突，通过原有方案选择让作者定方向，不自动丢弃标签。
- 切换 Genre 保留当前有效 Tags；需要重新确认后续设计，但不因过去的父子关联清空。
- 切换频道时先显示将失效的 Genre／Tags，使用系统统一弹窗确认后仅移除不兼容项，保留构想、资料及其他有效设置。
- 已开始讨论时变更频道属于基础设定变更：明确确认重新设计，保留历史讨论／骨架，不偷偷改写在途请求或已完成小说。

## 3. Genre 与 Tags 维护

继续使用现有“阅读预览／编写 Markdown／版本记录”，统一面板、现有字号与按钮，不再增加一套资料系统。

顶部维护信息：名称、Genre 或 Tag、**适用频道：女频／男频（可多选）**、启用状态。列表显示 `女频`、`男频` 或 `男频／女频` 徽标，并支持频道筛选。撤销 Genre 必填关联及其删除连带限制。

### 原文保护：仅追加频道指导

按用户最新限制，**现有 Genre／Tag 文件的文件头、正文、组合示例、措辞和顺序均不修改**。取消此前“提取、移动原文到通用／女频分区”的方案。实施时保存原文件字节与 SHA；追加前原字节必须完整保留，只有新增频道指导模块可发生变化。包括文件原有换行与编码，不借格式化修改原文。

维护页面仍可展示“原说明／女频指导／男频指导”，但原说明作为原样预览；本次自动变更范围只允许新增指导。已有通用编辑能力是否允许作者自行修改是另一件事，不等于本轮授权系统改写原文。

一个文件的结构变为：

````markdown
[现有文件完整保留，包括原文件头与所有正文]

<!-- novel-os:audience-guidance:start -->
## 频道写作指导

```yaml
schema: audience-guidance.v1
audience_channels: [female, male]
original_sha256: <原文件UTF-8字节的SHA-256>
original_bytes: <原文件UTF-8字节数>
```

### 女频写作指导
本标签在女频故事中的代入、人物目标、冲突方法、阶段回报与表达建议。

### 男频写作指导
本标签在男频故事中的代入、人物目标、冲突方法、阶段回报与表达建议。
明确如何适用原说明中的女性向默认要求；不靠替换人物称谓冒充适配。
<!-- novel-os:audience-guidance:end -->
````

此处是模块结构示意，尖括号占位符不可直接导入。页面的“适用频道与写作指导”弹窗自动生成枚举、原文收据和唯一模块标记；分区正文为自由 Markdown，用户不用手写 YAML。关闭某频道会保留其指导文字，但该指导不注入所选另一频道。页面沿用阅读预览／编写 Markdown／版本记录，保存新增版本，历史与删除状态不覆盖。

### 精确识别与校验

- 资料的**适用频道**从新增模块的 `audience_channels` 枚举读取，可为一个或两个频道；不能搜索正文中“男／女／女主”等词猜测。
- 本书的**选定频道**来自头脑风暴必选控件，只能是 `male` 或 `female`；代码冻结并传递，模型不能自行更换。
- 新增模块缺失／重复／不完整、未知枚举，或声明频道没有对应指导正文时，明确提示未完成；不默认为通用，也不静默选女频。
- 模块标记只在约定的顶层位置解析；正文代码示例／引用中的同名标题不能被当作元数据。不执行 Markdown 中的工具指令。
- `genre_ids` 可作为原文件历史信息保留不动；新创作选择规则不再把它作为必填或外键，不依靠删除原文解除关联。新建文件不再要求该字段。

### 原文已有女频要求如何处理

原有40个Tag及Romance均含女性向要求。**原文保存不动，不表示其每句话在男频小说中仍是同等优先的指令。** 新增男频模块必须具体说明该标签如何适配男频，编译器为原说明和频道指导标明用途与优先级：作者明确设定与本书频道在前，新增频道指导负责解释频道差异，原说明中的核心题材承诺仍保留。

例如，选择男频不能让Romance变成纯事业升级；原说明中的女主默认称谓也不能覆盖作者已确认的男性主角。男频不强制男主，仍服从作者的人物、性向、视角与来源事实。

如果原文与新增指导存在不能合理化解的实质冲突，先不启用该资料的男频适用范围并说明原因，不能以补一段“忽略原规则”伪装成高质量适配。模型对语义优先级的遵循仍需要对照样本验证，不能承诺只追加字段就绝对有效。

### 导入与补充

- 普通MD导入先完整保存，缺频道声明时让作者选择并补指导；不移动原文，不由模型猜频道。
- 当前41份资料按实际内容先补女频声明与方法；适合男频的资料逐份追加对应方法，通过审阅后再启用男频。
- 男频入口正式发布前至少完成一个可用Genre与配套Tags，不发布空列表。
- 推荐组合仍留在原文，只作创作建议，不成为启用、删除或选择的外键。

## 4. 模型如何真正执行

### 一次编译、全程使用

本书有效指导为：

```text
作者构想／已确认事实与偏好
＋本书频道
＋所选 Genre 的原说明与新增的本书频道指导
＋1–2 个 Tags 的原说明与新增的本书频道指导
＋本阶段原有产物协议
```

新增模块中另一个频道的指导不发送；原说明完整保留，不能声称其中原有的女性向措辞也被删除。通过明确用途和优先级应用原说明。Genre承担总体读者承诺，新增Tags指导只写独有频道差异，避免重复整套公共要求。第一轮将组合落成具体人物与剧情，不再输出冗长标签解释报告。

不新增男频 Agent／女频 Agent；原有文本模型、头脑风暴、骨架和正文链路复用同一编译结果。作者指定与已确认故事事实优先，资料是创作指导，不得覆盖代码协议、偷偷执行指令或擅改来源年龄／身份。

### 以故事产物体现，而非以“已遵循”声明体现

首轮方案仍用用户认可的格式：**叙事视角、核心剧情、看点／爽点、伏笔、章末钩子**。开头简短说明本书的代入人物、主要情绪承诺以及两标签如何结合即可。

落地重点：

| 产物 | 需要看到什么 |
|---|---|
| 开篇 | 具体事件让读者立即关心主角的处境与欲望；不靠贴频道标签 |
| 主角 | 有明确目标、可行动的能力、软肋和选择；性别／身份服从作者 |
| 中段 | 标签改变困难的形式与主角解决问题的方法，阶段回报累计、不归零 |
| 高潮与结局 | 兑现本书承诺的成就、关系、尊严或情绪回报，代价与前面选择相称 |
| 正文 | 视角、对话、场景信息和节奏服务本书读者体验；人物仍有独立性 |
| Synopsis、书名、封面 | 呈现同一本书的频道与情绪承诺，不额外编造身份或结局 |

同为 Romance + Revenge + Contract Marriage，可以设计截然不同的代入与关系阻力，但**Romance 的核心亲密关系仍必须支撑主线**。选择男频不能把它改成纯事业复仇后在结尾发放伴侣。

频道指导是可选择、可发展的叙事方法，不能变成性别定律。也不强制“每章都有反转”“固定前十章节拍”“女频必受辱”“男频必升级”。

### 验证与效率

- 代码确定性保证：频道枚举、1 Genre、1–2 Tags、频道兼容、启用状态、资料版本/hash、正确分区、快照一致、发行字段一致。
- 将“所选标签是否改变主线”“回报是否与本书频道承诺一致”接入现有设计核查，不增加新的逐章全文评议或无上限循环修正。
- 语义效果验收使用少量同构想对照样本审阅设计及开篇；比较主角行动、冲突发展、情绪回馈、标签组合和故事差异。该项尚未执行，代码校验不能保证读者一定喜欢。
- 1–2 Tags控制资料规模，只投影新增模块中的本书频道指导。原文不裁剪，追加方法会增加单份资料大小，不能承诺总输入或模型思考时间一定减少。保留原有整体容量预检。

### 组合建议：能被读到，不等于全部被执行

现状核对：自由 Markdown 的完整正文会进入选中资料的编译结果，组合章节也在其中；正文执行会冻结并使用对应阶段指导。编译器只遍历快照中的已选文件，不会因 A 的正文提到 B 就自动加载 B 的完整说明书，也不会自动增加公开标签。现有提案中的 `genre_roles` 和机制说明属于设计自述，不能证明最终正文已经兑现。

依据：`core/creative_types.py` 的 `compile_snapshot`、`core/creative_execution.py` 的冻结／阶段指导投影、`api/workshop_design.py` 的设计机制结构。

已在 `knowledge-compiler.v5` 的解释合同中实现以下规则，**不改原文件组合段落**：

- A、B 都被作者选中：优先借鉴两份说明中的组合方法，把作用落实到同一组人物选择、冲突和后果；建议不是固定剧情或强制章序。
- 只选择 A，原文推荐 A+B：B 是条件性参考，不能当作作者已经选择的第三标签，不自动加载或扩大本书的创作承诺。普通场景自然包含某类元素，不等于正式使用该 Tag。
- 若模型判断加入 B 会实质改变故事，应在头脑风暴给出选择建议；作者确认替换／补选后再更新快照，始终遵守一至两个 Tags。不能偷偷执行未确认的类型变更。
- 两份组合建议冲突时，遵守本书频道、Genre 核心承诺、作者确认的故事与来源事实；把真正影响大方向的分歧交给作者，不让用户处理细节仲裁。

### 骨架设计前展示标签组合方案，由作者选择

用户最新决定：标签贡献首先用于**设计决策**，不是等全文完成才提供事后说明。作者选定频道、Genre、Tags并输入构想后，在现有头脑风暴首轮提出2–3个有实质差别的整体故事走向，说明标签如何产生剧情、情绪和回报，再由作者选择。所有方案都使用同一组已选标签与作者事实；不能用某个方案偷偷替换标签或删掉其中一个。已有讨论只在未决的大方向上提出分支，不重新推翻已采用方案。

每个方案直接展示：

- 一句话故事走向，以及足以判断的具体事件、人物选择和代价。
- 所选每个Tag在本方案中的作用，各用一句具体剧情说明；说明两者如何相互影响，不堆写作术语。
- 主要看点／情绪回报、与另一个方案的实质区别。系统推荐其中一个并简短说明原因。
- 需要展开时沿用已认可的叙事视角、核心剧情、看点／爽点、伏笔、钩子格式，不同时生成三份完整骨架。

选择UI复用现有本轮决定卡片，整体方案单选；可以补充开放想法，也可以选择“都不采用，重新设计”。点击“采用方案并继续”时将方案ID、当前修订和用户补充一起提交，保存可见的决定记录，再继续推演。无选择不得被默认为接受推荐；重新设计是明确决定，不是跳过。作者提出混合思路时先整理成自洽方案供确认，不把互斥分支直接拼接。

用户只决定主线、关键关系、核心回报等大方向，不逐Tag、逐场景审批。后续阶段沿用故事进度、待定事项和已确认组合，只对重大分歧提供选项；主线成熟时提示可生成骨架。采用方案及作者补充进入后续骨架请求和正文交接。当前不新增一个强制的骨架分节，也不声称已由代码证明某标签对应的剧情节点兑现；具体故事作用仍需审阅产物。

这些字段复用同一次头脑风暴回复，不增加专门的“标签分析”模型调用。提案新增 `tag_contributions`、`choice`、`cost`、`payoff`；代码拒绝未知／重复标签，并从冻结资料读取显示名称。缺少所选标签的贡献或选择／代价／回报时，记录 `combination_status=partial` 和缺失项，页面显示“组合说明待补全”；保留有用回复，不额外付费重试，不仅因此阻断正文或交付。`complete` 只表示字段齐全，不代表故事精彩或文学兑现。

### 完成后保留创作依据，作为辅助回看

前置方案与作者决定是主要交互，最终说明仅回顾已确认设计如何落到正文。不能把“作者选了 Tag”或“模型说已使用”直接叫作文学质量验收。建议建立轻量贡献记录，分清四类信息：

| 层级 | 记录什么 | 可证明的范围 |
|---|---|---|
| 作者选择 | Genre、Tags、本书频道 | 书的创作目标与发行选择 |
| 指导注入 | 实际请求使用的文件版本、SHA、阶段 | 指导进入了模型输入，不等于模型遵循 |
| 骨架采用 | 本书采用的具体机制、关联人物和剧情节点 | 已确认设计如何落实标签 |
| 正文体现 | 对应章节／场景及短引文、正文版本 | 有可复核的文本依据，不等于读者必然满意 |

当前已实现前三层的冻结输入与历史采用记录：`GET /api/projects/{id}/creative-basis` 返回频道、资料版本／SHA、所选任务、交接和执行锁、历史已选方案；`/creative-basis/markdown` 提供独立作者说明下载。只读校验当前任务及其骨架绑定，不回退另一轮创作、不读取当前库替换旧资料。历史方案明确标为可能被后来自由文本修订的设计依据。

作品详情的故事页已集成可展开的“创作依据”，展示频道、冻结资料和历史已选设计，支持下载说明。**正文体现层尚无绑定定稿版本与逐字引用的自动提取链路**，返回空 `prose_evidence` 并明确“已规划／正文体现待确认”；没有宣称已检查每章、没有编造达标比例。保留后续证据扩展点，不新增逐章阅读、全书回读、独立模型调用或自动修正。公开 Tags 不因模型自述被自动增删。

### 作者补充优先：三条创作链路使用共同规则

头脑风暴、封面设计／精修、书名生成共用 `author-requirements.v1`：保存原文、顺序、来源、文本 SHA 与整体 SHA；最新明确修正优先，兼容旧要求保留，每个正式候选均应响应。仅显式 `supersedes` 引用改变台账状态，不用关键词或模型猜测自动撤销历史决定。完全相同的重复原文可引用共享，仍保留其时间顺序；不同原文不语义裁剪。

头脑风暴仍保存历史 accepted/revised 卡片，但明确标注“历史采用，不覆盖后来的自由文本修正”；不会伪称已确定性识别所有语义冲突并把旧卡片改为失效。新 story-first 正文交接 `creative-handoff.v4` 携带作者消息台账；旧运行锁与已冻结 v1–v3 handoff 不重写。原文中的问题、替代想法和阶段指令不等于全部被采纳，执行上下文明确要求结合最后采用的骨架解释。

封面重新设计累计历史偏好（缺字段沿用，显式空字段清除），精修链保留此前要求，明确最新站位修改可覆盖旧构图保持项；重试保留冻结输入。精修文本前后端统一为5000字符。命名仍只修改书名，保存历轮要求及定向起点；不可变的候选数量／长度和故事事实冲突由 `request_conflicts` 明确返回，不当作普通格式错误无限重试。

封面频道从经过校验的冻结选择传入方案、最终图片与原图精修提示，不依赖原说明中的称谓猜测。最终相关回归验证该传递链；没有额外生成图片来声称视觉效果已经达标。

命名还对**最新一条要求中明确加引号的保留／禁止词指令**执行确定性检查，逐个验证五个候选，不从任意文字猜禁词。旧兼容要求继续原样传入，但不因无法理解的后续自由文本撤销而强制沿用旧字面规则。上述工程绑定不等于语义遵循证明：不自动验证所有自由文本要求、情绪或视觉改动，也没有额外付费验证模型。详见[原始审查与实施追记](../reports/2026-11-08-author-revision-priority-audit.md)。

## 5. 统一数据与实现范围

已实现的新建接口提交形状（`source_sha256` 为实际已选版本散列）：

```json
{
  "creation_flow": "genre_tags.v2",
  "audience_channel": "female",
  "creative_types": [
    {"id": "genre.romance", "version": 2, "source_sha256": "..."},
    {"id": "tag.revenge", "version": 6, "source_sha256": "..."}
  ]
}
```

存储合同是 `selection-snapshot.v2`：包含 `audience_channel`、`genre_id`、`tag_ids`、完整版本 `documents`、公开 `publication_taxonomy`、`parent_sha256`、`snapshot_sha256`，编译器为 `knowledge-compiler.v5`。阶段输出仍为 `genre-context.v2`，每份资料的 `format=audience-markdown.v1`，解释合同为 `generative-guidance.v3`。原文文件头保留在快照；模型输入使用其完整正文与所选频道指导，并记录原文件、正文与指导的独立 SHA。另一频道新增指导不发送。

维护摘要提供 `audience_channels`、`audience_ready`、`audience_issue`；详情 `document.audience_guidance` 返回模块及原文收据。`POST /api/creative-types/{id}/audience` 接收 `revision`、`operation_id`、`audience_channels`、`guides`、`activate`；只更新模块，沿用版本、幂等和修订并发检查。保存草稿与启用分开；专用弹窗默认保存并启用，已有正文草稿会明确提示一同启用。

网页、接口、CLI 冻结文件入口共用快照校验。旧 v1 快照仍按原编译器读，原多标签选择、上下文摘要及运行锁保留。旧讨论修改题材／更新版本前须在基础设定明确选择频道并升级，不能通过类型更新 API 绕过。用户仅恢复历史讨论不强制迁移；正在运行的快照不随资料库变化。CLI 可读取旧快照或完整新 v2 快照，新 v2 骨架必须与频道及 taxonomy 一致。

已落实的职责边界：

- `audience_guidance`：独立负责标记模块严格解析、写入和原字节收据；`knowledge_markdown` 负责正文编辑视图与模块保留，不重新序列化原文件头来追加指导。
- `creative_types`：以现有统一快照接口校验、冻结和按频道／阶段编译；存储继续负责版本、幂等、删除。新协议删除 Genre 关联校验，旧 v1 编译规则仅为读历史快照保留。
- `workshop`、`knowledge_intake`、`creative_execution`：传递和使用同一冻结选择，保持现有恢复、快照和阶段协议。
- 前端选择器／资料维护：只消费统一摘要与校验结果，不从 MD 正文猜频道。
- 公开分类构造：由代码绑定作者频道和 Genre／Tags，不让模型改发行元数据。

移除新协议里的 `genre_ids` 必填、Genre归属检查、启用关系检查、换Genre删Tag、删除Genre连带阻断。旧文件解析仅用于历史读取和明确迁移；用户不再维护这个关系。

取消 Genre 范围后，**稳定 ID 是唯一身份**；当前实现对同一 kind 的启用资料全局检查规范化名称／别名冲突，不再按 Genre 分隔，不按名字合并资料或覆盖第一条。发生冲突需作者明确处理身份或别名；这与支持任意重名匹配的候选设计不同。

文档版本（内容）、编译器版本（解释规则）、公开分类版本（发行协议）各自独立，避免改一段写法就不必要地升级 H5 协议。

## 6. H5 与交付

本书频道通过骨架和 publication package 写入既有 `classification.audience.channel`（`male`／`female`）。旧作品 `general` 保留；新创建的这两个入口必须明确频道。频道不是新增一个 Tag，不占两个 Tag 名额。

继续遵守 Manifest V4、`novel-h5-import.v1`、`ready`、EPUB 正文、PNG/JPEG封面、Introduction限制、包大小和 SHA 规则；所有相关分类与哈希由代码同步生成。

H5 已有频道枚举不代表支持所有动态 Genre／Tags。仍需沿用此前动态分类交接方案，拿实际校验器验收，不能通过更改版本字符串伪装兼容。私有写作方法不进入公开分类。两标签上限是新创作约束，历史发行包不因此追溯失效。

### 精确频道与后台交接

唯一事实来源是本书冻结的作者选择。代码将其写入分类 sidecar、EPUB 内嵌分类与 publication package，并同步关联 SHA；模型回复或 MD 中的性别词不参与最终频道判定。例如分类对象为 `{"audience":{"channel":"female"}}`。新建入口与 v2 骨架绑定拒绝缺失频道，导出预检拒绝各产物分类不一致，不能默认 `general` 掩盖遗漏；旧书保留原值，不靠人物性别推断迁移。

已交付 [H5 频道适配手册](../h5-audience-channel-handoff.md)，结合现行导入规范和动态分类手册，包含：

1. 实际 ZIP 路径及 Manifest 定位方式、`classification.audience.channel` 字段、`male/female/general` 枚举与历史缺失值策略。
2. H5 入库、男／女频展示和筛选、动态 Genre／Tags 展示；频道是独立字段，不从 Tag 名称猜测。
3. EPUB／分类文件／publication package 一致性与 SHA 校验；重新导入和分类更新行为。
4. 男频、女频、历史 general 的有效样包，以及未知频道、分类不一致和哈希错误的拒绝样包；新建缺失频道由独立输入校验 JSON 证据覆盖，不生成违规 ZIP。明确本地结果与尚待 H5 联调的边界。

### 作者说明与 H5 ZIP 的边界

当前引擎 `core/h5_acceptance.py` 对公开路径／角色有白名单。标签贡献说明先在作品完成页展示并独立下载，**不直接向 H5 导入 ZIP 添加未定义的报告文件**。ZIP 仍携带作者确认的公共分类与精确频道，不包含私有 MD、完整提示词或讨论记录。若以后要求贡献报告随 ZIP 一同导入，需要正式扩展版本化协议并同时修改、验证双端校验器，不能默认接受。
