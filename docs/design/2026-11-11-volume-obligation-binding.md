# 分卷计划义务的统一绑定

## 问题与边界

长篇审计在每五章及卷尾检查 `ChapterContract.world_event_ids`。分卷 ID 和到期章由 `validate_volume_contracts` 生成，普通 Architect 提示要求模型抄回 ID；story-first 则直接投影细纲，细纲协议没有要求这些 ID。两条合法生产路径因此产出不同合同，直到第 5 章才暴露。原有短篇端到端用例和手工填好 ID 的长篇测试没有覆盖两条路径的交点。

这项检查只读取计划合同，不读取正文。ID 存在从来不是剧情兑现证据，缺 ID 也不足以证明小说遗漏情节。前五章真实审稿已经收到同一冻结基础方案的完整分卷设计。此次修复不修改冻结规划协议、已发提示或原文，不为内部编号增加模型调用。

## 共同的计划投影

`volume_obligations.bind_planned_volume_obligations` 是纯函数。输入为有效章节合同、锁定篇幅格式及完整且严格验证的分卷合同，输出为派生合同及来源回执。它只合并本章到期的程序生成 ID，保留其他字段和已有 ID；缺失或伪造分卷不能用默认卷补足。短篇不添加长篇义务。

回执分别记录原合同、派生合同、分卷来源哈希、章节、原 ID、增加的 ID 和到期义务，并明确 `planned_not_observed`。开卷 promise 表示建立读者期待，不表示提前完成整卷 payoff。

新 story-first 章节的本地投影使用同一函数，并给写作角色展示完整当前卷及本章义务。完整场景不删减，foundation 不修改，无需额外 Architect 调用。普通规划保留既有完整分卷提示；共同审计同样适用于普通规划模型漏写内部 ID 的情况。

## 历史任务恢复

长篇审计读取并验证原 Artifact 内容及章节归属，使用共同函数生成有效计划视图，在报告中记录原 revision ID/SHA 和派生回执。它不替换 Artifact head，不修改已批准正文、canon、晋级回执或规划检查点。已有晋级章节继续通过原生恢复路径复用。

报告升级为 `long-form-quality.v2`，标明 `assessment_scope=plan_integrity`、`semantic_delivery=not_assessed`。缺失/损坏/错章合同、既有结构重复及卷尾缺 Final 检查仍阻断。旧报告在被新报告替换前按原字节 SHA 存入 `outputs/quality/long-form/history/`，可追溯技术阻断的解除原因。

文学判断继续由携带完整分卷设计、当前细纲及正文的既有联合审稿负责。该流程并不构成每个里程碑都有独立兑现证据的保证，也不能由本次工程测试推断读者体验或全书质量。

## 验证

回归先复现原始错误，再覆盖 60/100 章 story-first 投影至首次长篇审计；旧空 ID 合同自动派生且文件不变；所有卷首、中点、高潮、卷尾及同章多个义务；重复调用幂等；短篇与错误卷/错章/损坏合同；旧报告原字节归档。真实项目只在隔离副本演练，生产部署前备份并校验全部作品数据。
