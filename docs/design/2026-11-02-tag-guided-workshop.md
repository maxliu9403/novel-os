# 标签驱动的故事共创：前后端重设计

日期：2026-11-02。状态：设计与独立 HTML 原型，待审核；未接入生产、未部署。

本方案取代本日早些时候的五层选择与组合方案提案。作者明确要求：先输入构想，再依次选择主类型、故事背景、故事类型、情绪与风格；四组均必填。维护对象只有标签的创作说明，不维护“组合方案”。

## 1. 产品路径

**故事构想 → 主类型 → 故事背景 → 故事类型 → 情绪与风格 → 开始讨论**。

输入和选择阶段不调用模型。提交后，后端一次校验、冻结选择及说明版本，装配首轮请求。模型基于整个组合提出不同的总体故事方案，作者选择或补充，继续现有头脑风暴。不能自动生成骨架，不能绕过作者的重大决定。

| 步骤 | 操作 | 约束与下一步 |
| --- | --- | --- |
| 故事构想 | 填写想写的人物、处境或情节；书名可选 | 非空，空白不计；不要求作者先写完整大纲 |
| 主类型 | 选择至少一个类型；首选默认主类型，可改 | 1 个主分类、最多 2 个辅助分类，全部参与创作 |
| 故事背景 | 多选背景 | 1–2 个 |
| 故事类型 | 多选故事承诺 | 1–3 个 |
| 情绪与风格 | 多选阅读体验 | 1–3 个 |

上限来自当前 H5 字典，不是新增的创作质量规则。四组的最小数量是本次新流程要求；不要反向改变历史会话的有效性。多背景、多情绪不代表每个场景同时呈现，应在首轮设计中说明其作用范围和变化关系。

不能跳过未完成步骤；可以回到已完成步骤修改。最后一页直接显示简短汇总和“开始讨论”，不再加一页解释性确认。已有讨论中的设定修改先保存草稿，再明确确认开启新一轮设计；旧决定归档，不混入新方案，已开始正文的冻结版本不变。

## 2. 分类身份与标签含义

四组直接引用 H5 `novel-types.2026-10` 的轴：`primary_genres`、`settings`、`story_types`、`tones`。固定 ID、所属轴、显示名称来自同一分类字典，浏览器或模型都不能另造 ID。

“家庭背叛”是现行 `domestic_betrayal` 的显示名；“婚姻背叛、婚后出轨”可作为搜索别名与创作说明内容，不能悄悄替换公共分类名称。“第二次机会”是 `second_chance`，同属故事类型，二者可以组合。主类型中的“情感现实主义”与情绪轴的同名项不同，必须使用轴与 ID 联合标识，不能仅按中文名称查找。

一个标签在当前工作区拥有一份启用的 Markdown 说明，可有草稿和历史版本。它定义选中这个标签后，故事必须提供哪些阅读价值、可以如何变化、怎样与其他标签交互。启用说明必须完整；缺失说明不能悄悄退回通用一句话后声称支持该标签。

维护页列出整个字典。没有说明的标签显示“待编写”，从标准模板开始；新建小说中仅启用的标签可选，未配置项不默认勾选。正式发布这条新流程之前，应完成计划开放范围的说明与验收，并明确尚未开放的标签，不能用薄模板假装全量覆盖。原型只准备少量完整示例，其他项展示待编写状态。

删除删除的是工作区创作说明，不是 H5 标准标签；旧书仍保有冻结副本。新增 H5 标签必须走双方字典升级，不允许在此页随意增加公共发行分类。自由故事细节可以写在构想和补充意见中，不要求先变成新标签。

## 3. 前端设计

沿用作品库白色单面板、浅蓝紫背景、深蓝文字及现有字体，不改变视觉体系。

### 3.1 新建头脑风暴

- 同一面板内五步，每屏只处理一件事；桌面顶部步骤导航，手机显示当前步骤。
- 构想页大输入区、可选书名；后续以可多选卡片呈现标签，卡片只保留名称和一句具体作用。
- 顶部显示“主类型 · 至少选 1 项”等短提示；底部显示已选项和上一步/下一步。
- 启用说明缺失、数量超过上限、字典明确互斥即时定位，不能到模型调用后才失败。
- 主类型选多项时以“主”徽标显示唯一主分类，提供明确切换按钮；主分类影响份量，辅助类型也必须兑现。
- 最后一步显示折叠式“本次选择”，默认简洁，不常驻术语解释、模型 JSON 或提示词全文。
- 所有输入保存为服务端草稿；刷新/返回恢复当前步骤。仅点击“开始讨论”创建模型任务。

### 3.2 创作元素维护

只保留一个工作面：左侧标签列表与四组筛选，右侧 Markdown 编辑器。

右侧标题显示标准标签、启用/草稿状态、当前版本；正文“编辑 / 预览”切换。操作为下载标准模板、导入 Markdown、保存并启用、停用和删除说明。高级详情折叠展示真实编译预览与版本记录，普通作者不需要填写几十个表单。

保存按钮仅在内容变化后出现；保存并启用执行结构校验，通过后显示保存成功弹窗。失败时保留全文与光标，按行定位缺项。新手通过模板内占位提示完成六个正文段落；这些占位提示不能作为正式内容启用。

新建讨论与维护页面引用同一启用库。切换页面不能丢失维护草稿，也不能用未保存的编辑内容开始真实讨论。保存新版本只影响新讨论，当前讨论显示自己的冻结版本。

### 3.3 讨论页

沿用已确定的重大决定、故事全貌与收束机制。首轮输出 2–3 个总体路线，各含开篇处境、核心冲突、推进变化、结局方向与取舍；默认只展示易读摘要，详情可展开。

首轮必须综合全部选择：例如“浪漫＋家庭生活＋家庭背叛＋第二次机会＋虐心”，应提出不同的背叛情境、发现方式、重新建立信任的行动和代价，全部保留最终重建这段关系的方向，而不是把离婚换新伴侣当其中一个普通候选。

作者单选路线，可附开放意见，也可要求重新提案；问题澄清不自动等于采用。模型负责日常细节，作者主要决定总体走向。每轮更新已定故事概要、当前设计部位与未决大问题；满足整体覆盖后建议生成骨架，仍由作者启动，不固定轮数。

## 4. Markdown 说明标准

借鉴 Skills 的“有身份、按需加载、可版本化文档”，用于小说创作知识，不作为能运行命令、打开任意文件或取得工具权限的 Agent Skill。

一个标签一个文件。元数据短而稳定；说明正文是作者主要维护对象。

```yaml
---
schema: novel-creative-element.v1
catalog_version: novel-types.2026-10
axis: story_types
tag_id: second_chance
commitments:
  earned_reunion: 原本破裂的主角关系最终重新开始，信任恢复必须由持续行动和关键选择赢得。
---
```

正文固定六节：

1. `## 读者期待`：读者为何选择这类故事，期待什么感受和回报。
2. `## 故事作用`：这个标签如何改变目标、冲突、行动、后果或表达。
3. `## 发散方向`：几个可选变量和不同路径；明确是候选，不能全部写进小说。
4. `## 组合规则`：如何与其他类型融合；冲突时哪些需作者决定，哪些可按时间/人物/场景分配。
5. `## 分阶段指导`：四个固定子节——头脑风暴、骨架、正文、评议。
6. `## 避免套路`：常见失败方式及更有故事性的替代方向。

`commitments` 为少量稳定 ID 对应的作者可读承诺，至少一条，建议 1–4 条；不是几十分项的评分表。ID 在版本更新中保持稳定，删改时产生新版本并保留旧记录。文本内容不自动变成正则规则，不能凭“字段存在”认定小说已做到。

结局承诺与发散选项必须分开：“最终给原关系第二次机会”是选中后应兑现的承诺；“孕期出轨、功成名就后的背叛、旧情复燃”是可选发散，未采用前不是事实。不靠标签出现频次判定遵循。

标准样例和空白模板见 `creative-element-markdown/`。版本号、修改时间、启用状态和 SHA 由存储层生成，不相信文件自己填写的“已审核”状态。

## 5. 按需加载与组合编译

### 5.1 数据结构

- `TagIdentity`：catalog_version + axis + tag_id，唯一身份。
- `ElementRevision`：身份、原始 Markdown、解析结果、原文 SHA、规范化内容 SHA、修订号；已启用版本不可原地修改。
- `CreationSelection`：构想、四组所选身份、唯一主分类及其他作者要求；无需保存可复用“组合方案”。
- `SelectionSnapshot`：这次讨论实际使用的完整文档副本与版本/SHA、分类字典版本、编译器版本。
- `BookDesignBinding`：每个已选标签及承诺，在本书中的解释、作用、提案/采用状态、骨架节点与正文证据；复用现有设计台账，不另起事实源。

建议存储为工作区隔离的元素目录、不可变修订及小型索引。直接编辑磁盘文件视为待导入草稿；不让文件监控自动改变启用版本。删除记录保留 tombstone 和历史快照，不按文件名复用旧身份。

### 5.2 确定性流程

```text
作者构想 + 四组标签
  → 校验四组非空、身份/数量/互斥、每项启用说明
  → 在同一事务/锁中取得指定修订并冻结全部原文
  → 解析六节与承诺，选择当前阶段内容
  → 构造请求、校验预算、保存实际请求摘要与哈希
  → 一次现有头脑风暴调用：联合提出不同总体方案
  → 作者采用 → 骨架/章节/正文继续使用相同冻结要求
```

不为每个标签分别调用模型，不按排列组合维护提示词，不把整个资料库发送给模型。逐标签文档读取并不等于逐标签推理。

编译器按类别、选择顺序稳定装配：系统通用创作方法和当前阶段任务；作者构想与明确要求；分类与所选标签；选中元素的承诺、公共说明和本阶段指导；已采用设计/待定事项；本轮用户意见。创作资料作为有边界的参考数据，不允许覆盖系统指令、发行协议、工具权限或作者决定。

默认完整保留当前阶段相关内容。`读者期待`、`故事作用`、`组合规则`、`避免套路`及全部承诺是公共部分；`发散方向`用于讨论和未定规划，已采用后以当前设计优先，不能重新打开已定故事；`分阶段指导`投影当前子节。未传递部分保留在冻结原文中，记录投影路径；不得假称模型读取了完整全文。

模型输入预算在调用前按实际编码字节和可获得的 token 估计核验，给出按元素分列占用。保存说明时提示长度，整次提交时再核对组合与完整作者上下文；超过预算保留草稿并定位材料，不截断承诺、原文事实或历史决定，不反复重试同一个超限请求。具体上限按当前模型传输能力配置，不复制此前封面的固定数字。

### 5.3 如何让模型理解组合

统一任务要求模型形成一个相互作用的故事，而不是每个标签一条独立支线。首轮在同一回复中交付：

- 总体方案 2–3 个：不同的冲突起点、发现机制、人物选择、对手应对与结局路径；不能只换名字职业。
- 每个选择的作用：主类型组织阅读承诺；背景影响资源/空间/关系；故事类型进入冲突与回报；情绪与风格形成阅读过程和叙述方式。
- 本轮重大决定与真正冲突。逐项对应可供调试或按需查看，不必全部挤在正文 UI。

一份通用编译/融合协议服务所有标签。狼人不能由程序硬编码桥段；用户新写的合法元素说明同样进入上述链路。示例说明是可维护资料，不是应用逻辑特判。

## 6. 处理冲突与保障作者意图

按三种情况处理，避免重演封面系统的过度语义阻断。

| 情况 | 处理 |
| --- | --- |
| 分类字典明确不允许 | 提交前阻断并定位；如 sweet_romance 与 dark_romance 互斥 |
| 可以协调的艺术差异 | 同轮提出组织方式；如虐心转甜蜜、都市与家庭交织；不自动删标签 |
| 作者要求与核心承诺冲突 | 首轮只提出需要决定的冲突和可选处理，不擅自覆盖；如明确永不复合却选择第二次机会 |

不能简单规定“作者要求优先，所以偷偷忽略第二次机会”。应明确变更哪一项，获得作者决定后更新版本化本书要求。若“第二次机会”的关系对象不清楚，首轮以主要关系为候选并让作者决定，不逐个询问所有配角关系。

对“家庭背叛”来说，婚姻出轨是重要发散方向之一，也可有其他亲属的信任背叛；用户明确写婚姻出轨时，不能改成无关亲属谋利。“第二次机会”的标准示例明确指向已破裂主角关系的重建，不能以个人重新生活偷换该承诺。以后可修改说明定义，但只影响明确采用的新版本。

## 7. 进入骨架与正文

复用现有 `creative_execution` 冻结交接、骨架与章节规划、读者投入方法及 M3 评议：

- 讨论阶段：方案具体体现全部所选标签，每轮保持已采用承诺和当前梗概。
- 骨架阶段：将承诺落实到开篇、转折、关系发展和结局节点；背景有具体场景条件；风格有视角、语言、节奏要求。
- 正文阶段：当前章节上下文带入全书关键承诺和本章相关说明；不要求每章把所有标签重复一遍。说明的阅读价值应通过行动、对白、环境、情绪和余波实现。
- 评议阶段：引用实际文本检查是否兑现，区分缺失、矛盾、艺术解释与建议，不把模型分数当质量保证。

工程代码保证完整传递、绑定版本、定位证据、输出协议。内容质量通过实际设计与阅读验证。新增承诺不转成无限自动检查/修复循环；普通艺术建议保持 advisory。核心冲突列为明确待处理，不用模型自报“通过”替作者决策。

## 8. API 与工程边界（拟议）

| 接口 | 职责 |
| --- | --- |
| GET /api/creative-elements | 按四组返回字典标签与工作区说明状态 |
| GET /api/creative-elements/{axis}/{tag_id} | 草稿、启用修订及版本信息 |
| PUT /api/creative-elements/{axis}/{tag_id}/draft | revision + operation_id + markdown，乐观并发保存 |
| POST …/activate | 结构校验并发布不可变版本，返回新 SHA |
| POST …/disable 或 DELETE … | 停用/删除说明；历史快照不变 |
| POST /api/creative-elements/compile-preview | 指定选择/版本/阶段，返回实际投影与预算，无模型调用 |
| PUT /api/workshop/creation-drafts/{id} | 保存故事构想、四组选择、当前步骤与 revision |
| POST /api/workshop/sessions | 新 flow 标识、四组选择、期待的启用版本、幂等键；校验冻结后启动首轮 |

提交出现启用版本变更时返回 409，前端提示查看变化后采用，不把点击时的旧说明换成新内容。重复点击用 operation_id 复用已有任务；请求未完成/断网返回后查询同一个任务，不自动创建第二个付费调用。

运行进度使用现有服务端任务记录与观察信号，切页/刷新可恢复；没有新模型内容时如实提示等待，不把心跳伪装成持续推理。取消、暂停和恢复按既有任务协议处理。

MD 导入按纯数据处理，安全解析 YAML，禁止未知身份、重复键、别名膨胀与任意路径读取；预览禁用 HTML/脚本。结构错误和空占位不允许启用。文本包含“忽略系统要求”之类命令不获得执行权限。请求日志只记录本地可核验信息，不公开作者原稿到外部日志。

现行入口 `api/creative_types.py`、`core/creative_types.py`、`api/workshop.py` 已有草稿/启用/冻结/投影；可复用存储和版本能力，但不能把旧 dimension/pub mapping 直接解释为新四组身份。新 flow 使用独立协议版本，由单一适配层读取历史资料和会话。旧讨论继续原快照，主动迁移时预览并确认，不批量修改已在写的小说。

新 H5 导出继续由 `api/workshop_classification.py` 和现有发布编译器绑定作者 ID、Manifest V4、novel-h5-import.v1、EPUB/ZIP/SHA；创作 MD、私有承诺、模型请求不进入公共交付包。保留 PNG/JPEG、Introduction 和 64/16 MiB、512 spine 等既定规则。

## 9. 交付顺序与验收

1. **设计审核**：五步流程、编辑 MD 页面、样例说明和首轮输出形态。
2. **文档底座**：解析/校验/版本/启用、字典覆盖、单一兼容适配层；不先动现有运行。
3. **创建与编译**：四组必填、顺序引导、草稿恢复、冻结、请求预览和幂等任务。
4. **下游传递**：本书承诺贯穿骨架/章节/正文/评议，复用现有决策与交接。
5. **真实验收**：获得调用范围后执行，不拿静态原型当实验结果。

工程用例：四组分别缺失；空构想；错误轴/未知ID；同名跨轴；数量上限/互斥；无启用说明；并发编辑；旧版本/删除后的恢复；未保存草稿不入请求；完整字节预算；重复提交；切页刷新；不自动输出骨架；H5所有派生物一致。

内容用例：同组合至少三条因果不同路线；仅切换故事类型/背景/情绪后的对照；家庭背叛＋第二次机会必须有可信重建；狼人必须改变故事机制；现实与超自然不能暗换；多情绪需要合理过程；与已明确结局冲突须询问。实际阅读骨架及样章，确认吸引力、因果、人物和表达，不只搜索提示词标签。
