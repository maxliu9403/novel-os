# 联合审稿证据协议与可恢复执行

## 故障归属

旧联合审稿要求模型逐字抄写正文，引文稍有展示差异即抛出 ValueError。真实第7章正文哈希正确，四维判断均通过，但两条摘录各多一个对白边界引号。原始回复、原请求和冻结上下文均已保存且可核验，恢复路径却会重新调用审稿模型。

检查还发现三个共用边界缺陷：Guardian 机器报告经过散文标点清洗；完整审稿校验前已保存状态提案；历史长篇审计依赖整份持续增长的 story_state，重算时触发全流水线生成失效，可能重写尚未晋级但已经付费的章节。这些是协议与执行生命周期问题，不足以证明正文有文学缺陷。

## 职责分离

`review_evidence` 只负责定位和证据绑定。新 `joint-editorial.v2` 输入是代码生成的完整段落目录，所有片段拼接严格还原原稿；候选 SHA、目录 SHA、精确范围和段落 ID 由代码计算。模型选择一个或多个证据 ID，并给出四维判断、理由及修改要求，不再抄引文或数偏移。解码器校验候选、目录和 ID 后从原文提取引用。

`chapter_review` 提供同一双协议解码器给审稿、定稿和晋级。完整报告校验同时核对唯一且完整的 continuity 报告、状态更新块及一致的总状态。JSON 中的文字不能伪装成机器状态块。证据定位正确不等于文学判断被程序证明；文学判断仍由同一次联合审稿承担。

`joint_review_session` 管理请求、原始回复和派生报告的持久化。请求绑定完整 prepared context，原始回复先保存并校验哈希，再解析。相同请求的并发处理持锁；失败后优先处理已收到的回复。孤立 raw 文件不自动获信任，必须通过原运行时的完成回执验证。若进程在 provider 已保存回复、调用层尚未复制前退出，恢复会按完整请求查找唯一已完成回复；多个不同判断不会被 UUID 或文件时间随意选中。

完整协议校验完成后，orchestrator 才发布报告；只有通过文学审稿且无确定性 critical 的结果才生成状态提案。机器证据不经过散文清洗。正常通过的章节仍只需要一次联合审稿，不增加日常模型调用。

## 旧任务与协议纠正

旧 `legacy_prompt` 保留原字节，原请求和响应先通过 `CreativeExecution` 的 source、context、user、system 和 response SHA 校验。v1 兼容仅允许剥除一层额外的首尾展示引号，剩余文本必须唯一、连续地精确匹配正文；不改变内部字词、大小写、空白或省略，不做相似度匹配。

恢复只改旧 JSON 的 quote 字段，原判断、理由、修改要求以及 JSON 外的 continuity 文本保持不变。原始付费回复、旧报告和来源绑定回执分别保留。导入的旧请求有自己的固定历史记录；即使纠正请求更新了可读 prompt 文件，后续恢复仍继续原请求及其已发纠正，不能重新开始付费初审。

无法安全定位、无效 JSON 或缺少机器协议块时，保存完整原回复，自动进行一次完整 v2 协议纠正。纠正仍必须核对完整正文；无依据的判断须要求修订，不能为了获得 PASS 编造证据。纠正也不合格时保留全部回复并停止，重复恢复不无限重付费。有效的 `revise` 继续进入原有文学修订流程。同一正文和上下文的审稿结果会复用，不能靠不改正文反复抽取 PASS。

## 历史审计失效范围

长篇审计输入指纹改为它实际读取的篇幅/分卷合同、截至审核章的章节合同修订，以及卷尾 Final 文件；缺失文件也有明确指纹。未来章节状态不改变历史审计输入。

`long_form.audit` 是只读派生阶段。旧指纹升级或历史合同改变会重新核查，但不会恢复旧故事快照、改变生产阶段的全局重跑标志，或产生新的故事状态快照。过去合同或 Final 的真实修改仍会触发审计；后续正文生产仍独立校验自己的真实输入及产物。

## 验收边界

回归覆盖新旧协议、多个不连续证据块、错候选/错目录/错 ID、歧义引文、重复字段、损坏回执、并发、两个崩溃窗口、已发纠正恢复、真实文学修订及旧任务零额外审稿恢复。历史审计测试先复现错误恢复故事快照及付费阶段失效，再验证范围隔离。

真实项目在隔离副本执行原生 resume：保留60章细纲、1–6章晋级及第7章现有正文，复用第7章付费审稿后只晋级一次；第二次恢复不重复 canon，首次需要新模型的步骤是第8章写作。工程与运行验收不能保证所有未来模型回复都有效，也不能替代最终小说质量审查。
