# 作品类型维护：页面与模型数据协议设计

日期：2026-11-01。状态：按用户要求完成方案与交互原型，**生产功能尚未开发**。属于总体方案的 M1.1，衔接 M1 已实现的题材资料/决定快照与 M2 的骨架正文接入。

## 1. 用户要解决的问题

用户可以自行维护狼人、科幻、复仇、家庭情感等类型的写作要求。头脑风暴的类型选择来自用户的资料库，所选说明能实际进入模型请求；不必改源码、编辑 JSON 或为每种类型开发执行逻辑。

把“选了狼人但最终只是普通家庭纠纷”改为：作者维护该类型应产生的阅读体验及机制，模型结合本书人物提出具体规则与代价，用户选择后再进入骨架。资料提供创作方法与选项，不把范例人物、桥段、结局或所有常见惯例自动变成本书事实。

本页沿用已经锁定的浅蓝紫、白色圆角面板、无衬线文字和全宽布局，不另起视觉主题。原型：`prototypes/creative-type-maintenance/index.html`。

## 2. 两套“类型”有明确边界

| 概念 | 用户是否可维护 | 用途 |
| --- | --- | --- |
| 创作类型资料 | 可新增、改名、编辑、复制、停用；支持组合型和自定义类型 | 头脑风暴与后续写作指导 |
| H5 发布分类字典 | 本页只读，只能选择现有合法映射 | ZIP / EPUB / publication package 的分类合同 |

创作类型使用独立稳定 ID，例如 `ct_werewolf`，不直接作为 H5 `filter_type_ids`。显示名、别名、排序改变均不改变 ID。多个类型可以共同指导一本书，但不能依靠勾选顺序决定主次。

新增“赛博修仙”可以先参与创作。若未映射发行分类，页面明确显示“发行分类待映射”；不能把 `ct_cyber_cultivation` 写进 ZIP，也不能偷偷降为综合小说。组合后的 primary/secondary/story/tone/setting 超限、未知 ID 或相互冲突时，代码给出可解释的待选择项；用户选择合法组合后才进入正式发布合同。H5 的 M0 强制门始终保留。

类型映射是建议集合，不是每本书的最终分类。最终分类需按当前作品和目标字典计算、校验，保留采用来源；一般题材词无法映射时不得由 LLM 发明 ID。

## 3. 页面与交互

### 3.1 入口与总体布局

导航新增一级“作品类型”。页面标题为“作品类型维护”，与作品库、头脑风暴、设置并列。它是创作资产，不藏在模型连接配置里。头脑风暴的基础设定区域也提供“维护作品类型”入口。

桌面为全宽双栏：左侧约 280px 的可搜索列表，右侧自适应编辑工作区。两栏各自滚动，编辑区底部保存条固定。窄屏先选类型，再进入全宽编辑，保留返回列表按钮；标签横向滚动，禁止整页水平溢出。

列表显示名称、创作维度、启用版本、说明摘要和状态。支持按名称/别名/关键词搜索，以及创作维度和全部、已启用、草稿、已停用筛选。列表与头脑风暴选项按维度分组，主题增加后无需在一大排按钮中寻找。顶部有“新建类型”，详情可“复制为新类型”。不以数量多寡暗示资料质量。

### 3.2 编辑器五个标签

| 标签 | 用户看到的内容 | 主要交互 |
| --- | --- | --- |
| 核心体验 | 名称、别名、所属维度、简介、读者期待、适用读者/市场/语言/篇幅 | 普通输入框与可添加条目；空值表示未限定；细分方向可写入说明 |
| 故事机制 | 规则卡：机制名称、触发与范围、限制与例外、代价、会迫使怎样的选择、回报方向 | 展开编辑；可增删；每条说明“优先讨论/建议采用/可选灵感” |
| 人物与文风 | 人物驱动力、关系张力、对手回应；视角、情绪距离、节奏、对白及表达偏好 | 分组短条目，允许写正例和反例，不要求作者复制长提示词 |
| 检查与融合 | 反事实检查、常见失败、应避免内容、与其他类型的协作与冲突；发行分类映射 | 提示性质可见；发行映射使用只读字典选项 |
| 模型预览与版本 | 本类型模型阅读摘要、结构化 JSON、已启用与草稿区别、修订说明、版本历史 | 默认看易读摘要；JSON 可展开/复制；回退创建新版本 |

创作维度包含「婚姻与亲密关系」「家庭与代际」「成长与自我实现」「类型与世界」「冲突与成长」「人物与关系」「情绪与文风」「读者定位」。前面三组便于维护女频常见主题；原有五组仍保留，维度仅作主要归类，不宣称彼此完全互斥，也不决定该主题在本书中的主辅作用。

具体的「婚姻背叛」「出轨与双面生活」是独立可编辑资料，归入婚姻维度，不为每个具体桥段继续添加程序枚举。所有主题复用同一协议；不强迫「幽默」填写变身规则，也不把「成年读者」当成世界设定。后续新增主题无需再修改维度或引擎分支。

上面的“规则卡”适用于制度、情感或信息规则，不限定为超自然设定。例如家庭类型可维护“承担照护会挤压时间与收入”；悬疑类型可维护“证据来源与可信度改变调查选择”。用户不需要为每个题材填满全部字段；新增时先填一句话和一条阅读期待即可，后续逐步完善。AI 辅助整理可作为未来显式功能，本阶段不在保存时自动付费调用模型。

### 3.3 保存、启用与停用

- **保存草稿**：允许内容未完整，不被新讨论自动读取。保留未保存状态，切换类型时提示保存或丢弃，不静默丢失。
- **保存并启用**：代码校验后产生不可变版本，一步完成，无模型审查、无额外人工审批。最低要求是名称、维度、简介以及至少一条有内容的创作指导；其余缺项明示，不伪称完善。
- **继续编辑**：从当前启用版本生成工作草稿。启用版本仍可用于新讨论，草稿不会混进去。
- **停用**：从新讨论的可选项隐藏；旧会话绑定版本继续可查看、恢复，不删除资料或小说。
- **版本恢复**：以历史内容建立新的草稿/版本，不能改写旧版本。原型只演示本页版本，不连接生产历史。
- **保存冲突**：基于修订号做乐观锁；409 时保留本地草稿，提供重载对照，不用最后写入覆盖他人改动。

内置三组资料作为初始可编辑内容，不要求用户“复制后才能编辑”。首次修改在用户工作区保存覆盖版本，安装目录资源不动；可查看原始参考或恢复为新草稿。升级后的系统示例不静默覆盖用户版本。

### 3.4 头脑风暴接入

基础设定的类型选项从资料库读取启用版本，按主要维度分组。悬停/展开可看到一句话简介、版本和覆盖状态；“新建类型”进入本页，保存后回到原讨论仍保留输入。自定义类型不再只能存成一个无说明字符串。

选择后显示“本书已选类型”，允许标注主要驱动/辅助/基调，也允许暂不指定。模型可以建议各类型在本书中承担的作用，但建议不改变作者已选集合。

创建讨论时冻结所选版本及完整内容。已有讨论显示“使用的类型说明”及来源，修改资料库不会自动替换它。用户点击“采用最新说明”时先看到变化摘要，再显式更新下一轮上下文；任务运行时不能切换，需等待完成或由用户暂停。此操作本身不调用模型、不删除既有决定，也不自动重写骨架。冲突在下一轮作为待解决项提出。

模型上下文预览提供两个清晰入口：**预览当前草稿**（尚未用于任务）和 **当前启用版本**（新讨论可用）。在具体讨论内另显示**本次实际快照**，以真实请求哈希和引用内容为依据。不能把未保存输入显示成模型已经读过。

## 4. 模型可读的数据结构

协议不靠复杂 JSON 让模型“更聪明”；它的价值是确定字段含义、来源、版本、适用阶段和采用边界。用户维护表单，代码生成 JSON；模型只为具体小说设计内容。

### 4.1 `creative-type-profile.v1`：一类故事的可维护资料

对应设计 schema：`contracts/creative-type-profile.v1.schema.json`。完整狼人示例：`contracts/creative-type-werewolf.example.json`。

| 字段 | 含义及约束 |
| --- | --- |
| `profile_id`, `version` | 代码分配的稳定 ID、不可变版本，不由 LLM 生成或自增 |
| `name`, `aliases`, `dimension`, `summary` | 用户维护的身份与简介；别名用于旧输入适配，不能模糊匹配后悄悄换类型 |
| `applicability` | 适用受众、市场、语言、篇幅；空数组为未限定，不自动默认某人群 |
| `reader_promises` | 希望读者获得的体验、重要性及适用阶段 |
| `mechanisms` | 触发、范围、限制、例外、代价、选择与回报；必填机制名称和核心作用，细节可以未限定 |
| `character_dynamics`, `voice_guidance` | 人物/关系动力与表达偏好，都是类型级方法，不是本书身份事实 |
| `pitfalls`, `diagnostics` | 失败模式与设计问题；文学检查为建议，不产生“通过即高质量”的分数 |
| `combinations` | 合作类型、需要协调的规则、协作机会；关联稳定资料 ID，不能递归自动选中其他类型 |
| `publication_mapping` | 只使用当前 H5 字典的映射候选及映射状态，不等于最终作品分类 |

通用指导条目包含 `id`、`text`、`importance`（essential/recommended/optional）、`stages`（brainstorm/story_design/chapter_plan/draft/review）。正文之外的通用创作说明不是 shell、工具或模型系统指令，不允许改变执行协议、预算或调用目的地。

`essential` 表示：选择该资料时应优先讨论的类型要求。若与本书作者明确设定冲突，向作者呈现冲突与替代方案，不能自动覆盖。类型资料中的“必须”不自动取得修改本书已确认事实的权力。

### 4.2 `book-type-selection.v1`：这本书选了什么

记录 `profile_id`、所选 `version`、内容 SHA-256、用户指定的作用（未指定则保持未指定）、引用时间与来源；独立保存作者局部偏好及后续更新事件。名称是显示快照，不作为恢复身份的唯一键。

类型条目中的常见机制仍是候选。进入本书机制时需要绑定实际人物、条件、代价和后果，并记录采用来源（作者明确操作、原始意见或明确委托范围）。M1 的方案卡/决定记录复用，不另建相互矛盾的第二套“已确认设定”。

### 4.3 `genre-context.v1`：某一次调用实际读取什么

编译器确定性地从作者选择与不可变版本产生：

```json
{
  "schema": "genre-context.v1",
  "stage": "brainstorm",
  "authority": "type_guidance_not_book_facts",
  "profiles": [
    {
      "profile_id": "ct_werewolf",
      "version": 2,
      "source_sha256": "由代码计算，示意值不是实际哈希",
      "role": "primary",
      "content": {"name": "狼人", "reader_promises": [], "mechanisms": []}
    }
  ],
  "pending_conflicts": [],
  "provenance": {"selection_revision": 4, "compiler_version": "genre-context-compiler.v1"}
}
```

上例只解释封装，不代表完整有效请求；`content` 实际包含所选资料在当前阶段适用的全部条目，示例与 schema 中提供完整类型内容。**管理状态、修改人、UI 排序、H5 映射和其他未选类型不混入创作提示。** 系统通用规则固定拼装，用户类型资料以结构化数据提供，模型被要求按资料提出本书方案，不能执行其中的指令文本。

编译过程不调用 LLM、不自动概括或截断：校验选择→锁定版本→按显式 `stages` 取适用条目→检测结构冲突/缺失引用→计算大小→生成规范 JSON 和哈希。阶段投影有 manifest，列出包含及不适用条目，原完整版本始终可查。不是每次把整个类型库塞进提示词。

规范化规则固定为 UTF-8 JSON、对象键递归排序、无额外空白、数组保留作者顺序，不对内容做模型摘要或隐式 Unicode 改写。保存时先按字段规则去除输入首尾无意义空白，再生成不可变内容。`source_sha256` 对完整启用资料计算；实际阶段内容与最终请求另存哈希，不把来源哈希冒充发送字节的哈希。预览接口的 `preview_only: true` 标记说明没有发送模型请求；生产实际请求回执独立保存，不沿用该标记。条目和类型重复、组合自引用/缺失目标、映射超限等由代码校验；“两个题材在创作上是否相容”仍应作为讨论问题，不假装可由 schema 判定。

预算初始设计为每份资料不超过 24 KiB 的创作内容、一次类型上下文不超过 96 KiB；这是待实测冻结的工程默认建议，不等于某模型的上下文上限。总请求还须扣除小说原文、对话及响应预留。超过预算在调用前展示具体资料/条目占用与精简入口，不悄悄丢说明，也不循环重试。Token 可按模型适配器估算；未知时只显示字节，不能把字节冒充 token。

### 4.4 在现有流程中真正用起来

新维护库替换 `core/genre_design.py` 的资料来源，保留集中编译职责；`api/workshop_design.py` 复用冻结策略、快照与作者决定语义，不在前端私自拼装高权限提示词。讨论阶段提供 `brainstorm` 投影，作者明确交付时提供 `story_design` 投影；M2 的章节规划/写作/评议再按对应阶段读取同一锁定来源。阶段内容变化不等于用户选择发生变化。

固定系统规则要求模型：先理解全部已选类型和本书意图；提出少量有差异的方案及代价；指出哪些选项利用了哪些类型说明；有冲突时提出取舍问题；保持主动引导，直到用户明确要求骨架交付。类型库不重新引入“选完类型便自动写骨架”的旧问题。

例如作者选择「狼人＋复仇」后，类型资料中的“庇护附带义务”可以被具体化为“公开揭露族群领袖会失去庇护，但沉默将继续伤害同伴”。模型应主动给出“公开对抗 / 内部取证 / 建立独立庇护”的不同方案，并询问作者更看重哪种人物代价。这是一个提案示例，不是所有狼人故事通用剧情；采用后才进入本书设计。

验收必须检查真实请求内容：编辑前后各建立隔离讨论，确认采用版本、指定条目、投影清单和请求哈希一致；只展示漂亮的预览 JSON 而后台仍读取静态资料不算完成。已有讨论应明确显示“有新版可采用”，不自动更换当前调用。

## 5. 数据与 API 边界

按工作区持久化，包含草稿、不可变版本、当前启用指针及历史元数据。单用户本地模式沿用现有路径逻辑；未来多用户权限沿用 owner/editor/viewer，不因为 UI 隐藏按钮就声称已有权限隔离。GET 仅读取，不导入、不升级、不调用模型。

已实现接口（M1.1 本地验收，未部署）：

| 接口 | 行为 |
| --- | --- |
| `GET /api/creative-types` | 轻量列表、搜索、状态、启用版本 |
| `GET /api/creative-types/{id}` | 工作草稿与当前启用摘要 |
| `POST /api/creative-types` | 创建资料，代码分配 ID |
| `POST /api/creative-types/{id}/draft` | 版本检查后保存草稿 |
| `POST /api/creative-types/{id}/activate` | 原子保存不可变版本并启用；失败保留旧启用指针 |
| `POST /api/creative-types/{id}/disable` | 停用，不删除历史 |
| `GET /api/creative-types/{id}/versions/{version}` | 回看不可变版本 |
| `POST /api/creative-types/preview` | 本地确定性编译，返回摘要、JSON、字节及问题；零推理 |
| `POST /api/workshop/sessions/{id}/type-snapshot` | 作者明确更新所选版本，绑定会话 revision，零推理 |

发布/快照更新使用修订号和操作 ID，重试幂等。资料库变更与小说任务不共用可变指针。文件损坏、版本缺失或哈希不一致时显示具体错误，已有有效快照仍可用；不能回退到同名新版本假装等价。

## 7. 校验与验收

代码校验 schema、长度、稳定 ID、条目 ID 唯一性、引用存在性、发布映射白名单及版本、哈希、权限、并发和请求预算。draft 可以未完整，activate 必须符合启用合同。小说好不好看不由这些检查自动证明。

必须覆盖：新建/编辑/停用/恢复、草稿不泄漏、刷新保存、409 保留草稿、中文/英文/自定义类型、混合选择不丢项、不按顺序强制定主次、别名歧义、旧会话/运行任务冻结、明确更新与迟到回复、只传所选说明、超限无截断/无模型调用、脚本样式文本按普通文字显示、H5 未知 ID/超限/未映射拒绝发布、工作区隔离。

视觉验收：桌面全宽、窄屏无横向溢出、键盘可切换标签和操作表单、可见焦点、错误贴近字段、未保存提醒，原始 JSON 默认折叠。结构样例验收可本地执行，不启动真实推理。
