# 头脑风暴运行状态与流式回复方案

日期：2026-10-08。状态：第一阶段运行快照与等待卡已实施，并增加调用级遥测；
第二、三阶段正文增量及 SSE 仍为后续方案。用户在调用链审计后授权先完成已确认的优化。

## 目标与范围

用户应知道请求处于哪个可验证阶段、最后一次收到内容是什么时候，以及能否暂停或离开后恢复。
采用“真实运行状态 + 有内容时流式展示”，保持现有页面配色与头脑风暴入口。

改动范围限于头脑风暴前端、状态/事件接口与 LLM 适配层的可选回调。
不改变小说推演、正文编写、封面、导出格式或启动命令逻辑；不自动修改模型、推理级别或超时时间。

## 第一阶段：复用轮询显示真实进展（MVP）

复用当前 1.5 秒会话轮询，将后端诊断投影成经字段白名单筛选的运行快照。
不要直接向前端暴露完整诊断文件、原始 stderr、认证信息或私有推理内容。

| 证据 | 页面状态 |
| --- | --- |
| 本地任务保存输入、构建上下文 | 正在准备本轮讨论 |
| 输入已可供子进程读取 | 正在启动模型调用 |
| 客户端发出 turn.started，尚无回复正文 | 等待模型回复 |
| 收到真实回复内容 | 正在接收回复 · 已收到 N 字符 |
| 完整结果到达、正在解析 | 正在整理回复 |
| 完整骨架进入校验 | 正在检查骨架完整性 |
| 已有格式修复机制发起下一次尝试 | 正在修复骨架格式 · 第 N 次 |
| 完整校验及持久化成功 | 本轮讨论已完成 |

运行快照包含：session_id、operation、revision、job_id、attempt、request_id、started_at、
deadline_at、当前阶段、worker 最近检查时间、最近 CLI 事件时间、最近实际正文时间及正文字符数。
没有收到正文时，正文时间为 null；不得用 heartbeat 或 turn.started 填充。

建议等待卡片：

```text
等待模型回复                                  已用时 03:42

后台任务检查：5 秒前
最近收到模型内容：尚未收到
本轮最长等待：15 分钟

关闭窗口后任务会继续，返回此讨论可恢复查看。

[暂停推导]                              [展开运行详情]
```

本地进程存活、浏览器连接正常与上游模型实际返回内容是不同信号，必须分开显示。
不虚构“正在设计人物”等模型阶段，不显示虚假的百分比，不将活动信号等同于模型正常思考。
长期静默只提示“已有 N 分钟未收到新内容，后台任务仍在等待模型”，不自动判定失败或启动重复请求。
浏览器连接断开、后台任务中断、模型调用失败分别呈现。

## 第二阶段：按提供商能力展示真实回复流

模型实际返回片段 → 后台保存临时回复 → 推送页面 → 完整返回后校验并正式保存。

- 为 LLM 适配层增加与诊断分离的内容回调；默认不影响其他调用方。
- 当前传输合同是 JSON，包含 reply、questions、prompt_md、ready_for_confirmation。
  增量展示需要正确处理 JSON 字符串转义、Unicode、字段边界及截断，只渲染其中可读的 Markdown。
  不向用户显示半截传输 JSON；最终仍进行完整解析与原有校验。
- 流式草稿与正式 messages/prompt_md 分开存储，标记“生成中、尚未完成校验”。
  未校验草稿不得替换上一版完整骨架或启用创作启动按钮。
- 格式修复使用不同 attempt 隔离草稿，不能将两次生成拼接为一条回复。
- 暂停/失败时保留已收到草稿供查看；它不自动变成已确认上下文。
  后续复用遵循原有候选骨架修复规则。
- 回复及事件存入现有持久化数据目录，遵守工作区隔离、大小限制和权限控制。
  无正文的诊断日志继续保持现有保留边界。

前端可以使用 SSE，并保留轮询降级。事件具有持久化序号，支持重连补发；
客户端先获取权威快照，再接续事件、去重。代理必须允许及时推送，避免缓冲造成假流式。
正文渲染适度批量更新、保持 Markdown 安全渲染；用户阅读上文时不强制滚动到底部。

## Codex 能力边界

已观察到实际 Codex exec 调用先发出 thread.started/turn.started，随后约 431 秒静默，
直到 item.completed 才提供完整回复。仅给网页增加 SSE 不会让这段调用更早输出正文。

- 提供文本增量的接口：展示真实增量。
- 只提供运行事件的接口：展示真实阶段及等待时长。
- 只返回完整结果的接口：明确等待完整回复，不用打字动画冒充实时生成。

Codex 逐字流式能力需验证可用适配接口后接入，不能假定 exec --json 已提供正文 token 增量。
不通过切换模型、服务商或额外并发请求伪造进展。流式展示也不保证缩短首个内容到达之前的等待。

## 恢复与并发规则

- 关闭窗口或 SSE 只结束观察，不取消后台生成。
- 刷新、切换讨论、重连使用服务端原始开始时间，不重置计时，不发起新模型请求。
- 所有更新核对 session/operation/revision/job/attempt/request 身份，防止跨讨论或重试串流。
- 暂停与完成竞态沿用当前操作校验，旧请求迟到片段不能覆盖新一轮。
- 服务重启后，不能证明仍在执行的任务应标记中断；恢复页面不等于恢复原模型进程。

## 实施顺序与验收

1. 状态投影、运行快照、MVP 等待卡片与诊断详情。
2. 内容回调、独立临时草稿、按能力增量展示。
3. SSE 推送、断线补发与轮询后备；验证 Codex 可用的增量接口。

验收覆盖长时间静默、正常增量、格式修复、超时、浏览器断线、刷新、关闭、
两讨论切换、服务重启、暂停与完成竞态。要求不串流、不重复提交、不丢已确认上下文、
不把未验证草稿标记为完整骨架、不将本地心跳误标为模型思考。

## 本次落地

沿用会话轮询，增加独立、大小受限的持久化进度投影；读取时核对讨论、版本、操作、
任务身份，修复尝试单独计数。页面区分后台检查、上游事件和实际收到的内容字符。
修复状态遵循真实事件顺序；迟到的旧尝试不能覆盖新尝试，乱序上游事件不能倒退时间。
进度只在 API 读取时附加，不写入原会话 JSON 或正文；详细诊断达到上限不会阻止更新。

Codex 调用按次启用回环 OTel 收集，采用字段和值的白名单，不保存原始遥测正文。
输出预算显示配置值和生效值；CLI 不支持本应用的预算参数时明确显示未生效。
这不等同于发现或修复原始 900 秒静默的唯一根因，仍需根据后续真实请求证据归因。
