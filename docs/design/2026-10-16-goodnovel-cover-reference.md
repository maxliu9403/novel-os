# GoodNovel 封面参考与 Novel OS 美术方案补充

2026-10-16 · 网站实看与代码对照；设计提案，尚未实施。

用户提供 https://www.goodnovel.com/，希望达到其封面的设计感与故事感。本轮在浏览器查看首页、四本书的详情封面及 Emotional Realism 分类，结合公开简介理解题材；没有读取全书，也没有依据阅读量推断封面转化率。以下是抽样视觉分析，不代表全站统一风格或对制作工具的判断。

## 1. 样本观察

[Emotional Realism 分类](https://www.goodnovel.com/stories/Emotional-Realism-short-novels) 同时能看到双人对视、单人肖像与人物场景等不同做法。不能把狼人爱情的年轻情侣、月亮和华服直接套到成熟家庭小说。

这些封面的故事感通常由**角色关系、题材信号、情绪与标题共同产生**。仅看图，未必能还原具体情节；结合标题，读者能形成明确的阅读期待。这是对视觉与文案配合的分析，不是已证明的点击率因果。

## 2. 修正上一版的两个设计倾向

第一，不再用“至少三张多人”作为通用验收指标。用户希望减少泛化单人图，应通过核心人物召回和关系表达解决。关系型小说的候选集应充分探索双人和群像；人物数量根据故事、画幅和受众决定，不把加人当作质量提升本身。

第二，不强制每张图表现明确动作或还原一个冲突现场。上面的三角站位和双人宣传姿态具有商业表达力。允许人物以设计过的姿势、视线和主次形成关系，由标题补充具体故事钩子；不要再以“没有足够动作”把方案送回审核循环。

同时保留对无意义分格拼图的警惕。并排头像若没有共同视觉中心、关系含义和统一美术，就仍然缺乏整合。组合本身没有优劣，关键在于它是否让人物关系更容易理解。

## 3. 新增「商业封面美术系统」

沿用完整骨架一次联合规划，不新增必经分析步骤。在同次规划中确定以下五项，并作为统一的生图与排版合同。

### 题材与读者的视觉定位

先确定主要阅读期待，如情感修复、背叛反击、危险吸引、权力争夺、奇幻命运、孤独求生。只在来源支持时使用对应题材符号，避免所有小说都套“漂亮人物＋豪宅”或“文件＋低头”。

不同题材可以选用不同配方：精修商业摄影、电影海报合成、半写实幻想美术、类型化插画等。配方是可选择的创作参数，不是硬编码一套网站风格，也不声称抽样图片都由某一种工具制作。

### 人物魅力与关系

保持故事确定的年龄、身份和关系，同时允许专业造型、发型、妆容、衣着与宣传布光。自然皮肤与角色魅力可以并存，不能把成熟人物一律画成疲惫、憔悴、灰暗的纪录照。

普通家庭故事也不自动换成富豪晚宴；选择符合角色经济处境与题材的精致表现。北美40–60岁女性读者定位不意味着把主角年轻化，更不授权推断种族身份。

主角要有清晰的视觉位置；配角的出现服务于吸引、冲突、牵挂、隐瞒或共同压力。两人关系、三角站位、前后景主次、象征性合成均可，不强制发生身体互动。

### 一组简洁、来源相关的题材信号

把最有价值的环境、道具或世界元素融入主视觉，而非列成物品清单。狼/月亮可辅助狼人故事，都市服饰/空间可辅助现代权力爱情，门槛/家庭空间可辅助归属关系；具体使用仍以各书内容为准。

画面要集中，不把全书所有秘密、伏笔和结局塞到一张封面上。每案主要承诺、人物关系与视觉识别应相互支持。

### 标题即主视觉的一部分

把完整准确的书名拆成保序的文字段落，规划主关键词与连接词的视觉层级；不自动删除、重排或缩短书名。需要实现真正可渲染的：

- 每行或文字段的字号、字体、字重与颜色。
- 可用于发布的字体库及明确回退，不局限两款英文粗体。
- 可调行距、字距、描边、阴影和局部可读性底衬。
- 按题材选择克制的渐变或金属效果，避免所有封面都使用金字。
- 精确字形边界、脸部保护区、文字与人物主次的版式预览。

先完成以上基础排版能力；人物遮挡文字、复杂蒙版等作为后续可选能力，不使普通任务额外调用模型。所有效果都由实际渲染器支持后再开放给规划器。

保留无字画稿与本地准确文字的双层资产。规划时同步设计画面与标题空间，生成后执行排版，而非给一张成图随意盖上大段文字。需要标题精修时优先本地调整。

### 缩略图上的整体效果

同时看大图和实际作品库缩略图：主要人物与关系是否可辨、题材气质是否清楚、书名是否有顺序和重点。标题与图像联合评价，不能要求去掉标题后仍证明所有剧情。

这几项在同一规划与已有轻量后台评价中完成，不为人物魅力、风格、排版分别新增模型审核员或阻断步骤。专业评价与实际读者偏好需要后续实测，不能从当前网站阅读量反推出设计效果。

## 4. 当前框架的具体差距

| 当前约束 | 代码依据 | 建议变更 |
| --- | --- | --- |
| 硬性要求真人摄影，并写明no beautification、禁插画/CGI | `core/cover_render_policy.py:6–14`；`core/cover_prompt_compiler.py:250`；`core/cover_validator.py:794` | 新协议按选定美术媒介编译和评价；年龄真实与专业美术处理分开，不在新模式中沿用绝对禁令 |
| 默认保守外貌和日常衣着 | `core/cover_prompt_compiler.py:70` | 根据故事与受众设计角色造型，允许有吸引力的商业表现，同时不改核心身份 |
| 仅三种字体ID；所有标题行同字体、字号、颜色 | `core/cover_typography.py:23–40,202–232`；`core/cover_director.py:1158` | 新版文字分段排版结构、字体资源和渲染器；冻结配方/校验与UI预览同步升级 |
| 标题区域要求大块均匀底色 | `core/cover_prompt_compiler.py:707` | 保留可读性目标，允许局部底衬与逐行文字区域，减少整块空白色带对画面的挤压 |
| 人物互动依旧进入具体事件与时空核验 | `core/cover_campaign.py:393–405` | 使用新poster_staging表达，宣传同框不被误当作逐章事件复现 |

代码并未固定所有标题只能在顶部，归一化region可变；也没有硬性要求所有合成都分格。色彩合同已反对强制棕黄暗淡，不能误报成现有硬限制。这些准确区分有助于只改真正阻碍效果的地方。

## 5. 合并后的开发范围

原提案的直接骨架规划、生成与评价解耦、轻量精修、异步恢复和旧数据兼容继续保留。本补充将美术能力明确为：

**故事核心与关系 → 题材/受众美术配方 → 人物造型与整体构图 → 图像和标题联合设计 → 四张候选 → 用户选择/精修。**

这些是同一创作任务内部的设计维度，不重新增加六个用户步骤或六轮模型调用。不要仅在提示词追加“GoodNovel style”：需要更新规划合同、渲染政策、图片编译、标题引擎及相应评价，制作原创封面。

真实验收选不同题材样本，同一本使用相同骨架/书名/模型配置比较新旧方案。分别评价整体吸引力、类型辨识、关系表达和标题设计；并保留单本书的特殊性。只通过代码测试或符合人数配额，均不等于视觉效果已达到参考水平。

本轮只有审阅文档与提案更新，无业务代码、真实生成或部署变更。
