# Genre / Tag 生成式创作设计方案

2026-11-06 · 作者已批准。首批五个指定 Tag 与阶段编译已实施并部署；全库改写及跨书相似性分析未实施。

原始资料位于 `resources/knowledge-imports/romance-35-tags/`，继续按原字节保留。作者指定的首批为 Action、Dark Romance、Possessive、Badboy、Age Gap；实施范围与验收见[交付记录](../reports/2026-11-06-five-generative-tags.md)。本方案后文的 Betrayal Markdown 仍是设计示例，未导入。模型路由及已有小说冻结内容未修改，未启动真实创作验收。

## 1. 结论与改造边界

让 Genre 定义作品的主要阅读承诺，让 Tag 提供能改变故事或表达的机制；具体人物、重大选择、事件链、揭露顺序与分章节奏，由每本书的头脑风暴产生。作者采用后，本书骨架继续约束正文。

本次改造集中于四处：

1. 重构知识文档的内容标准，解除固定十章节拍、指定地点和统一人物配置。
2. 调整阶段编译：探索阶段读创作方法，执行阶段读本书设计与适用指导，避免不断重新开故事。
3. 调整头脑风暴的路线比较、组合冲突处理和骨架承接。
4. 为作者提供清楚的版本、作用与模型输入预览，沿用现有页面与单选方案交互。

不增加一套平行的故事地图、逐 Tag 章节排期系统或全书评议任务。无需更换模型、调高随机性或增加常规模型调用次数。跨作品相似性提示作为后续独立增量，不能成为第一阶段上线前置。

## 2. 当前证据与不足

### 2.1 文件内容

对 35 份文件的“前 10 章强制节拍”表格逐项读取，其“功能”列只有 12 种完整序列。这不表示整份文档完全相同，也不能据此声称已经证明成书重复。

| 共用序列的部分 Tag | 共同功能路线 |
| --- | --- |
| Affair / Betrayal / Divorce / Face-Slapping / Misunderstanding / Regret / Revenge | 背叛 → 离开 → 第一次反击 → 被低估 → 证据曝光 → 公开打脸 → 后悔 → 第三方 → 选择 → 大揭露 |
| Arrogant / CEO / Dominant / Heir-Heirness / Office-Relationship / Ruthless | 当众否定 → 不可能的任务 → 第一次反击 → 绑定 → 公开局 → 越界 → 危机 → 低头 → 底牌 → 选择 |
| Contract-Marriage / Forbidden-Love / Hate-to-Love / Love-Triangle | 绑定 → 同住 → 假戏 → 第三者 → 亲密 → 契约危机 → 分开 → 追回 → 确认 → HE |
| Drama / Mystery | 爆点 → 站队 → 误会 → 反转 → 牺牲 → 真相 → 代价 → 选择 → 高潮 → 结局 |

Betrayal 另要求离婚登记处、宴会、法庭/发布会三个场景，要求每次反击有观众，并把公开地位反转作为通用表达。这些是具体商业写法，不应自动成为所有背叛故事的共同剧情。

First-Person-POV、Fast-Paced-Plot 也有各自十章剧情，混合了“表达方式”和“故事内容”。同时选择时，模型可能接受多套相互冲突的章节要求。

### 2.2 真实执行入口

- `core/creative_types.py`：`tag-prompt.v1` 在七个阶段完整发送 Markdown，固定节拍实际进入请求。原样导入本身遵守了用户先前要求。
- 同一模块已经支持六分节的 `novel-knowledge.v1`、不可变版本、冻结选择与阶段投影，可复用这些边界。
- 现代讨论由 `api/workshop_request.py:discussion_system` 和 `skills/novel-brainstorm-workshop/references/web-discussion.md` 组装。只改历史 `api/workshop_design.py:RULES` 不足以证明新讨论已生效，必须检查最终请求。
- `core/story_design.py` 已有全局设计与章卡，骨架由代码渲染。应在这里承接本书节奏，不再增加另一份逐 Tag 节拍表。
- `core/creative_execution.py` 已冻结来源骨架与各阶段知识，正文应从该交接执行，而非读取最新维护页。

### 2.3 需要一起解决的内容冲突

- HE 倾向与 Tragedy 同时出现时，不允许模型悄悄删掉一个要求。
- “必须离婚、绝不原谅”与 Second Chance 的核心关系修复可能冲突，应先明确作者希望修复哪段关系。
- 不能把主关系的 Second Chance 偷换成配角的小修复来假装兑现。
- 独立性不等于拒绝一切帮助，CEO 不等于必须羞辱下属，快节奏不等于省略情绪铺垫。
- 原故事推演继承已知人物与事实；通用“不得沿用人名”的原创要求不能覆盖这个模式。
- 来源样本的数量或标签共现次数只能说明这批资料的观察，不能当作市场效果证明或必须采用的组合。

## 3. 约束分层：哪些固定，哪些开放

| 层级 | 固定内容 | 允许模型设计的内容 |
| --- | --- | --- |
| 引擎合同 | Genre/Tag 身份、合法关联、版本、导出规则、用户确认的篇幅上限 | 不由模型改动 |
| 本书约定 | 作者明确决定、来源模式、已成立事实、采用路线、已写正文 | 被授权的未决细节与新场景 |
| 类型核心 | 该类型成立所需的主要体验和机制 | 具体角色、事件、场景、筹码、节奏 |
| 默认倾向 | 资料的常用情绪、关系倾向、常见表达 | 在不损失类型身份的前提下调整；重大取舍由作者决定 |
| 可选示例 | 功能示范和可能的变化方向 | 可不采用、可改造、可提出文档之外的新机制 |

“必须”的范围缩小到类型成立所需的内容与作者已确认要求。不能把所有强要求都降成参考，否则类型会失去特色；也不能用“为了多样性”违背作者已经选定的故事。

运行冲突策略：代码拒绝非法 ID、关联、版本或尺寸；模型在现有讨论中提出影响故事身份的冲突。文学判断不新增自动打回循环，不用枚举所有 Tag 对的禁配表限制创作。

## 4. 文档标准：一个条目仍然只有一个 MD

### 4.1 元数据

建议增加 `novel-knowledge.v2`，复用现有字段，只有 Tag 增加 `roles`（1–3 个贡献角色）。该字段由维护者设置，普通创作用户不额外填表。Genre 不需要该字段。

```yaml
---
schema: novel-knowledge.v2
id: tag.betrayal
kind: tag
name: 背叛
aliases: [Betrayal]
genre_ids: [genre.romance]
roles: [conflict, relationship]
publication:
  labels: {zh-CN: 背叛, en-US: Betrayal}
  definition: 背叛
---
```

这是私有创作资料的格式版本，不改变 H5 分类协议。ID、公开标签与定义默认沿用启用版本；只有作者明确修改公开信息时才增长公开 revision。写作方法变更只增长知识版本。

`roles` 的可用值：`conflict`、`relationship`、`character`、`world`、`setting`、`mood`、`voice`、`pacing`、`ending`。允许一个 Tag 跨角色。它说明“怎样影响故事”，不表示优先级，也不能用于丢弃某个已选 Tag。

例如 CEO 可以贡献人物资源与社会环境，Betrayal 贡献冲突与关系，First-Person-POV 贡献叙述信息边界，Fast-Paced-Plot 贡献推进密度。角色配置不会按 Tag 名字在业务代码里硬编码。

### 4.2 六个正文分节

保留现有六分节，降低迁移和维护成本。不新增十几套独立表单。

| 分节 | 新版写作要求 |
| --- | --- |
| 核心承诺 | 分清类型成立条件、阅读体验、默认倾向；不写固定场景序列 |
| 故事机制 | 解释压力、选择、代价、反馈如何产生剧情；可列方法，不能要求全部采用 |
| 发散空间 | 给能改变因果的设计问题与变量；示例非穷举，允许模型提出新答案 |
| 组合原则 | 说明该类型如何与其他类型相互影响，以及真正需要作者决定的冲突 |
| 场景与表达 | 情绪代入、人物声音、节奏、有效兑现及失败表现；无固定章节号与统一钩子 |
| 简介与兑现 | 发行 Synopsis 的吸引承诺、剧透边界、与本书实际设计的对应关系 |

可选 `封面表达` 单独服务封面；`研究依据`、`示例分析` 为可读附录，默认不进入生成请求。维护页面明确展示这一点，未知分节在启用前提示确认用途，不能默默漏掉作者认为会生效的内容。

不把必须遵守的内容藏在附录。组合冲突、表达边界和本 Tag 的关键承诺必须进入标准分节。

### 4.3 Betrayal 新版正文示例（供确认，尚未替换）

```markdown
## 核心承诺

让读者经历：投入被辜负的刺痛、看清关系的愤怒、重新获得选择权的释放。
背叛必须实质改变信任、利益或未来；不能只靠标签说明“她被背叛了”。
主角的回应应影响后续局势；代价与回报来自其行动，不能完全由救援者代办。
默认重视止损、反击与尊严恢复。复合、离开或新关系的终局由本书确认，
不能用临时误会或苦衷取消已经成立的伤害。

## 故事机制

先设计这段关系曾经值得信任的具体依据，再决定谁利用了它、为什么、
获得什么，以及主角因此失去了什么。背叛者要有动机、资源与行动限制。

根据本书选择最有效的机制：让共同目标变成伤害工具；让信息差改变
双方筹码；让受害者的退出权产生后果；让一次反击改变盟友与亲密关系。
这些机制可以变形或替换，不要求逐项使用。

反击需有可理解的办法与反馈。一次胜利可以带来新的关系代价，
也可以完成一次充分的情绪释放，不必立即被更大伤害抵消。

## 发散空间

思考：主角最想保住什么？对方利用了哪种信任？真相怎样改变一个选择？
主角真正掌握什么能力？赢回原来的一切还是建立新的生活更有意义？

可以改变背叛性质、关系起点、双方知情顺序、回应方式与最终代价。
不要只更换公司、城市、身份和名字。允许提出这些问题之外的新机制，
不把婚礼、宴会、法庭或任何职业当作固定舞台。

## 组合原则

与 CEO 组合：让企业责任、资源控制或利益冲突实际改变关系与选择，
而不只是给人物财富。
与 Independent 组合：让主角拥有行动能力、判断与边界；接受帮助不等于失去主体性。
与 Second Chance 组合：明确哪段关系获得第二次机会，提出可信的承担、
改变与重建过程；若作者要求绝不复合，先解决冲突，不能偷偷换成配角兑现。

本书不是默认复仇故事；只有作者采用复仇路线或选择相应 Tag，
才围绕清算设计主线。无论路线如何，背叛造成的后果都不能被轻易抹平。

## 场景与表达

用共同生活、承诺或具体付出，让读者知道这件事为何刺痛此人。
戏剧性来自行为与关系意义的反差，不靠无限叠加羞辱和灾难。
揭露、反击、对峙、关系靠近与余波的先后，由人物选择和本书篇幅决定。
开篇及时兑现本书最有力的情绪入口；不要统一限定第几章抓奸或公开打脸。
私下拒绝、有效退出和重新被珍惜，也可以形成有力量的回报。

避免：反复争吵却没有新行动；反派为送证据而降智；主角只靠新伴侣获救；
每次胜利都被取消；道歉直接替代实际改变。

## 简介与兑现

展示一个具体人物、一个无法维持原状的关系，以及值得读者期待的选择或反制。
可用冲突瞬间、双方目标对照或关键对白引入，不固定三句公式。
不把尚未采用的底牌、救援者或复合写成卖点，不提前泄露全部反击和结局。
正文应让读者较早获得与卖点相符的实际体验，再逐步兑现主要承诺；
是否到位看故事与篇幅，不统一限定前十章完成清算。
```

这个示例包含需要作者确认的实质调整：原版“背叛必走复仇”改为“背叛提供冲突，复仇可由另一个 Tag/本书决定”；原版指定观众与场地改为开放表达。原有情绪强度、主体性和行为后果保留。不能把这两种改动仅称为格式迁移。

其余文档同样逐份编辑，不用脚本删除某个标题后统一粘贴一段宽泛原则。Affair 需保留婚外关系机制，Revenge 需保留有目标的反击，Mystery 需保留线索和认知变化，Tragedy 需保留真实损失，不能全部改成同一种成长文。

## 5. 头脑风暴怎样改变

### 5.1 作者入口保持简单

故事构想/来源模式 → 一个 Genre → 关联 Tags 多选 → 篇幅与偏好 → 开始讨论。

不新增“主辅 Tag 配权重”表单。模型根据本书提出主冲突与各元素的作用，作者通过故事路线选择确认。标签顺序不表示优先级，每个选中 Tag 都应产生相称的影响。

### 5.2 初次开放构想：同一次请求产生 2–3 条差异路线

方案卡继续复用现有 `title/story/tradeoff/recommended` 字段，不新增一份庞大 JSON。

每条卡片让作者看清：

- 谁想要什么、为何现在必须行动。
- 最吸引人的核心关系与冲突。
- 关键选择怎样导致中段变化和最终代价。
- 读者主要获得什么体验，节奏有什么不同。

比较重点：目标、关系权力、对立力量、主要选择、信息揭露和终局代价是否实质不同。维度是模型设计提示，不是“差三个字段才通过”的硬门槛。

作者已经给出明确路线或已有同一故事时，保留边界，只针对尚未确定的关键分歧给选项；不得为凑三条另开三本小说。

### 5.3 选择与收敛

沿用当前单选、补充想法、自定义路线和明确委托操作。采用才进入本书决定；“继续”不自动采纳所有备选。局部修改无需重复选择全部路线。

按开篇、中段、高潮、结局推进，用现有故事地图展示完整梗概与当前焦点。细枝末节由模型提出，不要求作者填满机制表。因果路线贯通、关键分歧解决且容量可行时，建议生成骨架；不靠凑讨论轮数或新造问题延长任务。

### 5.4 冲突处理示例

| 选择 | 正确处理 |
| --- | --- |
| Betrayal + Second Chance | 明确主关系的背叛及重建条件；不能以一次救援自动免除伤害 |
| Romance + Tragedy | 讨论希望保留的悲剧终局和情感回报；其他资料的默认 HE 不是全局禁令 |
| Fast-Paced-Plot + Slow Burn（未来条目） | 外部事件快、关系发展慢可以共存，不因词面相反就禁配 |
| First-Person-POV + Mystery | 推敲信息获知与误判；不得隐瞒叙述者此刻明知的事实来制造假悬念 |

逻辑冲突交给模型在原有回复中说明，只有会改变作者故事身份的取舍需要询问。技术无效选择由代码在模型调用前拦截。

## 6. 从本书路线推导节奏，不从 Tag 复制章节

顺序为：已采用的主线与关系 → 人物目标和因果 → 重要场面的阅读收益 → 情绪积累、兑现和余波 → 根据每章容量分章。

在现有全局设计的 `causal_chain`、`decisions`、`voice`、`setups_payoffs` 写清本书的节奏选择；不增加一套节拍事实源。在现有章卡中落实视角、具体剧情、看点/回报、结尾与伏笔。

允许的变化：事件先发生后揭因、读者先知道而人物后知道、关系先靠近后重新理解、外部胜利与亲密损失交错、不同篇章承担不同功能。它们是可能手段，不是替代十章模板的三种固定路线。

长篇按阶段性目标和选择后果发展；不按“每 3–5 章重跑同一模式”。短篇也不用压缩相同十章节拍。章节增加或篇幅调整仍需现有容量方案的作者确认；不能为了容纳剧情擅自拉长单章。

静场、余波、关系靠近和有意义的日常可以保留。它们需要让读者获得理解、感受或关系变化，不必每章都安排羞辱、事故或突发反转。

## 7. 阶段编译与正文执行

### 7.1 一个编译入口

继续使用 `core/creative_types.py:compile_snapshot` 作为公开入口。若职责变大，按“文档解析”“阶段编译”“版本存储”边界拆内部模块，避免在 API、正文与封面里分别解析 MD。

新增 `knowledge-compiler.v3` 处理明确标记的 v2 文档。保留 v1/v2 编译对旧冻结数据的原语义，按快照声明核验分派，不能恢复时根据最新默认编译器猜测版本。每次请求记录编译版本、知识 SHA 与纳入分节。

| 阶段 | 读取内容 |
| --- | --- |
| 头脑风暴 | 六分节：包括发散方法与表达/节奏指导；不带封面段落与研究附录 |
| 骨架整理 | 六分节 + 当前已采用决定；保留本书路线，不重做未采用备选 |
| 章节规划 | 核心承诺、故事机制、组合原则、场景与表达 + 本书完整设计 |
| 正文写作 | 核心承诺、故事机制、组合原则、场景与表达 + 当章合同与既有事实 |
| 联合审稿 | 同正文指导 + 实际章稿和本章承诺；不带发散菜单或新故事示例 |
| 发行简介 | 核心承诺、简介与兑现 + 本书实际设计/成稿依据 |
| 封面规划 | 核心承诺、封面表达 + 本书骨架与选用参考图片 |

重要核心与组合边界不得靠阶段筛选丢失。附录和不相关阶段材料的排除可在模型输入预览中查看。所有已选 Tag 保留身份与承诺，不能因排在后面静默不发。

### 7.2 输入体积

- 新文档建议约 800–1600 中文字，复杂 Tag 可更长；这是编辑目标，不是以字数推断质量的门槛。
- 通用方法只放一处；每份 Tag 只写其特有内容，不重复整套系统政策和输出格式。
- 沿用单文档 24 KiB、知识上下文 96 KiB 上限，另检查实际模型连接的完整请求预算。
- 当前 Gemini 兼容网关还有完整请求 120,000 字节限制；知识不过限不等于最终请求不过限。
- 超限时明确展示贡献来源，不静默截断原始事实、已选 Tag 或用户对话，不临时调用模型压缩后冒充完整输入。

### 7.3 正文承接

冻结文档版本、编译版本与作者采用的骨架。正文实现本书的动作、关系与情绪，不因 Tag 的常见写法推翻已确认路线；未采纳的参考示例不进入 canon。

联合审稿在现有调用内检查：本章是否实现其设计、有没有重复受辱/重复觉醒、重要转变有没有被写出来。审稿不能要求每章显式出现所有 Tag，也不能按固定十章表打回。质量意见按证据提出，不新增文学评分放行器。

按贡献角色检查影响：冲突 Tag 看选择与后果，视角 Tag 看叙述信息边界，节奏 Tag 看场景组织，情绪 Tag 看阅读体验。不能用同一个“删掉后剧情有没有变”标准否定 POV 或文风。

## 8. Synopsis 与封面同样去模板化

内部故事地图的 synopsis 继续表示全书梗概；发行 Synopsis 表示面向读者的吸引承诺，两者不混用。

发行文案从已确认故事中选最有力的入口：人物困境、关系反差、关键对白或带代价的选择。格式可以不同，事实和承诺必须有依据；不统一套三句文案，也不把 Tag 示例中的底牌写进本书。

封面保留现有海报创作能力、参考图分析和艺术化处理。Tag 说明关系张力与可用视觉手段，具体人物数、构图、颜色和字体依据本书决定；删除“所有背叛封面都冷色、女主前景、男主虚化”的固定规定。主题相同时仍需找本书独特的角色关系与视觉冲突。允许海报式合成，不要求逐场还原小说。

## 9. 前端调整

沿用当前系统的单面板、浅色与紫色强调，新增功能集中在现有维护页和方案卡，不做全站重设计。

### 9.1 类型维护

- 保留目录、Genre 关联、Markdown 编辑、阅读预览、版本、保存并启用。
- 在标题下显示贡献角色、启用版本；角色编辑收进资料设置。
- 在编辑器旁提供“承诺 / 方法 / 示例”写作提示，不拆成大量表单。
- “模型输入”可切换七阶段，展示实际发送的分节和字节量；明确附录不会发送。
- 新版对比标出原有强制桥段、章节号和默认倾向的处理，作者能检查有没有削弱情绪/改变终局。
- 对“第 N 章必须”“每次都要”“所有故事都要”等文本提供可忽略的编辑提示；不能靠关键词误拦合理写作说明，也不能把提示通过说成文学质量通过。
- 保留原文下载。旧原样格式清楚标记，不能只换显示标题就声称已改成新版。

### 9.2 创作与方案卡

- 创建时仍为一 Genre、多 Tags，不新增主辅排序步骤。
- 方案卡突出核心冲突、关系变化、读者收益与取舍；沿用单选 + 补充 + 提交。
- 不把所有机制逐项要求用户勾选；用户只决定真正重要的方向。
- “本书如何体现这些标签”默认折叠，在已有方案正文/已采用决定中说明，不建立第二套可编辑事实表。

## 10. 跨作品多样性：分清本轮差异与历史差异

第一阶段能减少固定模板造成的重复，并让同一轮方案更有区别；没有历史输入时，不能宣称已经与过去所有书做了语义去重。

如验收发现同一组 Tags 多次创建仍反复出现相同核心路线，第二阶段增加轻量的历史相似性提示：

- 在既有全局设计调用中附带一份短“设计辨识摘要”，包括核心目标、关系起点、主要选择、揭露机制和终局代价；最多约 600 中文字，不再调用模型生成摘要。
- 摘要绑定原故事设计 SHA，作为派生比较材料，不是新的故事权威。后续设计变化后旧摘要失效，不能继续代表该书；缺失或无效摘要不阻塞小说生成。
- 仅检索同工作区、同 Genre、Tags 有交集的最近可用摘要，按 Tag 重合度和时间确定最多 3 本；过滤当前作品、它的来源作品及同一本书的其他版本。
- 在新书首次探索时冻结所用摘要范围，以“避免重复既有因果路线”的参考加入同次请求；普通后续讨论不反复发送，已选路线不被历史库更新打断。
- 总参考预算建议 6 KiB，超出只减少整条可选摘要并展示比较范围，不裁剪某条摘要后伪称完整比较。
- 相似性是建议，不按关键词、向量分数或一个模型分数自动拒绝。作者可以明确选择相似题材路线。
- 既有书没有摘要时不自动全书回读；初期覆盖范围如实展示，必要时单独安排补录。

第一阶段验收不依赖此模块；这是明确分开的增强功能，避免为解决十章节拍问题扩建一整套检索与评议平台。

## 12. 版本、数据与上线

1. 原目录和原样导入记录都保留，不能原位篡改历史版本。
2. 先提交几份代表文档的内容对照：Betrayal、CEO、First-Person-POV、Fast-Paced-Plot、Tragedy；用于验证冲突/身份/表达/节奏/终局五类边界。
3. 按确认标准逐份重构 35 份 Tag，同时核查 Romance 和现有 Second Chance 的组合一致性。没有来源证据的优化写成编辑方法，不能伪装成样本统计结论。
4. 使用现有批量导入的并发 revision 校验、备份与原子写入，全量成功后再启用；失败不留半套默认目录。
5. 新讨论默认冻结新版本；已有讨论和正在写作的任务继续原快照。明确“采用新版资料”时创建新 revision/子快照，影响既有路线则先展示影响，不把已经写出的正文悄悄重置。
6. 原样文件仍可导入并按其原格式读取，但不能把旧原文默默标为 v2、自动删节或宣称已解决固定模板问题。
7. 发布前检查活跃任务。设计阶段不部署、不重启、不启动真实模型；实施后的真实验收按用户确认的模型与预算安排。

## 13. 验收与实施顺序

### 阶段 A：内容标准和代表稿

交付新版规范、5 份代表稿与逐项改动说明。确认三件事：题材承诺仍有力度、固定桥段已解除、允许的结局和创作模式没有被擅改。

### 阶段 B：全量文档与引擎接入

完成全量编辑、编译、页面预览和冻结承接。工程测试至少覆盖：

- 原始 35 文件哈希不变，版本历史和原文下载仍能复现。
- 一个 Genre、关联 Tag、稳定 ID、重复导入、并发更新和原子失败正确。
- v2 各贡献角色可解析；未知角色/破损格式明确报错，不擅自猜测。
- 七阶段快照测试：每个选中 Tag 的身份与核心承诺存在，组合边界正确，未发送封面内容/研究附录的阶段可追溯。
- 实际发出的现代讨论请求含新版方法一次，正文没有原始十章节拍回流；不能只测试中间函数。
- 旧快照请求语义保持，混用格式有明确版本与预览；不能将旧请求冒充新请求。
- 字节超限在发送前报告，不静默丢 Tag、截断事实或替换模型。
- 选项采用、补充意见、暂停恢复与正文交接不丢确认决定。
- 1 章、短篇、多章和容量扩展不被十章假设绑住；常规章节允许静场与余波。
- H5 的 ID、公开标签与 EPUB/manifest/SHA 绑定保持一致，私有 Markdown 和 roles 不进入导出。

### 阶段 C：有限真实创作对照

保持模型、思考档位、故事输入、Tags、篇幅与返回格式一致，比较旧版与新版。首先测试方案，不直接跑几部全书。

建议最小对照：Betrayal/CEO/Independent 组合和一个含 POV/快节奏的组合；每组旧版、新版各一次，均返回 2–3 条路线。观察同一轮内路线差异与两组之间的题材差异。若要证明跨次稳定性，再追加独立重复样本，不能把一次输出当成统计结论。

在作者选定的方案上再检查开篇和一次关键情绪兑现的正文片段。评估具体问题：

- Tag 是否影响了相应层面，而不只在描述里出现名字？
- 路线差异是否进入关键选择和因果，而不只改了地点或身份？
- 开篇是否让人进入人物处境、产生具体情绪与继续阅读的期待？
- 回报是否在正文场面中成立，是否避免反复受辱、突然洗白或单纯堆灾难？
- 是否有不被固定章序绑住的节奏，同时保持连续性与容量？
- 相比旧版，完整请求字节、实际调用次数、首段等待、总用时怎样变化？

工程测试不能证明作品更好；模型自评不能冒充真实读者反馈。本轮对照是上线前有限验收，不把它常驻到每本小说的工作流。根据结果再决定是否需要第 10 节的历史相似提示。

完成顺序：标准确认 → 代表稿 → 全量编辑与接入 → 工程验收 → 有预算的真实对照 → 发布。不得以“换了标题”“加了一段多样性要求”作为完成依据。
