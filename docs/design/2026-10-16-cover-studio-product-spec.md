## 1. 产品结果与范围

用户进入工作室后，应能从完整小说骨架直接获得四个有区别的商业封面方向，确认后生成四张候选。每张完成即能查看、使用或精修，不需要先阅读分析报告、等待其他图片或填写接受理由。

故事感由**人物关系、题材信号、情绪和标题共同表达**。读者应大致感知“谁的故事、什么关系或处境、有什么吸引人的压力”，不要求通过一个静止画面证明特定章节的完整因果链。设计感来自人物主次、构图、造型、色彩和标题层级的共同设计，不等于增加人物数量或装饰元素。

本次目标：

- 缩短默认调用链，去掉面向海报创作不必要的前置逐段核验和反复语义审核。
- 从规划阶段召回重要主配角，避免四张候选都退回泛化单人、文件和低头表情。
- 允许原创宣传同框、静态关系姿态、象征合成和不同美术媒介。
- 保持现有蓝紫色、深蓝导航、白色卡片、圆角及全宽系统视觉。
- 将选择、精修、排版、失败恢复和费用信息做成可理解、可恢复的工作流。

本次不做：重写小说骨架、默认扫描章节正文、复制参考站插画、自动生成额外角色参考图、默认无限返工、把旧分析伪装成已完成。复杂人物蒙版、可编辑多层 PSD、印刷书脊与封底不进入首版。

## 2. 当前问题与设计依据

当前代码与任务记录的审阅详见前述两份报告。对一份八段骨架，首次无失败的参考路径为 20 次分析、2 次方向、4 次图片、8 次图片审核，共 34 次应用层调用；已完成分析会复用，不能理解为每批都调用 34 次。

实测一批四图的保存记录为 14 分 05 秒，其中图片调用区间合计约 412 秒，八次文本审核约 398 秒，且逐图串行等待审核。一次方向规划因机械字段修订耗时 14 分 26 秒。这些是单次观测，包含排队、传输及模型等开销，不能推算为稳定纯推理耗时。

新流程正常目标是 **1 次文本规划 + 4 次图片生成 + 最多 1 次后台组合建议**。减少应用层调用及串行依赖，不承诺固定完成分钟数、同比例降价或保证模型成功率。

## 3. 创作合同：什么必须保持，什么可以自由设计

| 层级 | 内容 | 处理方式 |
| --- | --- | --- |
| 核心不变量 | 主要人物身份与年龄阶段、核心关系、时代与世界、主要矛盾、作者明确禁项和剧透边界 | 规划必须保留；发现实质冲突时给出具体提醒，不以艺术处理为由篡改 |
| 创作自由 | 人物站位、视线、姿态、造型细节、光线、色彩、镜头、象征组合、跨章节同框 | 默认允许；标记为宣传式表达，不声称某一章确有该场景 |
| 商业建议 | 画面张力、人物魅力、替代读法、题材感、标题可读性、局部细节 | 建议性评价，不触发自动付费修订，不阻断完整图片选择 |
| 执行完整性 | 原图真实存在、可解码、尺寸有效、身份与 hash 可追溯、精确标题可合成 | 程序检查；损坏或不存在的资产不能冒充完整候选 |

新表达类型为 `poster_staging`。宣传同框不等于小说中的实际会面；不用给每个手势、凝视或前后景分别寻找事件证据。不可凭空增加故事中没有的主要背叛、死亡或人物关系。骨架中的内容一律作为资料，不执行其中夹带的工具指令；旧模型输出的封面偏好也不自动升级为用户硬约束。

用户可选择“偏关系海报、偏群像、偏人物、偏氛围”等偏好，默认仍由题材决定。**无固定人数配额**：关系型小说应认真探索核心主配角；单人求生可以通过人与环境形成压力；空洞的四人拼脸不能优于有故事承诺的双人封面。

## 4. 商业美术系统

### 4.1 一次规划中共同确定的内容

规划器读取完整骨架及用户设置，在同一调用内输出共享简报和四个方向。内部思考维度不变成六个用户步骤，也不拆成六轮模型审核。

| 设计维度 | 必须回答的问题 | 输出尺度 |
| --- | --- | --- |
| 故事承诺 | 谁受到什么关系或处境的压力，读者为什么想了解？ | 一句话，不复述全书 |
| 主配角 | 谁必须被读者记住，谁构成吸引、牵挂、对抗或共同压力？ | 只召回关键人物；原文未定外貌保留为设计选择 |
| 美术定位 | 对应什么题材、读者和情绪？采用什么表现媒介？ | 一套共享配方，可在各案变体 |
| 整体构图 | 第一视觉焦点、人物空间关系、辅助故事元素是什么？ | 一张图只承担一个主要视觉论点 |
| 标题设计 | 哪些词是主要识别点？如何让完整书名按序可读？ | 保序文字段、样式与区域 |
| 执行提示 | 图片模型需要生成什么，必须留出哪些标题与人物空间？ | 紧凑、无互相冲突的执行描述 |

美术媒介包括商业精修摄影、电影海报合成、半写实幻想、类型插画。媒介由方案显式选择，编译器与评价必须使用同一配方，不能上游允许插画、下游仍因“非摄影”拒绝。

成熟角色可以有专业造型、自然皮肤和有吸引力的布光；不默认憔悴，也不自动年轻化。不同受众设定独立绑定作品，不把此前“北美 40–60 岁女性”写成全站默认。

### 4.2 四方向差异怎么保证

规划器同时看到四个槽位，以不同的视觉论点区分候选。可选语法包括关系对峙、主角前景与关系后景、阵营/三角、统一象征合成、人物与环境压力；不是每本固定使用四个模板。

四案在以下至少一个主要维度有实质差异：关系重心、构图组织、故事符号或情绪承诺。仅换衣服颜色、裁切和左右位置不算充分探索。程序只能识别完全重复字段和配方，审美差异由轻量建议及用户判断，不新增阻断审核。

设计例：同一本家庭关系小说可以表达“独立选择”“无法回避的家庭牵连”“两种生活的距离”“重新取得主导”。具体人物及符号必须来自该书；不能因模板需要就添加第三者、豪宅或婚礼。

### 4.3 标题是画面的一部分

保留“无字画稿 + 可复现文字合成”两层资产。规划阶段先决定脸部保护区域、主配角空间和文字区域，避免出图后用整块色带覆盖故事。

首版排版引擎支持：

- 完整书名按原顺序切分为文字段；关键词可放大，连接词可较小。不可自动改名、删词或重排。
- 每段字体、字号、字重、颜色、行高、字距；限定在实际已支持的属性范围内。
- 已授权用于发布的字体清单、缺字检测和明确回退；字体文件版本随配方保存。
- 阴影、描边和局部渐变底衬；不把金属金字作为全部题材的默认。
- 精确字形边界、行间相撞和出界检查、完整图与作品库缩略图双预览。

复杂人物遮挡文字和手工蒙版放在后续版本。首版不向规划器暴露渲染器尚不支持的能力。屏幕预览与导出使用同一布局数据，导出需要真实渲染验收，不能仅相信 CSS 外观。

## 5. 信息架构与页面布局

页面沿用现有侧栏，内容区随可用宽度展开。桌面主区内边距 24–32 px，白色卡片、蓝紫强调、深蓝主操作。卡片和按钮遵循现有圆角及字体体系，不引入米白/墨绿文学站风格。

```text
现有系统侧栏 │ 返回作品 · 封面工作室 · 书名
             │ 骨架来源摘要 · 市场定位       历史 / 模型与费用 / 交付包
             │ 设计方案   候选封面 4/4      当前主要操作
             │ [有活动任务时出现的紧凑进度条]
             │
设计方案     │ 故事核心 + 关键人物关系
             │ 方向 01 │ 方向 02 │ 方向 03 │ 方向 04
             │                       按此方案生成 4 张封面

候选封面     │ 批次切换 · 当前选中状态     重新生成 4 张
             │ 大图 01 │ 大图 02 │ 大图 03 │ 大图 04
             │ 使用 / 精修 / 排版；建议和版本详情默认折叠
```

仅保留两个主 Tab：

| 入口 | 主要内容 | 不应出现的内容 |
| --- | --- | --- |
| 设计方案 | 故事承诺、关键角色、四个方向、单案编辑、统一生成 | 数百条证据、必经核查阶段、长审核 JSON |
| 候选封面 | 图片、单张状态、选择、精修、标题排版、版本 | 每卡重复一整段任务日志及默认展开的多层报告 |
| 来源抽屉 | 完整来源预览、文件/字节/hash、快照时间、变更提示 | 默认再次启动分析 |
| 历史抽屉 | 方案版本、图片批次、单图谱系、失败记录 | 自动重试或覆盖旧候选 |
| 模型与费用抽屉 | 请求模型/实际观测模型、用量、费用估算、调用阶段 | 把推测的图片模型显示为实际模型 |

宽屏显示四列候选；中等宽度两列；移动端单列，主要操作可吸底，但不遮挡内容。图片保持完整 2:3 预览，不因卡片等高裁去标题。顶部 Tab 可吸顶；不让悬浮栏占去大量首屏。

## 6. 关键交互与页面状态

### 6.1 从骨架到方向

1. 首次进入展示来源文件摘要、市场/读者定位及默认美术偏好；用户点击“设计 4 个封面方向”。
2. 立即取得持久任务 ID，页面显示“正在设计封面方向”，可切页或关闭。来源和用户配置此刻冻结。
3. 方案保存后呈现一句话故事核心、主要人物关系及四张方向卡；卡片有名称、视觉承诺、人物、构图与配色/标题意向。
4. 用户可修改单案的自然语言要求。修改产生新方案 revision，使先前出图批准仅适用于原 revision；不自动付费推理。
5. 点击“按此方案生成 4 张封面”，原子保存批准范围和幂等请求，再调度图片。完成方向的长期成功横幅自动收起，Tab 状态改为“已用于生成”。

用户自然语言修改如果需要模型重新设计，明确操作为“根据修改更新方向”，只更新对应方向并保存新版本；不把输入框失焦当作付费提交。首版允许更简单的“编辑创作要求 → 显式重新设计”，不声称任意文字修改可安全本地编译。

### 6.2 候选与选择

每张卡片优先呈现图片、简短方向名和状态，底部固定“使用这张”“精修”“标题排版”。评价以“可优化：标题对比度”等短提示展示，详细报告在折叠区。

- 一张完整候选生成后立即可选；其余三张生成或评价未完成不构成限制。
- 选中卡片显示“当前使用”；其余保留“使用这张”。点击选中图不会重复提交。
- 选择无需理由，模型意见保留；不以低分、曾被拒绝或“需修复”阻止选择。
- 更换选择只更新当前选择指针及后续交付版本，原候选和旧选择历史保留。
- 如果新封面已选中而旧交付包仍在更新，明确显示“封面已选中，交付包更新中”；不得把旧包当作新封面交付。
- 批次允许显式“重新生成 4 张”。一次失败不能永久耗尽方向；成功结果和历史费用也不能因新一批而清零。

### 6.3 原图精修

打开侧边工作面：左侧原图，右侧优化提示及可选保持项。直接展示“这次将生成 1 张精修版”，主按钮同名。

适用：表情、光线、衣着、局部背景、人物关系强调和构图优化。绑定真实原图 hash，用户提示作为编辑目标；不默认再走全骨架规划及独立批准链。要求改变故事核心人物/关系时，明确提示回到方向设计，不悄悄解释成原故事。

提交后精修另存 child 版本。原图始终可查看、可选；原选中封面不会自动换成精修版。精修成功后可并排比较并点击“使用精修版”。取消抽屉或切页不取消后台任务。

| 失败位置 | 页面行为 | “重试”实际做什么 |
| --- | --- | --- |
| 未取得图片 | 原图继续显示，错误收进详情 | 用户显式发起 1 次新编辑，绑定同一原图和要求，生成 successor 任务 |
| 图片已保存、排版失败 | 保留新画稿和原图 | 重做本地排版，不重新请求图片 |
| 图片与排版完成、建议失败 | 成品可直接使用，标注建议未完成 | 用户可重试建议；不会重新出图 |
| 原图缺失或 hash 不一致 | 指明资产问题，禁用图片编辑 | 不拿最新候选冒充原图；需恢复正确资产或重新选图 |

重试按钮针对最新失败任务。重复点击同一请求只返回同一 successor；如果 successor 再失败，下一次明确重试从它创建新任务，历史链完整保存。

### 6.4 标题排版

独立抽屉展示完整封面和缩略图；支持标题段落、关键词层级、字体、颜色、对齐、区域与可读性底衬。编辑立即本地预览，不调用图片模型。

“保存排版版本”生成新排版 recipe 与合成资产，保留同一无字原图。若当前选中旧版本，不自动切换；另有“保存并使用”作为明确组合操作。对没有无字原图的历史图片，应标明“该历史图含内嵌标题”，不能承诺无损替换旧文字；精确覆盖范围之外的去字须另行显式图片编辑。

### 6.5 来源变化

骨架变更只将旧方案标为“基于较早骨架”，保留历史图可选。创建新方向使用新快照。用户仍可精修旧图，但界面明确其继承原版本；如需要采用新剧情，选择“使用新骨架重新设计”。不自动把新骨架混入旧图精修，也不因来源更新让历史下载失效。

## 7. 异步状态与可观察性

任务状态和候选状态分开，不能用一个全局 `busy` 禁用所有操作。

| 对象 | 状态 | 用户仍可做什么 |
| --- | --- | --- |
| 规划任务 | queued / running / succeeded / failed / interrupted | 看已有方案/图片；失败后显式重试 |
| 图片批次 | queued / running / succeeded / partial / failed / interrupted | 看已完成图片、选用、切页；不启动重复的同批请求 |
| 单张候选 | queued / generating / composing / ready / failed | ready 可选；图片已保存的 composing 可查看画稿 |
| 建议任务 | pending / running / completed / unavailable | 所有 ready 候选始终可选 |
| 精修任务 | queued / editing / composing / ready / failed / interrupted | 原图和已选图始终保留 |

进度只显示可验证信息：“已完成 2/4 张，第 3 张请求已提交”；未收到输出时显示等待。拆开记录后台心跳、最近上游事件、最近实际内容、图片保存时间。心跳或连接事件不能证明模型一直在思考；实际模型未知时如实写“服务未返回”。

刷新恢复过程为读取任务与资源状态，不创建新任务。前端持久化未确认请求 ID，服务端按 owner 和请求 ID 绑定参数/结果；POST 响应丢失可重放同一 key。网络中断先恢复查询，不把重连当作重试出图。

服务重启后发现执行器失联，应标为 `interrupted` 并保留已完成资产。不要默认假设远端请求未执行：若无法确认结果，显示“本次结果未知，重试可能产生新费用”，由用户显式决定新尝试。原生渠道有可靠结果恢复能力时先恢复既有结果。

首版沿用保守图片并发 1，先移除审核串行等待；依据成功率、429 和首图耗时实测后再开 2。并发是提供方配置，不以固定 4 路作为速度承诺。评价独立于生图队列。

## 8. 新协议与数据模型提案

新协议独立于旧 V9/V11 方向合同，不继承四十多个字段后继续打补丁。以下为待实施接口概念，字段名和路径需在编码时与现有 API 核对，不能视为当前可用接口。

```text
SourceSnapshot
  id / project_id / complete_documents / content_hash / byte_count / created_at

PosterPlan
  id / revision / pipeline_kind="skeleton_poster" / schema_version
  source_snapshot_id / source_hash / author_constraints / preference_snapshot
  brief { premise, audience, genre_promise, principal_cast, core_relationships,
          visual_anchors, invariants, spoiler_boundary }
  directions[4] { id, name, promise, cast_refs, staging, story_elements,
                  art_recipe, title_recipe, image_instruction }
  compiler_version / plan_hash / provenance

CoverBatch
  id / owner_id / request_id / approved_plan_id+revision+hash / count
  model_configuration_snapshot / status / candidate_ids / task_id

CandidateVersion
  id / batch_id / direction_id / parent_candidate_version_id?
  artwork_asset_id+hash / composition_asset_id+hash / typography_recipe_hash
  status / requested_model / observed_image_model? / model_observation_source?
  created_by { generation | refinement | typography } / usage_event_ids

CoverSelection
  project_id / candidate_version_id / revision / selected_at

Advisory
  batch_id / candidate_version_ids+image_hashes / review_policy_version
  task_id / status / per_candidate_notes / portfolio_notes / usage_event_ids
```

共享人物 ID、hash、序号、时间戳、画布尺寸和版本由程序分配；模型只写创作所需内容。本地校验角色引用、字段类型、完整标题、支持的媒介/字体/效果、区域边界和明确已结构化的作者禁项。不得声称本地程序已经验证全部故事事实。

`ready` 要求完整、可解码、可追溯的合成封面存在；无字画稿保留为不同资产类型。模型质量状态单独记录，不加入 ready 判定。旧的模型审核报告不转写成新建议回执。

## 9. 模块与 API 行为提案

对外模块维持少量完整操作，调用方不自行拼装分析、ledger 和批准链：

| 操作 | 输入与效果 | 幂等及并发边界 |
| --- | --- | --- |
| `plan_from_snapshot` | 完整快照、用户偏好、request_id → 持久规划任务 | 同 key 同参数返回原任务；同 key 不同参数拒绝 |
| `save_plan_revision` | 已有 revision 与用户编辑 → 新 revision | 比较 revision；并发编辑冲突时返回最新版本，不能静默覆盖 |
| `generate_batch` | plan id/revision/hash、4 张、request_id → 批次 | 批准范围与任务 reservation 原子绑定；运行中相同范围请求合并并记录别名 |
| `refine_candidate` | 原图版本/hash、优化提示、保持项、request_id → 单图任务 | 每个显式请求最多一次新图片编辑；重复请求返回原任务 |
| `retry_task` | 最新失败任务、request_id → successor | 明确恢复阶段；保存图片后不得误从生成阶段重新开始 |
| `compose_typography` | 画稿版本/hash、文字 recipe → 新合成版本 | 相同 recipe/hash 可复用；不发图片请求 |
| `select_candidate` | candidate version、expected selection revision | 原子更新选择；与后台结果写入无相互覆盖 |
| `get_workspace` | 项目与可选历史版本 | 只读投影来源、方案、任务、候选、选择、费用 |

可用资源式路径如 `/cover/poster-plans`、`/cover/batches`、`/cover/candidates/{id}/refinements`、`/cover/selection`；最终名称不应强迫旧客户端同时升级。

后台任务按资源级增量写入，避免“整批 JSON 最后保存”覆盖刚发生的选图或精修。批次终态触发最多一次建议任务，键包含批次、成功图片版本/hash 与建议协议；全部失败跳过。组合建议失败不把图片批次改为失败。单张精修不自动重评整个旧批次。

## 10. 完整骨架与请求预算

读取输入必须是完整冻结骨架及用户明确启用的附件，不自动附加章节正文。请求中原文放一份；不再默认复制数百条提取证据、全局账本和多份语义说明。

发送前完成：

1. 核对来源文件和冻结 hash，记录实际 UTF-8 字节。
2. 构造最终请求后计算实际字节和适用的上下文 token 预算，预留返回与一次格式更正所需空间。
3. 已知模型 tokenizer 可用时准确计量；不可用时保守估算并标注估算，不能声称已证明适配上下文。
4. 请求过大时在调用前给出“来源大小、预算、可执行选项”，不静默裁切原文、不用摘要冒充全文、不偷偷换模型或降推理等级。

默认规划一次模型调用；仅协议无法执行时最多一次定点更正，与原请求共享明确的修正额度。能本地派生的机械字段不送模型修复。美术喜好、轻微歧义或缩略图无法证明具体动机不触发自动更正。

初次预检还要检查下一次更正的保守包络；真实更正请求生成后仍需再次检查。若仍超限，保留首次输出与任务记录，停止并展示具体阶段，不能反复重试相同大小请求。通道不支持细粒度输出上限时明确记录“不支持”，不把配置值写成已执行限额。

这条新链解决默认输入冗余，但不承诺任意长度骨架都适配任意模型。对真实超过上下文的作品，应由用户选择能容纳完整来源的配置；多阶段长篇模式如后续提供，必须显式开启，并保留完整覆盖记录。

## 11. 模型、费用与日志

费用面板沿用全作品口径，分头脑风暴、正文、封面及总计。封面再分方向规划、图片、精修、建议、纯本地排版。排版可以显示“无模型调用”，不能将缺失图片用量写成 0。

每次调用保存请求模型、提供方、已观测实际文本/图片模型及观测来源；宿主 Codex 文本模型不冒充内部图片模型。未返回实际图片模型时显示“请求配置：自动；实际图片模型：未返回”，而非推测具体型号。

费用估算使用调用时冻结的模型单价与汇率：

`人民币估算 = Σ(各计费项用量 × 对应单价) × 该事件汇率`

区分输入、缓存输入、输出、图片计量等不同类别，避免缓存重复计费。tokens 只汇总实际返回且口径可合并的字段；缺失项单独列明。未知价格显示“待配置”，未知用量显示“未返回”，总计注明覆盖范围。估算不是订阅实际扣款。

日志同时记录排队、请求发送、首内容、首图保存、全部图片保存、建议结束；错误保留足够定位信息但过滤密钥。前端只展示简明错误与“查看详情”。重试成本保留在原小说与阶段下，不因失败或迁移消失。

## 12. 旧 V11 数据兼容

旧方向、分析、批准、图片、选中封面、费用和失败历史保持原 bytes/hash 与语义，不重写，不重新计算旧批准。通过 `pipeline_kind` 和 schema version 分派新旧校验/编译。

- 新模式不要求 `analysis_id`，也不制造“complete”分析。
- 旧分析失败时，用户可以主动使用完整骨架创建新版方向；迁移不自动调用模型。
- 旧候选继续可选、可下载，并可通过轻量适配器精修原图；绑定旧版本和实际资产，不要求重建四方向。
- 历史缺少无字原图、字体或完整来源时分别展示能力限制；不随便填充虚假来源或拿其他图片替代。
- 两种流程的图片可共存。选中版本只有一个明确指针，交付包与 EPUB/manifest 按现有协议引用同一合成封面与对应 hash。
- 旧深链接映射到相应方案/批次及辅助抽屉，不出现刷新后丢失任务。

新流程使用 feature flag；规划、生成、精修、选择和交付版本分派全部贯通后才对用户开放。仅换 UI 或只开放新方案生成会制造新的不兼容记录，不作为可发布阶段。

## 13. 验收矩阵

| 场景 | 必须可观察的结果 |
| --- | --- |
| 新作品无旧分析 | 可直接由完整骨架设计四方向；正常只发生一次规划调用 |
| 完整输入 | 请求中完整原文出现一次，来源 hash 对得上；附件范围清楚 |
| 关系型故事 | 四案充分探索核心主配角，不以泛化单人重复敷衍，也不以人数打分 |
| 单人或非爱情题材 | 不为群像模板虚构人物，不强制豪宅、礼服或爱情姿态 |
| 静态宣传站位 | 不因无法匹配某章动作或唯一动机被自动返工 |
| 长标题 | 全文保序且无缺字，关键词层级可调，完整图和缩略图实际渲染验证 |
| 单张已完成 | 即使其余生成中或建议失败，也可直接使用且不需要理由 |
| 方向规划中切页/刷新 | 恢复同一个任务和已保存输出，模型调用次数不增加 |
| POST 响应丢失/重复点击 | 幂等 key 或别名返回原任务；无额外图片调用 |
| 四图全部失败 | 可显式重新生成，旧失败历史和费用保留；刷新不自动出图 |
| 部分成功 | 成功图始终保留，失败图可单张重试，批次可终态结束 |
| 精修失败 | 原图和当前选择仍可用；可显式重试，成功编辑图不重复生成 |
| 只改标题 | 图片调用为零；无字原图不变，新合成有独立版本/hash |
| 选图与后台写入并发 | 当前选择不被陈旧批次保存覆盖；冲突可检测 |
| 来源更新 | 旧图可看可选，新规划绑定新快照，不混用新旧输入 |
| 请求超限 | 调用前失败，报告实际阶段和大小；原文不截断，旧结果不丢失 |
| 服务重启/结果未知 | 恢复既有任务或如实标中断，不把不确定请求自动重放 |
| 模型/用量缺失 | 未观测模型、未知 token 和待配置单价均显式区分 |
| 旧 V11 | 方向、图、选择、费用、ZIP 保持可用，历史 hash 不变 |
| 下载与实际选图 | ZIP 可解压，完整封面、EPUB 内嵌、manifest 引用/hash 一致 |
| 布局与可访问性 | 全宽、多断点、键盘 Tab/抽屉焦点/ESC、状态不只靠颜色、无横向溢出 |

视觉验收使用 8–12 份不同题材/读者骨架检查方向，选择代表作品真实出图。相同作品尽量保持骨架、标题和模型配置一致比较新旧；分别观察吸引力、题材辨识、关系表达与标题设计，不将“通过代码测试”当作“达到 GoodNovel 效果”。

性能记录规划耗时、首图可见、全部图片可见、建议完成、调用数、报告 tokens、估算费用和失败原因，积累 p50/p95。基线不足时报告样本量，不用单个成功案例承诺速度。

## 15. 本次设计交付的判定

详细规格、原创视觉示例及可点击交互稿可以评审“流程是否更短、画面是否有关系和题材感、视觉是否统一、精修与排版是否好用”。交互稿中的时间、费用、模型名及候选状态若为演示值，应清楚标注，不能被当作真实任务结果。
