# 全书一致性核查：谁说的、影响哪里、谁可以改

已采纳的作者原文、模型生成的候选大纲、评审意见是三种不同的记录。评审可以指出矛盾，但不能把候选里的假设升级为作者设定；在原文中找到了某句话，也不等于评审对这句话的解释成立。

## 从发现问题到改写

1. 初审保留所有发现。清楚且有原文支持的单章或全局小修可以直接进入原来的定向流程。混合问题、归属不明的说法和定向修订器无法处理的创作争议交给证据规划器。已启动的旧核查保留原协议。
2. 证据计划逐项登记作者原句、候选证据的位置、受影响章、可改写章和只读依赖。受影响不授予写权限；程序在应用修订时再检查权限。计划协议一次反馈可检测的多个错误，不消耗多次调用逐项发现字段错误。
3. “原文冲突”在计划中只是待核实意见。在独立请求中重读完整采纳原文，分别考虑角色所信、他人所述、时间差、遗漏细节与实际发生的事。可自洽的说法进入复核，候选偏离原文时修候选。只有涉及同一对象和情形、不能同时成立的两段独立原文才能提交作者。程序验证引文来自原文；文学判断仍由独立读审完成。
4. 同时存在多个问题时，计算写入目标和只读依赖的交集，暂缓受裁决影响的章及其依赖组。其余组先修订并保存。作者看到的是两段原文，没有默认选择或技术说明表单。选择绑定本次原文、任务和两段引文；模型、问题排序与引文顺序变化不会让作者重新选择。最后一次核查必须检查每条决定，全部窗口都未检查到某个决定时不能发布。证据本身超容量时不问作者，不裁剪故事；先保存能够完整接收依据的独立组。
5. 生成的假设可由独立的字段修订替代；原始假设、原文、已保存的章节批次均保留。适用的章节修改先对完整候选的副本验证，再重新执行语义审读及原有发布门槛。获得写权限或修正字段均不等同于书稿通过。

## 旧任务及中断恢复

版本化的证据计划和修订结果是新的子检查点；不就地修改旧回复。迁移核对原文、任务身份、创作锁、全书路线、逐批前驱哈希、旧请求和完成回复。已确认的旧成果可重放，错引的候选假设必须能定位到原候选。不能证明来源时不得当成作者原文，也不能静默更新权限。若某个已开始的请求不能验证，保留原件并停止。恢复、资格查询和诊断不得自动选择作者原句。

## 验收边界

测试必须区分：可同时成立的两种叙述、候选假设偏离、真正互斥原文、已授权和越权的章、独立和传递依赖的修订、已经答复和过期的裁决，以及迁移后首次模型调用。真实任务恢复的依据是任务状态及新产生的证据文件；替身回放只能证明恢复路径及写入边界，不代表出版质量已通过。
