# Tag 创作说明书：方法相同，故事不同

本轮以用户在系统中启用的「动作、冒险、出轨、黑暗浪漫」四份自由 Markdown 为参照，重写其余 36 个 Tag。四份参照及 Romance Genre 不修改。这里规定编辑原则，不新增 Markdown 导入限制，也不建立固定剧情模板。

## 推荐组织

| 部分 | 要回答的问题 |
| --- | --- |
| 定位与情绪承诺 | 读者为什么选择这个 Tag？希望经历什么、获得什么？ |
| 人物与关系动力 | 双方各想要什么、依赖什么、在哪些地方误判？ |
| 核心推演方法 | 条件如何影响选择，选择如何引发回应、改变关系与处境？ |
| 场景表达与发散空间 | 怎样写得可感？换哪些因果变量才能产生不同故事？ |
| Tag 融合与取舍 | 与其他已选 Tag 怎样互相影响？发生冲突时需要明确什么？ |
| 执行自检 | 该 Tag 的承诺是否落实？是否出现其特有的失败方式？ |
| 简介与封面 | 如何诚实传达本书独特的关系、张力与阅读期待？ |

七部分是便于阅读的编辑结构，不是解析器必填字段。用户仍可以使用前言、不同层级标题、列表及其他普通 Markdown。系统管理身份、关联、版本和哈希；正文保存创作方法。

## 方法如何保留创造力

不规定「第一章受辱、第二章反击」或固定前十章节拍。改为给出可选择的推演抓手：利益如何冲突、信息怎样被误读、哪项行动改变信任、胜利给人物带来什么生活。

发散不只换职业和名字，还改变：

- **关系起点**：陌生、合作、稳定关系、决裂或重逢。
- **因果条件**：谁先知道、谁有决定权、谁承担代价、谁可以退出。
- **行动与回报**：公开反击、安静拒绝、合作、重新谈判或建立新生活。
- **节奏**：哪些情绪需要停留，哪些事务可以概述，何时兑现部分期待。

这些是可选变量，不要求每本书逐项填写或全部采用。头脑风暴阶段提出真正不同的大方向；作者采用骨架后，正文深化该方向，不再次随机改线。

## 不同 Tag 不能混成同一种故事

| Tag | 主要作用 | 避免替换成 |
| --- | --- | --- |
| Betrayal | 信任被利用、选择权发生变化 | 必然出轨、必然报复 |
| Regret | 失去后的认识、责任与代价 | 后悔就能复合 |
| Second Chance | 旧问题改变后再次主动选择 | 重逢或道歉即修复 |
| Possessive | 独特依恋、失去恐惧与回应 | 不断控制—逃跑—抓回 |
| Contract Marriage | 交换条款与真实感情相互改变 | 必定到期分手再追回 |
| Mystery | 公平线索、认识变化与阶段答案 | 无限隐瞒、条条线索推翻全局 |
| Sweet Love | 准确理解、互相投入与生活回报 | 重复礼物、单方全能照顾 |
| Tragedy | 有前因的失去与留下的价值 | 突然事故或强行 HE |

组合举例是说明已有标签如何互相作用，不是自动添加未选的标签。主线有冲突时，以作者确认的核心关系、结局与尺度为准，不能把标签承诺偷偷转移给配角。

## 执行与篇幅

- 不要求固定冲突回合数、每场必有危机、每次胜利必有损失，也不强制每章出现所有标签。
- 自检不产生额外模型调用；状态延续沿用系统已有协议，不把「机制结算」附到小说正文。
- 简介、封面指导只在相应任务中应用；自由正文完整传递到各阶段，由现有阶段解释规则限定用途。
- 主角可以受伤、犹豫、失控和求助；主体性体现在对选择与后果有影响，不是永远情绪完美。
- 亲密尺度、人物年龄事实与作者结局约定保持明确；甜宠、悲剧等保留自身情绪契约。
- 文档本身简洁，靠具体机制与自检支撑质量，不靠反复强调「必须高质量」。

## 四份参照的评审建议（未修改原文）

它们的优势是明确受众体验、人物动力、场景表达与反套路要求。仍有几类表述值得作者后续决定是否放宽：

1. 「计划必定失败」「固定循环」「至少 3–5 回合」容易变成新的节拍模板，建议换成适用条件与充分性判断。
2. 「每章末尾强制机制结算」容易让创作指导侵入正文输出协议；本轮其他 Tag 已明确内部自检，不附加正文表格。
3. 某份 Tag 固定第三人称、某份固定年龄受众，组合时可能覆盖本书作者选择；应区分偏好与本书已确认要求。
4. 四份参照对儿童配角的口径并不完全相同。未替作者统一改写；其余 Tag 沿用先前确认的年龄约定，并保留来源年龄及孕育、家庭事实，亲密互动仅限成年人。

## 如何验收

工程验证检查 ID／公开分类保持、版本保留、全文进入七阶段、组合大小和旧冻结输入不变。它不证明读者更喜欢作品。

下一次真实创作重点看：同一组合是否产生因果不同的方案；标签是否影响主角行动与核心关系；读者是否得到具体情绪回报；正文是否保持已采用的走向。无需为了验收本次资料更新自动启动模型。
