# 封面输入与提示词合同

2026-11-05 · 已在现有 `skeleton_poster` 实现。无第二套封面引擎；不恢复全书逐事件证明和昂贵语义审核。

## 唯一数据边界

`ReferenceAssets` 保存原始PNG/JPEG字节；asset_id=`reference-<sha256>`，包含sha256、content_type、width、height、size_bytes、origin(upload/source_book)。工作区或项目目录决定归属，API不接受任意文件路径。完整解码、40MP/12MiB和路径校验先于模型调用；原件不做隐式旋转/重编码，真实传输SHA可复核。候选精修继续使用其已保存原画与原有验证器。

参考选择为 `{asset_id, mode}`，mode是 `visual_inspiration` 或 `adaptation_reference`。服务端查验图片后把资产元数据、字节和模式冻结到计划输入。源图书名/作者/人物关系不能冒充本书设定。

## 一次规划

输入顺序：现有系统/排版合同 → 本书完整骨架与附件 → 选中Genre/Tags封面投影 → 作者偏好 → 可选真实图像块。文本/图片中文字都是资料，不授予工具权限。知识投影只有核心承诺与可选封面表达，含ID/版本/SHA；研究附录、未选标签不进入请求。

无图使用现有文本planner；有图通过视觉模型 `complete_with_images`，一次返回共同故事理解、参考图拆解和四个方向。上下文预算仍按现有provider检查，不把base64复制进文本，不截断骨架或已选Tag；原有一次格式纠正上限保留，因此不是无条件“永远一次调用”。

拆解字段采用紧凑的五个字符串数组，每组最多10条、每条1200字符；有图至少一项observation。代码绑定资产ID/SHA，模型不生成它们：

```json
{
  "reference_analysis": {
    "observations": ["可见前景主体与后景两个人物，背景是暖色建筑灯。"],
    "interpretations": ["前景可能是情绪中心，人物身份与关系不能单从图片确定。"],
    "retain": ["前后层次、冷暖光色对照"],
    "translate": ["改为本书两位主角，用旅馆环境表达再次合作。"],
    "exclude": ["原书标题、作者和不属于新故事的人物关系"]
  }
}
```

不另建 observation ID / recommendation ID / reference_use 的平行JSON关系图，避免把普通美术理解变成另一套脆弱引用协议。画面观察与解释仍分开；每条保留/转译/排除直接服务实际出图。

## 共同设计规则

- 保护本书人物身份、关键关系、世界规则与作者明确限制。宣传式同框、象征、蒙太奇、艺术化环境可用，不要求重现某一剧情场景。
- 优先从关系与情绪表达故事：主体层级、距离、视线、光线、环境和少量有意义的象征。Genre/Tags共同改变表达，不能一个标签一个道具。
- 多人物构图在故事支持时使用；不机械规定人数，不为构图添加不存在的孩子、情人或反派。女性自主不等于必须单人封面。
- adaptation_reference以原图为编辑依据；visual_inspiration可更大范围重组。两者都实际传图，区别是保留程度。
- 源图标识不自动进入新书，目标是重新创作完整封面，不交付去水印的原图副本。
- 生成无字2:3画稿，遵守现有标题区域与本地排版器能力。准确书名由本地排版完成。

## 出图和精修

每张图片请求只编译该方向、共同底线和参考分析，完整骨架不重复送入四张图。无参考图走generate；有图走edit，验证实际operation与reference_image_sha256。响应必须有可解码新图片；exit 0不代表出图成功。

计划保存当时的不可变骨架/知识/图片绑定；改素材后需新建方向，旧方向和结果保留。新建接口请求幂等仍由现有poster任务所有者负责。失败不删素材，刷新显示持久任务。无支持图像输入的provider会明确失败，不能悄悄退回文生图。

单张精修以所选候选原画＋修改要求执行，优先于最初参考图；不重新规划全书，其他候选保持原样。选用完整图片不要求评分通过或接受理由。4候选、直接选用、失败重试、本地排版、历史版本和ZIP/EPUB同一封面均沿用现有已验证能力。

工程验证包括真实图片字节到单次规划、四次edit、直接选用、换模式/刷新/移除、损坏图片拒绝、输入SHA改变拒绝。文学和实际图像效果尚未做本轮付费验收。
