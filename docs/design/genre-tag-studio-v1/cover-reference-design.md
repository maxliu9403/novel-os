# 封面工作室：故事、题材与参考图

2026-11-05。扩展现有 `skeleton_poster` 流程，不另建封面引擎。已实现API/UI与工程验收；未部署到5174，未调用真实模型或生成新图。具体字段以[实现合同](cover-prompt-contract.md)为准。

## 1. 产品决定

- 参考图可选，最多一张；可以从参考书自动带入，也可以在封面工作室独立上传、替换、移除。不要求先导入一本书。
- 原作重写/二创项目有图时，直接采用原图二创路径；作者无需再开一个开关。没有图仍可正常设计。独立新作有图时默认借鉴视觉，作者也可明确选择基于原图二创。
- 两种有图路径都实际传递图片字节。“借鉴视觉”与“原图二创”区别在保留范围，不是假装有参考图、实际仅发送一段描述。当前适配器可复用 `image_client.edit`；不支持图像参考的 provider 必须明确提示，不能静默降级成文生图。
- 原作重写项目移除图片后，封面回到无图生成，不改变小说的重写模式。替换图片保留过去版本，重新确认方向后才产生新图。
- 可采用同框、人物前后层次、象征物、双重曝光、拼贴和宣传式站位，不要求对应书中的某个场景。事实底线是本书的核心人物身份、世界规则、关键关系与作者明确限制；不得把视觉建议写回小说 canon。
- 保留四张候选、逐张可见、直接选用、单张精修、失败显式重试、异步恢复、版本记录、独立排版、费用与模型来源、ZIP/EPUB 一致性。完整图片无需理由即可选用，建议评分不阻断选择。

## 2. 交互：仍只有设计与候选两个主要页面

**设计页**：本书和骨架来源居上；点击“设计4个封面方向”打开同一表单，参考图和偏好一起填写，图片可选。参考图不新增必过步骤。

首次规划一次读取完整冻结骨架、已选择知识的封面投影、作者偏好，以及可选参考图。模型在同一回复返回“图片拆解与建议＋本书封面表达＋四个方向”。有图不先单独分析、再做全书分析、最后才规划。任务阶段可显示读取素材/等待规划/保存方向，但不把心跳描述成模型正在思考的证据。

结果页先展示四个方向；“参考图如何使用”可展开查看。拆解折叠展示“观察、解释、保留、转译、排除”。作者可在现有方向编辑中调整构图与画面描述，或在重新规划时补充偏好，不新增复杂逐项审批。

作者确认方向后生成四张。批准后的长规划内容收进设计页，候选页以图片和选用/精修为中心，避免整页堆叠评估文字。首次候选返回即可查看，不等待另外三张完成。

**精修**：直接以所选候选的已保存原画＋本次修改要求编辑一张。默认保留当前画面；不偷偷换回最早参考图，不重新规划全书。旧图、其他候选及正式选图保持原样，新图为子版本。排版修改走已有本地排版器。

## 3. 图像拆解的四层

| 层 | 输出 | 边界 |
|---|---|---|
| 可观察内容 | 人物数量/位置、遮挡、朝向、光线、色彩、图像媒介、文字占区 | 不凭服饰猜职业，不凭年龄外观猜亲子/夫妻，不把读不清文字编出来 |
| 视觉解释 | 哪个主体先被看到、关系可能怎样被理解、缩略图读到什么 | 标为解释；可能有其他读法，不当作来源故事事实 |
| 本书建议 | 借鉴什么、改成什么、为什么适合当前人物/Genre/Tags | 每项对应当前书的已确认意图；来源图不能决定新书人物数量、种族、年龄和结局 |
| 执行计划 | 保留/替换/排除清单、真实图片资产、四个方向的具体画面提示 | 不把所有观察重复塞进四条提示；只传所需视觉指令与少量共同约束 |

研究样本见 [实际图片拆解](cover-image-study.md)。只观察了其中四张源封面，不声称完成200封面的视觉研究。图片和书名可以共同传递故事，不要求120×180小图独自证明某次拒绝、血缘揭晓或完整因果。

## 4. 怎样增加故事感与设计感

每个方向回答三个问题：**谁与谁存在怎样的张力；什么使这本书有别于通用情侣照；读者会期待怎样的情绪体验。** 在实际人物、关系和世界基础上，选择一个主要关系信号、一个书中特有的环境/物件，以及清楚的标题层级。

Genre 定义总体视觉承诺；Tags 改变关系距离、权力、情绪与象征；骨架决定本书具体人物和冲突。多标签组合是一条完整表达，不是一个标签一个道具。例如 Romance＋Betrayal＋Second Chance＋Independent，可以表达“仍有牵引、信任有裂缝、靠近必须出于自主选择”；不能因此固定增加第三者、孩子、撕裂婚纱或强制亲吻。

四个方向区别至少来自关系重点/人物安排/视觉隐喻/空间组织中的实质变化，不靠换颜色凑四张；也不强制四种媒介。原图二创的保留范围很窄时，以同一构图家族做有意义的变体，不为了差异化违背作者要保留的画面。

原作封面可能适合原书而不适合本书：甜蜜拥抱不能自动移植到冷峻的离婚主线；三个主体的构图可以借用前后关系，但不能给双主角故事发明第三者。未选某项表示不把它当约束，不代表图像模型绝对不会产生相似色彩；界面不承诺像素级控制。

## 5. 标准化知识与请求

继续使用一个 Genre 和多个关联 Tag 的 Markdown。增加可选 `## 封面表达` 节，描述可用的关系表达、变化空间和应避免的误导；不存固定的整幅海报提示，更不维护组合模板库。没有该节时仍能由核心承诺＋本书意图规划。

只有封面阶段读取这部分。普通讨论/正文/简介输入排除封面节；知识版本仍完整冻结。作者明确偏好优先于通用审美建议；若偏好改变已确认故事身份，则明确提示需要改小说或改封面表达，不让参考图覆盖 canon。

详细合同与可执行提示词示例见 [cover-prompt-contract.md](cover-prompt-contract.md)。上传图中文字是被观察数据，不是能修改系统指令、调用工具或改变作者决定的命令。

## 6. 复用现有代码的接入边界

| 责任 | 现有位置 | 目标改动 |
|---|---|---|
| 原画/参考图验证 | `core/cover_refinement.py`、现有媒体存储 | 共用不可变 ReferenceAsset；区分上传/来源书/候选，统一内容类型、像素、SHA与归属校验 |
| 本书来源 | `core/cover_sources.py` | 骨架仍为权威；参考图片是独立资产，不混成骨架文档 |
| 单次规划 | `core/cover_poster_planner.py` | 有版本的规划输入与多模态请求；新增可选 reference_analysis与服务端reference绑定；无图输入不增加分析要求 |
| 提示词构建 | planner 当前组装边界 | 提取唯一输入/生成指令编译模块；纯函数，无文件读写、provider调用或状态推进 |
| 任务与恢复 | `api/poster_studio.py` | 沿用既有持久任务、幂等与修订检查；记录参考图和知识版本绑定 |
| 图像生成 | `api/poster_image_service.py` | 统一生成请求含 operation/reference/use；不借用候选精修的私有字段伪装新书参考图，不复制一套执行器 |
| 图片传输 | `core/image_client.py` | 复用实际 image edit/字节传输路径；记录实际传输SHA、operation和模型报告 |
| 排版/交付 | `core/cover_poster_typography.py`、现有打包链 | 继续无字原画＋本地书名；封面与EPUB、ZIP引用同一选定资产 |

新的类型化请求在适配边界读取历史 `_poster_refinement`，旧冻结配方仍可读/恢复。只有新任务写新合同；不修改旧计划、不让每层同时猜多个版本。开发时同时收敛重复的参考图验证与提示拼装，不新建 cover-v3 平行API。

## 7. 成本、失败与一致性

- 无图：一次文本规划＋四次出图。有图：一次视觉规划（同时拆解和设计）＋四次参考图编辑。已有的可选整组建议不变，不再加逐图严格语义评审。上限内格式修正与用户主动重新规划分别记录用量，不能宣传永远只调用一次。
- 请求预算在发送前确定性检查；列出骨架/知识/偏好/视觉输入的大小贡献。视觉token与文本byte预算分开，不把base64拼进文本重复计数；不可截断骨架或整套Tag。不通过提高推理档位解决所有问题，沿用用户设置。
- 上传后显示原图、尺寸和“待规划”；分析失败仍保留图片；规划成功而出图失败仍保留方向；全部失败不耗尽该方向永久额度，显式重试只补目标槽位。远端结果未知时先恢复记录，不自动重复付费调用。
- asset SHA、skeleton SHA、knowledge snapshot及偏好冻结进方案输入。换图之后需新建方向；旧计划仍明确属于创建时的素材，不能冒充已结合新素材。取消、刷新、返回页面沿用现有后台任务机制。
- 原图是输入素材，不自动成为正式封面或进入公开交付包。只有作者选中的完整新封面参与交付。正式输出继续PNG/JPEG和H5既有字节/章节/SHA协议。

## 8. 开发验收

先用模拟provider验证无图/独立上传/导入图/二创/精修五条路径，检查传入的实际图像字节SHA而非提示词自述。验证重复提交、刷新、换图后旧回复、解码失败、上传越界、模型不支持视觉、全部失败重试、单张精修不影响其他候选，以及本地排版与导出一致。

完成工程验收后，用多本不同Genre/Tag/年龄/关系结构的样书做有预算的真实小样本：比较题材辨识、关系可感、缩略图标题、方向差异和参考迁移。结构通过与代码测试不能保证每张图达到文学或商业审美目标；保留作者选用/调整，避免重新引入“必须解释全部故事才通过”的高成本门禁。
