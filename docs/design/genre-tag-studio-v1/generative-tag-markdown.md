# Genre 与生成式 Tag Markdown 标准

2026-11-06。已用于 Romance Genre，以及 Action、Dark Romance、Possessive、Badboy、Age Gap。

一份 Markdown 是一个 Genre 或 Tag 的唯一可编辑来源。复制已启用的新版文件最方便；不是给每种组合再建一份模板。

## 文件头

```yaml
---
schema: novel-knowledge.v2
id: tag.example
kind: tag
name: 示例标签
aliases: [Example]
genre_ids: [genre.romance]
roles: [relationship, conflict]
publication:
  labels: {zh-CN: 示例标签, en-US: Example}
  definition: 对读者公开的一句话类型定义。
---
```

`id` 是稳定身份，修改写法不换 ID。`genre_ids` 指合法关联的 Genre。`roles` 为1–3项不重复作用：`conflict` 冲突、`relationship` 关系、`character` 人物、`world` 世界规则、`setting` 背景、`mood` 情绪、`voice` 表达、`pacing` 节奏、`ending` 结局。它描述作用，不设主次排名，也不要求作者再填写一套表单。Genre 不填写 Tag 的 roles。

公开 labels/definition 进入既有动态 H5 分类；私有方法和 roles 不进入公开分类。只修改创作方法时保留公开信息。不要把全部情节设计写进 definition。

Genre 同样使用 `novel-knowledge.v2`，但 `kind: genre`、ID 使用 `genre.` 前缀，不填写 `genre_ids` 和 `roles`。参照 [Romance 原文](../../../resources/novel-knowledge/genres/romance.md)。Genre 定义整本书的主要阅读承诺；Tag 定义怎样改变其中的关系、冲突、人物、世界或表达。两者使用同一套分节与阶段投影，不另建组合模板。

## 六个必需分节

| 分节 | 写什么 | 避免什么 |
| --- | --- | --- |
| `## 核心承诺` | 读者必须感受到的体验，Tag 成立的必要条件，明确标识默认倾向 | 一部固定小说的剧情；把默认倾向写成永远必须 |
| `## 故事机制` | 欲望、障碍、选择与后果如何形成故事；可采用的机制 | 抽象形容词清单；只有严谨没有吸引 |
| `## 发散空间` | 人物目标、关系利益、信息顺序、关键代价等可变化轴；少量可选路线 | 十章节拍表；只允许换职业地名 |
| `## 组合原则` | 本 Tag 如何改变其他 Tag 的关系、行动或表达；冲突何时需作者决定 | 每个 Tag 各演一遍套路；偷换核心含义假装满足 |
| `## 场景与表达` | 可见的行动、人物声音、情绪铺垫与有分量的回报 | 固定感官数量、统一台词、逐章情绪循环 |
| `## 简介与兑现` | Synopsis 怎样提出本书的具体吸引与期待，正文如何兑现 | 固定句式；靠未采用情节或虚假卖点吸引读者 |

建议增加 `## 封面表达`，写视觉承诺与可变化因素，保留海报式艺术化组合。未提供时仍发送核心承诺。其他分节作为附录留存，预览明确标识不进入模型；生效要求必须放在上述分节内。

具体经典路线可以保留，但标识为可选示例，不是排除其他创意的白名单。类型核心、默认倾向和可选示例用清楚的自然语言区分，无需更多嵌套数据。人物、终局、现实限制、来源身份仍由本书作者设定决定。格式校验只保证可读取和可传递，不证明文学质量。

## 分阶段使用

| 阶段 | 新版 Genre / Tag 输入 |
| --- | --- |
| 头脑风暴、骨架设计 | 六个分节 |
| 章节规划、正文、现有联合审稿 | 核心承诺、故事机制、组合原则、场景与表达 |
| 出版简介 | 核心承诺、简介与兑现 |
| 封面 | 核心承诺、封面表达 |

`knowledge-compiler.v3` 每次请求添加一次组合解释，保留所选文档来源与投影清单。不增加新的模型调用或全书阅读。未升级的旧资料按原编译方式处理；在混合选择中，其原文要求仍会进入模型，不能宣称所有标签都已解除固定节拍。

每份文件不超过24 KiB，所选阶段上下文不超过96 KiB，超限拒绝而不截断。修改启用后，新讨论选择新版；已有讨论保留冻结版本，只有作者显式更新选择才改变它，已启动的正文交接不自动迁移。
